Metadata

الهدف من هذا الدرس

تصميم ما يُلصق على الدالة أو الصنف: مفتاح ثابت، قيمة صغيرة، وهدف واضح، حتى يقرأها Reflector من غير اتفاق شفهي.

المشكلة التي يحلها

المفتاح النصي العشوائي يتصادم بين مكتبة وحارس. القيمة الضخمة التي تحمل خدمة أو طلبًا تُنسخ على الصنف خطأً. وضع المزخرف على الصنف بينما القارئ يسأل الدالة فقط يترك المسارات بلا سياسة. هذا الدرس اتفاق اللصق قبل أداة الاكتشاف.

الفكرة ببساطة

Metadata هنا قيمة وقت تشغيل مربوطة بهدف. الهدف إما الصنف (كل المسارات) أو الدالة (مسار واحد). المفتاح ثابت مصدَّر من ملف المزخرف. القيمة علم أو مصفوفة نصوص أو رقم. القارئ يوثق إن كان غياب المفتاح يعني المنع أو السماح. مكتبتك تصدّر المزخرف والثابت معًا.

التعريف التقني

import { SetMetadata } from '@nestjs/common';

export const ROLES_KEY = 'roles';

export const Roles = (...roles: string[]) => SetMetadata(ROLES_KEY, roles);

@Roles('admin', 'editor') على الدالة يخزن ['admin', 'editor'] على تلك الدالة. المزخرف نفسه على الصنف يخزنها على الصنف. لا تخزن كائن الطلب. لا تخزن صنف خدمة قابلًا للحقن داخل القيمة وتتوقع أن يُحقن تلقائيًا. القيمة بيانات خاملة.

Reflector.createDecorator<string[]>() يولد مزخرفًا يحمل مفتاحه، مناسب عندما لا تريد سلسلة عامة. DiscoveryService.createDecorator يولد مزخرفًا يمكن التصفية به عبر metadataKey لاحقًا. اختر واحدًا للسياسة الواحدة حتى لا يُلصق المفتاح مرتين.

تصادم السلاسل: حزمة خارجية قد تستعمل 'roles' أيضًا. إن نشرت مكتبة، فضّل Symbol أو مزخرف createDecorator على سلسلة قصيرة. داخل التطبيق الواحد الثابت المصدَّر يكفي إن كان الاسم فريدًا في ملفاتك.

الوراثة: صنف ابن لا ينسخ metadata الأب تلقائيًا بطريقة تعتمد عليها في كل المزخرفات. ضع المزخرف على الصنف الذي يخدم المسار فعلًا، واقرأ الصنف الذي يعيده getClass().

Mental Model

ملف المزخرف: المفتاح + الدالة
المتحكم: @Roles على الصنف أو الدالة
الحارس: يقرأ المفتاح ويقرر الافتراض عند الغياب

اللصق وصف. الحارس سياسة.

أبسط مثال

import { Controller, Get, Post } from '@nestjs/common';
import { Roles } from './roles.decorator.js';

@Controller('invoices')
@Roles('staff')
export class InvoicesController {
  @Get()
  list(): string[] {
    return [];
  }

  @Post()
  @Roles('payroll')
  create(): { ok: true } {
    return { ok: true };
  }
}

GET يرى أدوار الصنف فقط إن كان القارئ يغلب الدالة ثم يعود للصنف عند الغياب. POST يملك مفتاحًا على الدالة. إن استخدمت getAllAndOverride فـ payroll يستبدل staff على POST. إن استخدمت getAllAndMerge تُجمع القائمتان. اختر واحدة واكتبها في الحارس.

شرح المثال

المثال بلا حارس ناقص عمدًا: اللصق وحده لا يمنع الطلب. القيمة تجلس حتى يسألها Reflector. هذا أكثر خطأ شائع بعد اختلاف المفتاح. سجّل الحارس كـ APP_GUARD أو @UseGuards وإلا فالمفتاح زينة.

ماذا يحدث داخليًا؟

  1. تقييم invoices.controller.ts يشغّل مزخرف الصنف ثم مزخرف الدالة.
  2. مخزنان منفصلان: واحد على الدالة create وواحد على InvoicesController.
  3. list بلا مخزن دالة لهذا المفتاح.
  4. عند الطلب يسأل الحارس الهدفين حسب قاعدته.
  5. تغيير المصفوفة بعد اللصق خطر إن خزنت المرجع نفسه في مكان آخر. مرر القيم إلى SetMetadata ولا تعدّل المصفوفة لاحقًا.
  6. الاختبار الذي يستدعي الدالة مباشرة يتخطى الحارس. اختبر الحارس بهدف مزيف أو عبر HTTP.

مثال عملي

علم لإخفاء الحقل في التسلسل، ومفتاحه مختلف عن الأدوار:

import { SetMetadata } from '@nestjs/common';

export const REDACT_KEY = 'redact';
export const Redact = () => SetMetadata(REDACT_KEY, true);

المعترض يقرأ REDACT_KEY من الدالة. لا تعِد استعمال ROLES_KEY. سياستان مفتاحان. القيمة true أصغر من كائن يصف المستخدم.

أخطاء شائعة

  • لصق بلا قارئ مسجّل.
  • سلسلة مفتاح مكررة بين مكتبتين.
  • قيمة فيها request أو كلمة سر.
  • افتراض أن ابن الصنف ورث المفتاح.
  • قراءتان مختلفتان: حارس يغلب ودالة أخرى تدمج، لنفس المفتاح.

متى نستخدمه؟

وصف ثابت على المسار: دور، علم عام، اسم عملية للقياس، مهلة.

متى لا نستخدمه؟

حالة تتغير كل طلب، أو سر، أو بديل عن عمود في القاعدة.

مقارنة

المكان يسري على يغلب عند override إذا وُضع أولًا
الدالة ذلك المسار نعم إن سبق الصنف في القائمة
الصنف دوال بلا مفتاحها، أو تُدمج بعد الدالة في قائمة التغليب
الغياب لا قيمة سياسة القارئ

تمارين

تمرين سهل

ماذا يخزن @Roles('admin')؟

الحل

المصفوفة ['admin'] تحت ROLES_KEY على الهدف الذي فوقه المزخرف.

تمرين متوسط

لماذا لا يكفي المزخرف على المتحكم من غير Guard؟

الحل

اللصق لا يغيّر مسار الطلب وحده. حارس أو معترض يجب أن يقرأ المفتاح ويرفض أو يبدّل السلوك.

تمرين متقدم

مكتبة خارجية استعملت 'roles'. ماذا تغيّر في مزخرفك داخل الشركة؟

الحل

مفتاحًا فريدًا عبر Symbol أو Reflector.createDecorator، وتحدّث القارئ إلى المفتاح الجديد حتى لا يقرأ قيمة المكتبة الأخرى.

أسئلة مراجعة

  • ما حجم القيمة المناسب؟
  • من يملك الاتفاق عند غياب المفتاح؟
  • لماذا سياستان لا تشتركان في سلسلة واحدة؟

الخلاصة

Metadata وصف صغير على دالة أو صنف، بمفتاح واحد بين الكاتب والقارئ. الحارس يحوّل الوصف إلى قرار، ويوثق التغليب أو الدمج.

ماذا بعد؟

DiscoveryService: مسح المزودات والمتحكمات التي تحمل مزخرفًا معينًا.
