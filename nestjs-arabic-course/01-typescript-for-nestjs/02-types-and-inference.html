Types و Inference

الهدف من هذا الدرس

كتابة الأنواع التي ستظهر في خدمات Nest، ومعرفة متى يكتبها المترجم عنك.

المشكلة التي يحلها

إذا كتبت نوعًا على كل ثابت صغير، الملف يغرق. إذا لم تكتب نوعًا على حدود الدالة، قارئ الخدمة لا يعرف ماذا يدخل وماذا يخرج، والمترجم يتراخى عند أول any صامت.

الفكرة ببساطة

اكتب النوع على حدود الدوال والكائنات العامة. دع المترجم يستنتج النوع داخل الدالة عندما تكون القيمة ظاهرة.

التعريف التقني

التعليق النوعي (type annotation) تكتبه أنت: const port: number = 3000. الاستنتاج (inference) يحسبه المترجم من القيمة: const port = 3000 يصبح number. الأنواع الأساسية هنا: string و number و boolean و null و undefined و bigint و symbol.

Mental Model

حدود عامة:  اكتب النوع     create(input: NewBook): Book
داخل الدالة: دع الاستنتاج   const label = input.title
قيمة من الشبكة: لا تستنتج معنى   unknown ثم فحص

أبسط مثال

const title = 'Refactoring';
const price = 40;
const published = true;

function label(name: string, amount: number): string {
  return `${name}: ${amount}`;
}

شرح المثال

  • title استُنتج string من القيمة.
  • price استُنتج number. كتابة : number هنا تكرار.
  • label حدودها مكتوبة لأن من يناديها من ملف آخر يجب أن يرى العقد من غير قراءة الجسم.
  • ناتج القالب استُنتج string، ويوافق نوع الإرجاع المكتوب.

ماذا يحدث داخليًا؟

المترجم يسير من القيمة إلى النوع في الاستنتاج، ومن النوع إلى الاستخدام في الفحص. عند strictNullChecks، string لا يقبل null. هذا يمنع إعادة "كتاب أو لا شيء" بصمت. إن غاب الكتاب فالنوع الصادق Book | null، وستكتبه عندما نصل إلى الاتحاد.

any يطفئ الفحص على تلك القيمة. unknown يقول "لا أعرف" ويجبرك على الفحص قبل الاستخدام. جسم الطلب مكان unknown، لا any.

مثال عملي

function discount(price: number, rate: number): number {
  return price * (1 - rate);
}

const next = discount(40, 0.1);

next يُستنتج number. لا تكتب : number عليه إلا إذا أردت أن يصرخ المترجم عندما تغيّر الدالة وترجع نصًا بالخطأ. كتابة النوع على الثابت المستنتج من دالة موثوقة قرار توثيق، لا ضرورة.

أخطاء شائعة

  • const books: any[] = [] ثم دفع أي شيء. استخدم نوع العنصر عندما تعرفه.
  • كتابة الأنواع على كل سطر داخل دالة قصيرة حتى يختفي الكود.
  • استنتاج نوع من JSON.parse والظن أنه Book. الناتج واسع، غالبًا any. ضيّقه بفحص.

متى نكتب النوع؟

على معاملات الدوال العامة، وقيم الإرجاع غير البديهية، وحقول الكائنات التي تعبر الملفات، وقيم unknown القادمة من الخارج.

متى نترك الاستنتاج؟

للثوابت المحلية ذات القيمة الظاهرة، ولناتج نداء دالته معلنة النوع.

مقارنة

annotation inference
من يقرر أنت المترجم من القيمة
مكانه الطبيعي الحدود الداخل
يفشل فيه طلب HTTP نعم، لأنه ليس قيمة في الكود نعم للسبب نفسه

تمارين

تمرين سهل

ما نوع const ok = books.length > 0 إذا كانت books مصفوفة؟

الحل

boolean، لأن المقارنة تنتج قيمة منطقية والمترجم يستنتجها.

تمرين متوسط

لماذا function find(id: string) أوضح من ترك المعامل بلا نوع؟

الحل

بلا نوع يصبح المعامل any في الإعدادات المتساهلة، أو يخطئ في strict حسب السياق. الحدود المكتوبة تمنع نداء find(2) إذا كان المعرّف نصًا.

تمرين متقدم

دالة تقرأ process.env.PORT. لماذا نوع الناتج ليس number حتى لو كتبت في الملف .env الرقم 3000؟

الحل

متغيرات البيئة نصوص أو undefined من وجهة Node. المترجم لا يفتح .env ليحولها. التحويل إلى عدد قرار وقت تشغيل، مثل Number(process.env.PORT)، مع التعامل مع الغياب. فصل الإعداد سيثبت هذا.

أسئلة مراجعة

  • أين تكتب النوع، وأين تترك الاستنتاج؟
  • ما فرق any عن unknown بالنسبة لجسم طلب؟
  • هل الاستنتاج يحمي JSON القادم من العميل؟

الخلاصة

الأنواع على الحدود، والاستنتاج داخل الدالة. ما يأتي من خارج العملية يبدأ unknown حتى يُفحص.
