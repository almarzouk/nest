# Access Modifiers

## الهدف من هذا الدرس

تحديد من يحق له استخدام عضو الصنف: `public` و `protected` و `private`، وحدود ذلك وقت التشغيل.

## المشكلة التي يحلها

إذا كانت كل الحقول عامة، أي ملف يعيد تعيين اتصال قاعدة البيانات أو يقرأ سرًا وُضع على الكائن بالخطأ. المعدّل يوثق القصد ويجعل المترجم يرفض الاستخدام الخارجي.

## الفكرة ببساطة

- `public`: من أي مكان. هذا الافتراضي.
- `protected`: الصنف نفسه والأصناف التي ترثه.
- `private`: الصنف نفسه فقط، من جهة TypeScript.

## التعريف التقني

المعدّلات حقول نوعية في TypeScript. الناتج JavaScript لا يطبق `private` التقليدي إلا إذا استخدمت الحقول الخاصة الأصلية التي تبدأ بـ `#`. Nest وكتب TypeScript التعليمية يستخدمان `private` و `public` لأنهما جزء من أسلوب الإطار منذ سنوات، والفحص يتم في المترجم.

## Mental Model

```text
خارج الصنف  -> public فقط
ابن يرث     -> public و protected
جسم الصنف   -> الكل
```

## أبسط مثال

```ts
class Safe {
  public label = 'desk';
  protected level = 1;
  private code = 'secret';

  reveal(): string {
    return this.code;
  }
}
```

## شرح المثال

- `label` تُقرأ من `safe.label`.
- `level` خطأ من الخارج، ومسموح داخل `class Better extends Safe`.
- `code` خطأ حتى على الابن في فحص TypeScript.
- `reveal` دالة عامة تعيد قيمة مشتقة. هي بوابة، لا فتح للحقل نفسه. في مثال حقيقي لا تُرجع السر كما هو.

## ماذا يحدث داخليًا؟

المترجم يحذف الكلمات ويبقي خصائص عادية. `JSON.stringify` على الكائن قد يكتب `code` إذا كان حقلًا قابلًا للعد. `private` ليس تشفيرًا ولا إخفاء للرد. إخفاء الرد `@Exclude` لاحقًا في Serialization.

الحقل `#code` في JavaScript يمنع الوصول حتى من خارج الفحص، بما فيه `obj['code']`. Nest لا تفرض هذا الأسلوب في الأمثلة الرسمية. افهم الفرق حتى لا تخلط الأمان بالمترجم.

## مثال عملي

خدمة كلمات مرور: الهاش خاص، والتحقق دالة عامة.

```ts
class PasswordHasher {
  hash(plain: string): string {
    return `hashed:${plain}`;
  }

  matches(plain: string, hashed: string): boolean {
    return this.hash(plain) === hashed;
  }
}
```

المثال تعليمي ومفتاح الهاش هنا ليس خوارزمية. الفصل الأمني يستبدل هذا بـ bcrypt أو ما يوثّقه Nest. القصد: المستدعي يرى `hash` و `matches`، ولا يرى تفاصيل داخلية لو أضفت حقل ملح `private salt`.

`public` على الدالة يمكن حذفه لأنه الافتراضي. كتابته أحيانًا تقابل `private` في الملف نفسه ليبقى القصد ظاهرًا.

## أخطاء شائعة

- وضع سر في حقل `private` ثم إرجاع الكائن كله من متحكم. الحقل يخرج في JSON.
- الاعتماد على `private` لمنع طلب HTTP من قراءة شيء. الطلب لا يمر بفحص المعدّل.
- جعل كل شيء `public` "حتى لا يزعجني المترجم". تضيع حدود الصنف.

## متى نستخدم كل واحد؟

| المعدّل | في Nest |
| --- | --- |
| `public` | دوال يستدعيها متحكم أو خدمة أخرى |
| `private` | تفاصيل الخدمة، والاعتماد المحقون الذي لا يعاد تعيينه من الخارج |
| `protected` | أساس صنف يرثه غيره، مثل استراتيجية Passport لاحقًا عندما توسع صنفًا جاهزًا |

## متى لا نستخدم private كأمان؟

عندما يكون التهديد عميلًا على الشبكة أو `JSON.stringify`. هناك عقود إخراج وفحص حقول.

## مقارنة

| | `private` في TS | `#field` |
| --- | --- | --- |
| من يفرضه | المترجم | JavaScript وقت التشغيل |
| أمثلة Nest الرسمية | شائعة | نادرة في التوثيق الأساسي |
| يمنع JSON | لا | لا إذا سُلسل الكائن بطريقة تصل للقيمة |

## تمارين

### تمرين سهل

أي سطر يقبله المترجم من خارج الصنف: `safe.label` أم `safe.code`؟

<details>
<summary>الحل</summary>

`safe.label` فقط.

</details>

### تمرين متوسط

ابنٍ `class AuditSafe extends Safe` هل يستطيع قراءة `level` و `code`؟

<details>
<summary>الحل</summary>

`level` نعم لأنه `protected`. `code` لا لأنه `private` على الأب فقط.

</details>

### تمرين متقدم

لماذا إرجاع `this` من خدمة مستخدمين فيها `private passwordHash` خطر حتى مع المعدّل؟

<details>
<summary>الحل</summary>

المعدّل لا يحذف الخاصية من الكائن. المتحكم إذا أرجع الكائن، طبقة JSON تكتب الحقول القابلة للعد ومنها الهاش. الحل لاحقًا: لا تضع الهاش على الكائن الخارج، أو استبعده عند التسلسل. افصل كائن المستخدم العام عن سجل الاعتماد.

</details>

## أسئلة مراجعة

- ما الافتراضي إذا حذفت المعدّل؟
- من يرى `protected`؟
- لماذا `private` لا يكفي لإخفاء حقل عن HTTP response؟

## الخلاصة

المعدّلات توثّق الحدود ويفحصها TypeScript. `public` للعقود، `private` للتفاصيل، `protected` للوراثة. الأمان على الشبكة طبقة أخرى.

## ماذا بعد؟

نجمع المعدّل مع constructor في السطر الذي تتكرر كتابته في Nest.
