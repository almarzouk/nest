# Cluster ونموذج العمليات

## الهدف من هذا الدرس

استخدام أكثر من عملية Node على نفس الجهاز أو خلف موازن حمل، مع معرفة ما الذي يتسارع وما الذي يبقى بطيئًا في متجر رف.

## المشكلة التي يحلها

القياس أثبت أن الحلقة تقضي وقتًا في JavaScript (تسلسل، تحقق، ضغط داخل العملية) وأن نواة واحدة من ثمانٍ مشغولة والبقية فارغة. عملية واحدة لا تشغّل JavaScript على أكثر من نواة. الطلبات تنتظر دورها على تلك النواة.

## الفكرة ببساطة

شغّل عدة عمليات من التطبيق نفسه. كل عملية لها حلقتها وذاكرتها. نظام التشغيل أو `cluster` أو موازن الحمل يوزع الاتصالات. الطلب الواحد لا يصبح أسرع. عدد الطلبات المتزامنة هو الذي يكبر.

## التعريف التقني

وحدة `node:cluster` تشغّل عملية أساسية تتفرع إلى workers بـ `fork`. كل worker يشغّل `bootstrap` ويستمع على نفس المنفذ؛ النظام يوزع المقابس. `availableParallelism()` من `node:os` يعطي عدد العمال المناسب للجهاز. البديل الذي تصفه صفحة Deployment هو التوسع الأفقي: عدة نسخ خلف Nginx أو موازن سحابي، غالبًا كحاويات. الذاكرة لا تُشارك: كاش الذاكرة، الجلسات في الذاكرة، وعداد داخل متغير تختفي حدودها عند حدود العملية. صفحة Deployment تتحدث عن health checks حتى يسحب الموازن النسخة المريضة.

## Mental Model

```text
موازن أو عملية أساسية
   ├─ worker A  حلقة + ذاكرة
   ├─ worker B  حلقة + ذاكرة
   └─ worker C  حلقة + ذاكرة
Postgres مشترك خارجهم
```

## أبسط مثال

```ts
import cluster from 'node:cluster';
import { availableParallelism } from 'node:os';
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module.js';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  await app.listen(process.env.PORT ?? 3000);
}

if (cluster.isPrimary) {
  const workers = availableParallelism();
  for (let i = 0; i < workers; i++) cluster.fork();
} else {
  await bootstrap();
}
```

## شرح المثال

- الأساسية لا تستمع للـ HTTP. هي تنشئ العمال وتعيد إنشاء من يسقط إن أضفت `cluster.on('exit', ...)`.
- كل عامل يحمل نسخة كاملة من المزوّدات singleton. الإقلاع يتكرر بعدد العمال.
- المنفذ واحد من جهة العميل. التوزيع على مستوى المقبس لا على مستوى مسار Nest.

## ماذا يحدث داخليًا؟

1. العملية الأساسية تنشئ عمالًا.
2. كل عامل يهيئ Nest ويتصل بمجمع Postgres الخاص به ضمن حد `pool` ذلك العميل.
3. اتصال جديد يذهب إلى عامل. الطلب يعيش ويموت هناك.
4. إن خزّنت قائمة الكتب في ذاكرة العامل، العامل المجاور لا يراها.
5. مجموع اتصالات القاعدة = عدد العمال × حجم المجمع. هذا سقف يجب أن يبقى تحت `max_connections`.

## مثال عملي

على رف، التقرير الليلي ليس طلب HTTP. شغّله عملية بأمر منفصل حتى لا يزاحم العمال:

```ts
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module.js';
import { PriceReportService } from './reports/price-report.service.js';

const app = await NestFactory.createApplicationContext(AppModule);
try {
  const report = app.get(PriceReportService);
  await report.histogram();
} finally {
  await app.close();
}
```

`createApplicationContext` عملية بلا منفذ HTTP. عمال الويب يبقون للطلبات. شارك Redis إن كان الكاش قرارًا صحيحًا تحت التعدد، كما في درس التخزين.

## أخطاء شائعة

- توقع أن cluster يخفض زمن استعلام 800ms. الاستعلام ملك القاعدة.
- جلسة في الذاكرة ثم فشل التجديد لأن الطلب التالي وقع على عامل آخر.
- `pool` بحجم 20 مع 8 عمال فيصبح 160 اتصالًا.
- عداد «طلبات اليوم» في متغير على الخدمة singleton واعتباره إجمالي الجهاز.

## متى نستخدمه؟

عندما CPU العملية هو السقف، والقاعدة والشبكة تحتمل مزيدًا من التزامن، وقست ذلك. محليًا للتجربة، أو في الإنتاج كعمال على آلة واحدة. عبر الآلات، النسخ الأفقية في صفحة Deployment أوضح من محاولة مد `cluster` بينها.

## متى لا نستخدمه؟

كأول رد على SQL بطيء أو فهرس غائب. ولتطبيق حالته كلها في الذاكرة ولم تنتقل بعد إلى مخزن مشترك.

## مقارنة

| النموذج | نوى | ذاكرة مشتركة | جلسة في الذاكرة |
| --- | --- | --- | --- |
| عملية واحدة | واحدة لـ JS | نعم داخلها | تعمل |
| `node:cluster` | عدة عمليات على الجهاز | لا | تنكسر |
| نسخ خلف موازن | عدة أجهزة | لا | تنكسر أيضًا |

## أسئلة مراجعة

- ماذا يوزع `cluster`: الطلب داخل Nest أم المقبس على العمليات؟
- أي حالة يجب أن تخرج من ذاكرة العملية قبل التعدد؟
- لماذا تقرير CPU-heavy لا يُشغَّل داخل عامل الويب؟
- كيف يدخل حجم المجمع في حساب الاتصالات؟

## الخلاصة

تعدد العمليات يستعمل النوى الفائضة. كل عملية Nest كاملة ومستقلة في الذاكرة. هو لا يصلح استعلامًا بطيئًا، ويُلزمك بمخزن مشترك لكل حالة كانت تعيش في singleton.

## ماذا بعد؟

إن بقي CPU الـ HTTP نفسه هو السقف بعد القياس، صفحة Performance تقترح Fastify. الدرس التالي يضع الشرط: قياس، لا شعار.
