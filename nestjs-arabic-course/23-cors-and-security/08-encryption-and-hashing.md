# Encryption و Hashing

## الهدف من هذا الدرس

اختيار التشفير لاسترجاع سر، والتجزئة لكلمة المرور التي تُقارن ولا تُفك.

## المشكلة التي يحلها

تخزين كلمة المرور بدالة تُفك بمفتاح يعني أن تسريب القاعدة والمفتاح يعيد كلمات المرور. تخزين ملاحظة خاصة بتجزئة يعني أنك لا تستطيع عرضها لصاحبها لاحقًا. الخلط بين العمليتين يكسر الاسترجاع أو يكسر كلمات المرور.

## الفكرة ببساطة

التشفير اتجاهان: نص مفتوح يصبح نصًا مشفرًا، والمفتاح يعيده. التجزئة اتجاه واحد: الناتج يُقارن ولا يُعاد إلى الكلمة. Nest لا يغلّف `node:crypto` بحزمة إضافية. كلمات المرور في هذه الدورة عبر `PasswordHasher` من `@nestjs/authentication`، و scrypt بالمعاملات التي تذكرها صفحة التشفير والتجزئة.

## التعريف التقني

الصفحة تعرض `aes-256-ctr`: مفتاح 32 بايت، `iv` من `randomBytes(16)`، ثم `createCipheriv` و `createDecipheriv`. المثال التعليمي هناك يشتق المفتاح بـ `scrypt` من عبارة وملح ثابت. في التطبيق ضع مفتاح البيانات في متغير بيئة لا يُلتزم، وولّد `iv` جديدًا لكل قيمة، وخزّن `iv` مع النص المشفر. الملح الثابت والعبارة المكتوبة في المصدر مثال توثيقي لا إعداد إنتاج.

```ts
import { createCipheriv, randomBytes } from "node:crypto";

const iv = randomBytes(16);
const cipher = createCipheriv("aes-256-ctr", key, iv);
const encrypted = Buffer.concat([
  cipher.update(plaintext, "utf8"),
  cipher.final(),
]);
```

`key` هنا `Buffer` بطول 32. فك التشفير `createDecipheriv` بنفس المفتاح و `iv`.

كلمات المرور:

```ts
constructor(private readonly passwordHasher: PasswordHasher) {}

await this.passwordHasher.hash(password);
await this.passwordHasher.verify(password, storedHash);
```

`hash` يعيد سلسلة تصف المعاملات والملح والناتج، مثل بادئة `$scrypt$`. `verify` يقارن بزمن ثابت. تمرير `undefined` عند غياب المستخدم يتحقق من تجزئة وهمية حتى لا يكشف الزمن وجود البريد. `needsRehash` بعد نجاح التحقق يحدّث التجزئة إن تغيّرت المعاملات. `hash` يرفض الفارغ وما فوق 4KiB بـ `RangeError`. التطبيع NFKC قبل التجزئة.

الخيار `password.logN` في الوحدة يرفع التكلفة. الاختبارات تستطيع `new PasswordHasher({ logN: 10 })` حتى لا تبطئ المجموعة. الإنتاج يبقى على افتراض الحزمة أو أعلى ضمن السقف الموثّق.

من يفضّل argon2 أو bcrypt يغلّفهما في مزود خاص: `hash` و `verify` لـ argon2، و `compare` لـ bcrypt. bcrypt يقرأ أول 72 بايت فقط. كلاهما وحدة أصلية. المسار الافتراضي للدورة `PasswordHasher`.

لا تمرّر كلمة المرور إلى `createCipheriv` لكي «تستطيع الدعم فكها».

## Mental Model

```text
كلمة مرور -> hash -> مقارنة لاحقًا
ملاحظة خاصة -> encrypt مع iv -> decrypt لصاحبها
مفتاح البيانات في البيئة
ملح التجزئة داخل سلسلة PasswordHasher
```

## أبسط مثال

```ts
@Injectable()
export class NoteCrypto {
  seal(plain: string, key: Buffer) {
    const iv = randomBytes(16);
    const cipher = createCipheriv("aes-256-ctr", key, iv);
    const body = Buffer.concat([
      cipher.update(plain, "utf8"),
      cipher.final(),
    ]);
    return Buffer.concat([iv, body]).toString("base64");
  }
}
```

## شرح المثال

أول 16 بايت هي `iv`. الباقي النص المشفر. عند القراءة تُقطع البادئة ويُستدعى `createDecipheriv`. كل ملاحظة `iv` مختلف حتى لو تكرر النص. المفتاح لا يُخزَّن بجانب الملاحظة في الجدول نفسه بلا حماية. متغير البيئة أو مدير أسرار، وقد مرّ في الإعداد أن `.env` لا يُلتزم.

هذه الدالة لملاحظات المكتبة الخاصة، لا لعمود `passwordHash`.

## ماذا يحدث داخليًا؟

`aes-256-ctr` يولّد تيار مفتاح من المفتاح و `iv` ويخلطه مع البايتات. فقدان `iv` يمنع الاسترجاع حتى مع المفتاح. إعادة `iv` نفسه مع المفتاح نفسه لنصوص كثيرة تضعف التدفق. لذلك `randomBytes` لكل ختم.

`scrypt` في `PasswordHasher` يستهلك ذاكرة عالية حتى يصعب التخمين على معالجات الرسوم، ويعمل على تجمع الخيوط حتى لا يوقف حلقة الأحداث. الناتج لا يكفي وحده لاستعادة الكلمة.

تسريب جدول المستخدمين بلا مفتاح التشفير لا يعرض كلمات المرور إن كانت مجزأة. تسريب المفتاح يعرض الملاحظات المختومة. الميزانية مختلفة.

## مثال عملي

التسجيل يستدعي `hash` ويحفظ الناتج في `passwordHash`. الدخول يستدعي `verify`. إن نجح و `needsRehash` أعادت الحقيقة، حدّث العمود بتجزئة جديدة في الطلب نفسه. اختبار رخيص يبني `new PasswordHasher({ logN: 10 })` ولا يستخدم `logN` المنخفض في الإنتاج.

ملاحظة المسودة تختبر أن `seal` ثم الفك يعيد النص، وأن تغيير بايت في `iv` يفسد الناتج. لا تطبع المفتاح في السجل.

## أخطاء شائعة

- تشفير كلمة المرور بمفتاح التطبيق.
- ملح أو `iv` ثابت لكل الصفوف.
- مفتاح AES داخل المستودع.
- `bcrypt` على كلمة أطول من 72 بايت مع ظن أن الباقي يُفحص.
- مقارنة التجزئة بـ `===` على ناتج غير مخصص لذلك. `verify` هو المقارنة.

## متى نستخدمه؟

التجزئة لأسرار الدخول. التشفير لبيانات يجب أن تُقرأ لاحقًا وتستطيع حماية مفتاحها.

## متى لا نستخدمه؟

لتجزئة عنوان مقال تريد البحث عنه. التجزئة لا تُفهرس للبحث النصي. ولا لتشفير معرف الجلسة بدل العشوائية والتجزئة التي تخزنها حزمة المصادقة للرمز.

## مقارنة

| `PasswordHasher` | `aes-256-ctr` |
| --- | --- |
| لا استرجاع للكلمة | استرجاع بالمفتاح و `iv` |
| ملح داخل الناتج | `iv` تخزنه مع النص |
| دخول وتسجيل | ملاحظة أو حقل سري يُعرض |

## الخلاصة

التشفير يعيد السر بمفتاح. التجزئة تثبت المعرفة بلا إعادة الكلمة. كلمات المكتبة على `PasswordHasher`. الأسرار القابلة للعرض على `node:crypto` بمفتاح خارج المستودع و `iv` فريد.
