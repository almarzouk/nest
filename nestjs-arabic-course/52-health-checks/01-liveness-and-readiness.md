# Liveness و Readiness

## الهدف من هذا الدرس

فصل سؤال «هل العملية حية» عن سؤال «هل هي جاهزة لاستقبال العمل»، وربط كل سؤال بمسار HTTP يفهمه المنسّق.

## المشكلة التي يحلها

فحص واحد يضرب Postgres. حين تغيب القاعدة لثوانٍ تفشل كل النسخ، فيعيد Kubernetes تشغيلها معًا فيزداد العطل. فحص آخر دائمًا `200` فيُبقي نسخة أغلقت القاعدة أو ما زالت تهاجر ضمن التوزيع. السؤالان مختلفان: القتل مقابل سحب المرور.

## الفكرة ببساطة

Liveness مسار رخيص يثبت أن حلقة الأحداث ترد. لا قاعدة ولا Redis. فشله يعني أن العملية عالقة فيُعاد تشغيلها. Readiness تسأل التبعيات التي لا يمكن الخدمة بدونها. فشلها يعيد `503` فيُخرج المنسّق النسخة من Service أو من `upstream` ولا يقتلها. عندما تعود القاعدة تعود النسخة وحدها.

## التعريف التقني

في Kubernetes، `livenessProbe` الفاشل يعيد تشغيل الحاوية. `readinessProbe` الفاشل يحذف النسخة من نقاط النهاية. المهلة والفترة في تعريف المنصة، والمسار في التطبيق:

```text
GET /health/live   200 إن ردت العملية
GET /health/ready  200 أو 503 حسب المؤشرات
```

الحياة لا تستدعي `HealthCheckService` على قاعدة. الجاهزية هي التي تستدعيه، كما في درس Terminus. أثناء `SIGTERM` تفشل الجاهزية أولًا (`shutting_down`) وتبقى الحياة ناجحة حتى لا يُقتل الإغلاق اللطيف في منتصفه.

لا تضع `AuthGuard` على المسارين. المنسّق ليس مستخدمًا. لا تخزّن الاستجابة في Nginx.

## Mental Model

```text
live  = العملية ترد          فشل = أعد التشغيل
ready = التبعية لازمة        فشل = أوقف المرور فقط
إغلاق = ready يصبح 503       live يبقى 200 حتى الخروج
```

## أبسط مثال

```ts
import { Controller, Get } from '@nestjs/common';

@Controller('health')
export class LiveController {
  @Get('live')
  live(): { status: string } {
    return { status: 'ok' };
  }
}
```

هذا الملف لا يحقن Prisma. الجاهزية متحكم آخر أو دالة أخرى في الفصل التالي.

## شرح المثال

`GET /health/live` يعيد فورًا. إن سُدّت الحلقة بحساب متزامن فلن يصل الرد في مهلة المسبار، وهذا قتل مبرر. انتظار الشبكة لا يسد الحلقة، لذا عطل القاعدة لا يُرى هنا، وهو المقصود.

## ماذا يحدث داخليًا؟

1. المسبار يطلب الحياة كل بضع ثوانٍ.
2. Node يرد `200` إن كان الخيط حرًا.
3. مسبار الجاهزية يطلب `/health/ready`.
4. فشل مؤشر لازم يعيد `503` فتُسحب النسخة.
5. عند `SIGTERM` الجاهزية تفشل والطلبات الجارية تكمل.
6. `SIGKILL` بعد المهلة لا ينتظر أي مسار.

## مثال عملي

متجر بثلاث نسخ. `livenessProbe` على `/health/live` بمهلة ثانية. `readinessProbe` على `/health/ready` التي تنفّذ `SELECT 1`. انقطاع Postgres لعشر ثوانٍ يضع النسخ خارج الخدمة ثم يعيدها. لا إعادة تشغيل. نشر نسخة جديدة يفشل جاهزيتها حتى تنتهي الهجرة، والقديمة تبقى.

## أخطاء شائعة

- مسار واحد للكل يضرب القاعدة.
- ذاكرة الكومة على الحياة، فذروة GC تعيد التشغيل.
- حارس JWT على `/health/live` فيرى المنسّق `401`.
- كاش الوكيل يعيد `200` بعد أن صارت النسخة غير جاهزة.
- اعتبار `degraded` للكاش سببًا لقتل العملية.

## متى نستخدمه؟

خلف Kubernetes أو Nginx `upstream` أو أي منسق يسحب النسخ.

## متى لا نستخدمه؟

عملية واحدة على جهازك بلا مسبار. مسار `/health` الذي يعيد `{ ok: true }` يكفي للتطوير. لا تنسخ مسبار الحياة إلى اختبار الوحدة.

## مقارنة

| | الحياة | الجاهزية |
| --- | --- | --- |
| السؤال | هل الحلقة ترد؟ | هل نخدم؟ |
| القاعدة | لا | نعم إن كانت لازمة |
| الفشل | إعادة تشغيل | سحب المرور |
| أثناء الإغلاق | تبقى ناجحة | `503` |

## تمارين

### تمرين سهل

أي مسار يُسمح له بانتظار Postgres؟

<details>
<summary>الحل</summary>

`/health/ready`. الحياة لا تنتظر القاعدة.

</details>

### تمرين متوسط

لماذا إبقاء الحياة ناجحة أثناء `SIGTERM` مهم؟

<details>
<summary>الحل</summary>

حتى لا يعدّ المنسّق الإغلاق اللطيف عطلًا ويقتل العملية قبل `$disconnect`. الجاهزية هي التي تُخرج النسخة من التوزيع.

</details>

### تمرين متقدم

ذروة `heapUsed` على `/health/live` أعادت تشغيل النسخ السليمة. أين تنقل الفحص؟

<details>
<summary>الحل</summary>

إلى مسار تشخيص أو جاهزية بحذر، لا إلى الحياة. ذروة الذاكرة ليست دليلًا أن الحلقة ماتت، والقتل الجماعي أسوأ من تنبيه مراقبة.

</details>

## أسئلة مراجعة

- ماذا يفعل فشل الحياة في Kubernetes؟
- ماذا يفعل فشل الجاهزية؟
- لماذا المسار عام بلا حارس؟

## الخلاصة

الحياة تثبت أن العملية ترد. الجاهزية تثبت أن التبعيات اللازمة متاحة. لا تخلطهما في مسار يضرب القاعدة، وأبقِ الحياة ناجحة أثناء الإغلاق اللطيف.

`@nestjs/terminus`: كيف تُجمَّع مؤشرات الجاهزية في رد واحد.
