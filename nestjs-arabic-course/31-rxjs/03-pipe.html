pipe

الهدف من هذا الدرس

تركيب خطوات على تيار الرد بـ pipe من غير الاشتراك داخل المعترض.

المشكلة التي يحلها

تحويل جسم المتحكم بعد إرجاعه يتطلب مكانًا بين الخدمة والـ JSON. إن غيّرت الكائن داخل المتحكم اختلط العرض بالمجال. pipe يعلق الخطوات على التيار الذي تعيده next.handle()، وNest تبقى المشترك الوحيد.

الفكرة ببساطة

source.pipe(stepA, stepB) يعيد تيارًا جديدًا. المصدر لا يُشغَّل حتى الاشتراك في الناتج. الترتيب من اليسار إلى اليمين: خرج الخطوة الأولى دخل الثانية. الخطوات التي نحتاجها هنا قليلة وتُشرح في الدروس التالية. هذا الدرس عن التركيب نفسه.

التعريف التقني

import { map, pipe } from 'rxjs';

const addYear = pipe(
  map((title: string) => `${title} (2026)`),
);

pipe المستوردة كدالة تبني عملية قابلة لإعادة الاستخدام. طريقة المصفوفة على التيار هي التي ستراها في Nest:

return next.handle().pipe(
  map((body) => body),
);

كل وسيط دالة معامل. إن رمى معامل أو أصدر error، تتوقف الخطوات التالية ما لم تُدرج catchError.

لا تستدعِ subscribe في نهاية pipe داخل intercept. أعد ناتج pipe.

أبسط مثال

معترض يغلّف الرد الناجح في شكل ثابت:

import { CallHandler, ExecutionContext, NestInterceptor } from '@nestjs/common';
import { map, Observable } from 'rxjs';

export class EnvelopeInterceptor implements NestInterceptor {
  intercept(_context: ExecutionContext, next: CallHandler): Observable<unknown> {
    return next.handle().pipe(
      map((data) => ({ data })),
    );
  }
}

متحكم يعيد { title: 'NestJS' } يصبح جسم HTTP { data: { title: 'NestJS' } } بعد هذا المعترض.

شرح المثال

map الخطوة الوحيدة، ودرسها التالي يفصلها عن tap. التركيب هنا هو .pipe(...). إضافة خطوة ثانية تعني سطرًا آخر داخل الاستدعاء نفسه، لا pipe متداخلًا بلا سبب. المعترض لا يعرف إن كان المصدر متحكمًا أو معترضًا داخليًا. هو يرى تيارًا.

ماذا يحدث داخليًا؟

handle() يعيد تيارًا باردًا يمثل بقية السلسلة. pipe يربط المعاملات. عندما تشترك Nest في ناتج intercept، يسري الاشتراك نحو المتحكم، فتُنفَّذ الدالة، ثم تمر القيمة صعودًا عبر map. خطأ من المتحكم يقفز فوق map إلى أقرب catchError أو إلى المرشح. لذلك ترتيب catchError بالنسبة إلى map يغيّر هل يُغلَّف الخطأ أم لا.

مثال عملي

غلاف للكتالوغ فقط، لا لكل المسارات. ركّب المعترض على BooksController لا عالميًا إن كان رفع الملف يعيد StreamableFile. map على ملف متدفق قد يحاول وضع التيار داخل { data } فيكسر الإرسال. استثناء المسار أو فحص النوع يبقى قرار المعترض قبل التحويل:

return next.handle().pipe(
  map((data) => (data instanceof StreamableFile ? data : { data })),
);

الخطوة ما زالت داخل pipe واحد.

أخطاء شائعة

  • subscribe بعد pipe داخل intercept.
  • pipe ثانٍ على ناتج اشتراك لا على تيار.
  • غلاف { data } عالمي يكسر StreamableFile و redirects.
  • خطوات بترتيب يعكس النية: تسجيل الخطأ بعد ما ابتلعه معامل سابق.

متى نستخدمه؟

في المعترض كلما أردت تحويل الرد أو تسجيله أو التقاط خطئه كسلسلة واحدة.

متى لا نستخدمه؟

لتفرع مجال معقّد. إذا صارت السلسلة أطول من بضعة أسطر، انقل القاعدة إلى الخدمة واترك pipe على العرض.

مقارنة

الأسلوب الاشتراك
return next.handle() Nest، بلا تحويل
return next.handle().pipe(...) Nest، بعد الخطوات
next.handle().subscribe() داخل المعترض أنت، وغالبًا مرة زائدة إن أرجعت التيار أيضًا

ماذا يعيد pipe؟

الحل

تيارًا جديدًا يطبّق الخطوات عند الاشتراك، لا نتيجة نهائية فورية.

تمرين متوسط

لماذا يسبق map الغلافُ فحص StreamableFile؟

الحل

حتى لا يُلف الملف المتدفق داخل كائن JSON فيتعطل إرسال StreamableFile.

تمرين متقدم

أين تضع catchError إن أردت أن ترى الخطأ قبل أن يتحول إلى قيمة؟

الحل

في المكان الذي يجب أن يمر فيه الخطأ: عادة قبل معامل يبتلع الخطأ، وبعد الخطوات التي قد ترمي.

أسئلة مراجعة

  • من يشترك في ناتج intercept؟
  • ماذا يعني ترتيب المعاملات؟
  • أي رد في المتجر لا يُغلَّف؟

الخلاصة

pipe يعلق الخطوات على تيار المعترض. أعد الناتج. لا تشترك أنت إذا كان الإطار سيشترك.

ماذا بعد؟

map يغيّر القيمة و tap ينظر إليها ويتركها.
