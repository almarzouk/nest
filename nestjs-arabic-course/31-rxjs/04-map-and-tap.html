map و tap

الهدف من هذا الدرس

التفريق بين تحويل الرد وبين أثر جانبي مثل قياس الزمن، حتى لا يغيّر السجل شكل JSON.

المشكلة التي يحلها

معترض الغلاف الذي كتبناه يستعمل map لأن الجسم يجب أن يتغير. تسجيل «استغرق 12ms» إذا وُضع في map قد يستبدل الرد بالرقم. tap يشغّل دالة ولا يمس القيمة التي تكمل إلى الخطوة التالية.

الفكرة ببساطة

map(fn) يصدر fn(value) بدل القيمة. tap(fn) يصدر القيمة نفسها بعد استدعاء fn. استعمل tap للزمن والسجل، و map لشكل العقد.

التعريف التقني

من rxjs:

import { map, tap } from 'rxjs';

source.pipe(
  tap((value) => console.log(value)),
  map((value) => ({ data: value })),
);

tap يقبل كائن ملاحظ أيضًا: { next, error, complete } إن أردت أثرًا عند الفشل من غير التقاطه. tap لا يبتلع الخطأ. هو ينظر ثم يعيد إصداره.

map الذي يرمي ينقل التيار إلى حالة خطأ. لا تضع try/catch فارغًا داخل map وتُرجع undefined فيصبح الرد {"data": null} صامتًا.

Mental Model

قيمة المتحكم
  tap  سجّل الزمن، مرّر القيمة
  map  غيّر شكل العقد
  JSON

أبسط مثال

import { Injectable, NestInterceptor, ExecutionContext, CallHandler } from '@nestjs/common';
import { map, Observable, tap } from 'rxjs';

@Injectable()
export class CatalogInterceptor implements NestInterceptor {
  intercept(_context: ExecutionContext, next: CallHandler): Observable<unknown> {
    const started = Date.now();
    return next.handle().pipe(
      tap(() => console.log(`catalog ${Date.now() - started}ms`)),
      map((data) => ({ data })),
    );
  }
}

شرح المثال

started يُلتقط عند بناء السلسلة، أي عند دخول الطلب، قبل أن يشترك الإطار. عند وصول القيمة يحسب tap الفرق ويطبعه، ثم map يغلّف الجسم. لو انعكس الترتيب، الغلاف لا يغيّر الزمن كثيرًا هنا، لكن tap بعد map كان سيطبع الشكل المغلف. ضع القياس حيث تريد أن ترى القيمة: قبل التحويل لترى جسم المتحكم.

console.log مؤقت. الفصل 37 يستبدله بـ Logger. لا تسجّل data كاملة إن كانت تحمل بريدًا أو رمزًا.

ماذا يحدث داخليًا؟

المشترك يستلم خرج آخر معامل. tap يعيد إصدار نفس المرجع. إن غيّرت خصائص الكائن داخل tap فأنت تغيّر الجسم رغم أن المعامل «لا يحوّل». مرّر الكائن للقراءة فقط. map يجب أن يعيد كائنًا جديدًا { data } لا أن يعدل الدخل ثم يعيده، حتى يبقى شكل المتحكم سليمًا إن وصل إلى معترض آخر.

مثال عملي

إخفاء حقل قبل العميل، وهذا تحويل فيبقى map:

map((book: { id: string; title: string; costPrice?: number }) => ({
  id: book.id,
  title: book.title,
})),

costPrice يسقط من العقد. الأفضل أصلًا ألا يخرج من @ObjectType أو من DTO. إن وصل من خدمة قديمة، map آخر خط دفاع على مسار REST لا مكان لإخفاء المجال كله.

أخطاء شائعة

  • إرجاع رقم من tap وانتظار أن يصبح الرد.
  • طباعة جسم فيه Authorization أو جلسة.
  • تعديل الكائن داخل tap.
  • map يغلّف StreamableFile.

متى نستخدمه؟

tap لزمن أو عدّاد. map لشكل رد متفق عليه على المسار.

متى لا نستخدمه؟

لا تخفِ costPrice في المعترض إن كان DTO أصلًا لا يتضمنه. ولا تستخدم map لالتقاط الأخطاء. ذلك catchError.

مقارنة

المعامل القيمة التالية مناسب لمتجر الكتب
tap نفسها زمن الكتالوج
map ناتج الدالة { data } أو إسقاط حقل

تمارين

تمرين سهل

أي معامل يطبع الزمن ويبقي JSON المتحكم؟

الحل

tap.

تمرين متوسط

لماذا يُؤخذ Date.now() قبل pipe لا داخله فقط عند الطباعة؟

الحل

لأن بداية القياس لحظة دخول intercept، قبل تنفيذ المتحكم عند الاشتراك. داخل tap الوقت هو لحظة وصول القيمة، وتحتاج البداية من الإغلاق الخارجي.

تمرين متقدم

tap عدّل book.title. ماذا يصل العميل ولماذا هذا خلل؟

الحل

يصل العنوان المعدّل لأن tap يمرر المرجع نفسه. الأثر الجانبي غيّر كائن المجال. اقرأ فقط، وحوّل في map بكائن جديد.

أسئلة مراجعة

  • ما خرج map مقارنة بدخله؟
  • هل tap يوقف الخطأ؟
  • أي حقل لا يُسجَّل مع الزمن؟

الخلاصة

map للعقد و tap للملاحظة. لا تغيّر الكائن الذي يمر عبر tap، ولا تسجّل الأسرار مع الزمن.

ماذا بعد؟

catchError: ماذا يحدث عندما يرمي المتحكم أو يفشل التيار.
