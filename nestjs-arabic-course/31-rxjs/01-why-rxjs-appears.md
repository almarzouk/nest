# لماذا تظهر RxJS داخل Nest

## الهدف من هذا الدرس

معرفة المواضع التي يعيد فيها Nest تيارًا، حتى لا تُستورد المكتبة كلها بحثًا عن دالة.

## المشكلة التي يحلها

معترض يغلّف الرد، أو عميل HTTP في الفصل التالي، يعيد `Observable` لا وعدًا. من يعامل القيمة كأنها `Promise` ينادي `then` على كائن بلا `then`، أو يشترك مرتين فيبدأ الطلب الخارجي مرتين. العكس أيضًا وارد: تحويل كل شيء إلى وعد ثم فقدان سبب وجود `pipe`.

## الفكرة ببساطة

`Observable` يمثل قيمًا قد تصل لاحقًا، صفر مرة أو أكثر، ويمكن إلغاؤها. Nest تشترك في التيار الذي يعيده المعالج أو المعترض عندما يكون من هذا النوع. المواضع التي تهم هذه الدورة: معترض يحوّل الرد، و `HttpService` في `@nestjs/axios` الذي يعيد تيارًا لكل طلب. الباقي من RxJS ليس فرضًا.

## التعريف التقني

مكتبة `rxjs` مدمجة مع Nest. ما سنستعمله:

| الاسم | دوره هنا |
| --- | --- |
| `Observable` | التيار الذي تعيده دالة |
| `pipe` | تركيب معاملات على التيار |
| `map` | تحويل القيمة |
| `tap` | أثر جانبي بلا تغيير القيمة |
| `catchError` | استبدال الخطأ أو إعادة رميه |
| `timeout` | فشل إن تأخرت القيمة |
| `firstValueFrom` | أخذ أول قيمة كوعد عندما تريد `await` |

`HttpClient` في حزمة `@nestjs/http-client` الحالية يعيد وعودًا مبنية على `fetch`. الفصل التالي يدرس `HttpModule` و `HttpService` من `@nestjs/axios` لأنهما يعيدان `Observable`، والحزمة ما زالت متاحة. لا تفترض أن كل عميل HTTP في التوثيق تيار.

المعترض الذي يعيد `next.handle().pipe(...)` هو المثال الداخلي الأشهر. Nest تشترك مرة واحدة في الناتج.

## Mental Model

```text
دالة تعيد Observable
  Nest تشترك
    قيم -> الرد أو الطلب الخارجي
    خطأ -> طبقة الاستثناء إن لم يُلتقط
  اكتمال -> نهاية الاشتراك
```

## أبسط مثال

معترض يسجّل زمن المعالجة بلا تغيير الجسم. التفاصيل في `tap` لاحقًا. هنا شكل الإرجاع فقط:

```ts
import { CallHandler, ExecutionContext, NestInterceptor } from '@nestjs/common';
import { Observable } from 'rxjs';

export class TimingInterceptor implements NestInterceptor {
  intercept(_context: ExecutionContext, next: CallHandler): Observable<unknown> {
    return next.handle();
  }
}
```

`next.handle()` تيار الرد القادم من المتحكم. إرجاعه كما هو يعني «لا تحويل». التحويل يكون `pipe` في الدرس الثالث.

## شرح المثال

التوقيع يعيد `Observable<unknown>` لا `Promise`. لو كتبت `async intercept` ثم `return await next.handle()` فأنت تنتظر كائن تيار لا جسم الرد. الاشتراك مسؤولية الإطار عندما تمرر التيار له. اشتراك يدوي داخل `intercept` بالإضافة إلى الإرجاع يشغّل السلسلة مرتين.

## ماذا يحدث داخليًا؟

المتحكم قد يعيد قيمة عادية. Nest تغلّفها في تيار قيمة واحدة حتى تمر المعترضات على الشكل نفسه. المعترض الخارجي يشترك في تيار المعترض الداخلي. عند الإكمال تُسلسَل القيمة إلى HTTP. خطأ في التيار يدخل المرشحات إن لم يلتقطه `catchError`. لهذا تظهر RxJS في مسار الطلب حتى في تطبيق لا يستدعي `HttpService`.

## مثال عملي

قرار المتجر:

| المكان | الشكل |
| --- | --- |
| خدمة الكتب | `async` ووعد، لأن Prisma وعد |
| معترض زمن أو غلاف رد | `Observable` عبر `next.handle().pipe` |
| استدعاء API غلاف خارجي لاحقًا | تيار `HttpService` أو `firstValueFrom` إن أردت `await` |

لا تحوّل `BooksService` إلى تيار حتى «تشبه المعترض».

## أخطاء شائعة

- `subscribe` داخل المعترض وإرجاع التيار نفسه.
- استيراد عشرات المعاملات لنسخ مثال لوحة.
- معاملة كل عميل HTTP في توثيق Nest 12 كأنه `HttpService`.
- تجاهل التيار وتحويله دائمًا إلى وعد داخل المعترض، فتصعب سلسلة المعترضات.

## متى نستخدمه؟

عندما تعيد الدالة تيارًا يكمّله الإطار: معترض، أو طلب Axios المغلف الذي ستدرسه بعد هذا الفصل.

## متى لا نستخدمه؟

في خدمة مجال ترجع صفًا واحدًا بـ `async`. الوعد أوضح. ولا في بوابة WebSocket التي كتبناها بأحداث Socket.IO.

## مقارنة

| الإرجاع | من يشغّل العمل |
| --- | --- |
| قيمة عادية | Nest تغلفها |
| `Promise` | Nest تنتظره |
| `Observable` | Nest تشترك فيه |

## أسئلة مراجعة

- من يشترك في تيار المعترض؟
- أي ستة أسماء ستكفي هذا الفصل؟
- أي حزمة HTTP تعيد تيارًا وأي حزمة حديثة تعيد وعدًا؟

## الخلاصة

RxJS تظهر لأن Nest تمرر الرد كتيار في المعترضات، ولأن `HttpService` يعيد تيارًا. لا تحوّل المجال كله إلى مكتبة تيارات.

## ماذا بعد؟

ما الذي يمثله `Observable` عند الاشتراك والإلغاء، بمثال أصغر من المعترض.
