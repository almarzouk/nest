Observable

الهدف من هذا الدرس

إنشاء تيار قيمة واحدة والاشتراك فيه مرة، ورؤية أن العمل يبدأ عند الاشتراك لا عند بناء الكائن.

المشكلة التي يحلها

الدالة التي تعيد new Observable(...) لا تنفّذ المصنع حتى ينادي أحد subscribe. في HTTP هذا يعني أن الطلب لا يخرج من العملية عند استدعاء http.get فقط. من يبني التيار ثم يمرره إلى Nest يترك الإطار يشترك. من يشترك ثم يمرر التيار نفسه قد يرسل الطلب مرتين.

الفكرة ببساطة

Observable وصفة. subscribe يشغّلها. الملاحظ يستلم next ثم complete أو error. تيار HTTP المعتاد قيمة واحدة ثم اكتمال. الإلغاء عبر كائن الاشتراك يهم عندما يغادر العميل قبل أن يصل الرد.

التعريف التقني

import { Observable } from 'rxjs';

const titles = new Observable<string>((subscriber) => {
  subscriber.next('NestJS in Practice');
  subscriber.complete();
});

حتى هذا السطر لم تُطبع شيء ولم تُستدعَ الدالة الداخلية من أجل مستهلك. الاستهلاك:

const subscription = titles.subscribe({
  next: (title) => console.log(title),
  error: (error) => console.error(error),
  complete: () => console.log('done'),
});

subscription.unsubscribe() يوقف الملاحظ. إن كان المصنع أعاد دالة تنظيف، تُستدعى عند الإلغاء.

تيار بلا complete يبقى مفتوحًا. لا تفعل ذلك في معترض HTTP. الرد قيمة ثم اكتمال.

Mental Model

بناء Observable     وصفة صامتة
subscribe           يبدأ العمل
next                قيمة
complete أو error   نهاية
unsubscribe         إلغاء إن تأخرت النهاية

أبسط مثال

دالة متجر تعيد عنوانًا كتيار، للتجربة لا للاستبدال عن الخدمة:

import { Observable, of } from 'rxjs';

export function titleOf(bookId: string): Observable<string> {
  return of(`book-${bookId}`);
}

of يصدر القيم ثم يكتمل. titleOf('42') لا يطبع. الطباعة في subscribe أو عندما تعيد الدالة التيار إلى Nest فتشترك هي.

شرح المثال

of مناسب لاختبار سلسلة pipe بلا شبكة. لا تستخدمه لإخفاء استدعاء Prisma. الخدمة تبقى async. هذا المثال يوضح كسل التيار: بناء titleOf رخيص، والمشترك هو من يسحب القيمة.

ماذا يحدث داخليًا؟

كل subscribe على تيار بارد يشغّل المصنع من جديد. http.get في الفصل التالي بارد: اشتراكان يعنيان طلبين. تيار ساخن يشارك تنفيذًا قائمًا، وليس ما تحتاجه لطلب HTTP واحد. لذلك لا تخزّن نتيجة http.get في حقل وتشاركها بين طلبات مستخدمين. ابنِ التيار داخل الدالة واترك مشتركًا واحدًا.

firstValueFrom(source) يشترك وينتظر أول next ثم يلغي. إن أكمل التيار بلا قيمة يرفض الوعد. هذا الجسر إلى await عندما لا تريد تمرير التيار إلى Nest.

مثال عملي

في اختبار معترض، ادفع قيمة واحدة:

import { of } from 'rxjs';
import { lastValueFrom } from 'rxjs';

const handled = await lastValueFrom(interceptor.intercept(ctx, { handle: () => of({ title: 'NestJS' }) }));

lastValueFrom ينتظر الاكتمال. لتيار of القيمة الأخيرة هي الوحيدة. لا تشترك في الاختبار يدويًا ثم تنادي lastValueFrom على التيار نفسه إن كان باردًا ويطلق أثرًا جانبيًا مرتين. هنا of بلا أثر، لكن العادة تبقى: مشترك واحد.

أخطاء شائعة

  • الاعتقاد أن new Observable نفّذ العمل.
  • اشتراكان على طلب HTTP بارد.
  • تيار لا يكتمل في مسار HTTP.
  • تخزين تيار الطلب على مزوّد singleton.

متى نستخدمه؟

عندما تبني سلسلة ستشترك فيها Nest مرة، أو عندما تختبرها بـ lastValueFrom / firstValueFrom.

متى لا نستخدمه؟

كغلاف حول كل دالة خدمة. return title يكفي داخل BooksService.

تمارين

تمرين سهل

هل of('NestJS') وحده يطبع العنوان؟

الحل

لا. الطباعة عند الاشتراك أو عند من يشترك نيابة عنك.

تمرين متوسط

ماذا يحدث لطلب HTTP بارد إن اشتركت مرتين؟

الحل

يخرج الطلب مرتين. كل اشتراك يشغّل المصنع.

تمرين متقدم

متى تختار firstValueFrom بدل إرجاع التيار؟

الحل

عندما تريد await داخل خدمة ولا يوجد معترض ينتظر التيار. في المعترض أعد التيار حتى تكتمل السلسلة.

أسئلة مراجعة

  • ما الفرق بين بناء التيار والاشتراك؟
  • لماذا الاكتمال مهم لمسار HTTP؟
  • أي دالة تحول أول قيمة إلى وعد؟

الخلاصة

Observable وصفة باردة حتى الاشتراك. مسار HTTP يريد قيمة ثم complete، ومشتركًا واحدًا لكل طلب خارجي.

ماذا بعد؟

pipe: كيف تركّب خطوات على الوصفة قبل أن يشترك الإطار.
