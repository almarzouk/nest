ملفات .env

الهدف من هذا الدرس

تشغيل المكتبة محليًا بملف مفاتيح، من غير رفع الأسرار، ومن غير الخلط بين ملف التطوير وبيئة الإنتاج.

المشكلة التي يحلها

تصدير عشر متغيرات في الطرفية قبل كل npm run start:dev ينكسر حين تنسى واحدًا. وضع القيم في src/config.ts يعيدها إلى Git. ملف .env وسط بين الاثنين: المفاتيح في المشروع، والقيم السرية على جهازك فقط.

الفكرة ببساطة

.env قائمة KEY=value يقرأها dotenv عند الإقلاع. .env.example يُرفع وفيه أسماء المفاتيح من غير أسرار. .gitignore يمنع .env. على الإنتاج تضبط المنصة المتغيرات نفسها، والملف المحلي لا يُنسخ إلى الخادم.

التعريف التقني

@nestjs/config يستخدم dotenv. ConfigModule.forRoot() يبحث عن .env في مجلد تشغيل العملية، غالبًا جذر المشروع، ثم يدمج المفاتيح مع process.env. إن وُجد المفتاح في الاثنين، قيمة التشغيل تربح. override: true يعكس ذلك فيجعل ملف .env يربح.

envFilePath يبدّل المسار أو يمرّر مصفوفة. أول ملف يحتوي المفتاح يربح. ignoreEnvFile: true يتجاهل الملف ويقرأ بيئة التشغيل فقط، وهذا مناسب للإنتاج حين لا تريد ملفًا على القرص.

تعارض الأسماء يتبع قواعد dotenv. التوسعة ${APP_URL} تحتاج expandVariables: true، والحزمة تستخدم dotenv-expand داخليًا.

CLI يستطيع تحميل الملف قبل إقلاع Nest نفسه:

nest start --env-file .env

هذا يمرّر الملف إلى علم Node --env-file، فيصبح المتغير متاحًا حتى قبل تحميل ConfigModule، مثل خيار يُمرَّر إلى NestFactory.create.

Mental Model

.env.example   -> Git        PORT=
                               DATABASE_URL=
.env           -> جهازك فقط  PORT=3000
                               DATABASE_URL=postgresql://...
الإنتاج        -> لوحة المنصة بلا ملف في الصورة إن أمكن

أبسط مثال

# .env.example
PORT=3000
DATABASE_URL=
LIBRARY_NAME=neighborhood-library

# .gitignore
.env
.env.local
.env.*.local

import { Module } from "@nestjs/common";
import { ConfigModule } from "@nestjs/config";

@Module({
  imports: [
    ConfigModule.forRoot({
      envFilePath: [".env.local", ".env"],
    }),
  ],
})
export class AppModule {}

شرح المثال

.env.local يسبق .env، فقيمة جهازك الشخصية تغلب القيمة المشتركة للتطوير. LIBRARY_NAME ليس سرًا ويمكن أن يبقى في المثال. DATABASE_URL في المثال فارغ عمدًا: من ينسخ الملف يضع عنوانه هو.

لا تكتب كلمة مرور حقيقية في أي ملف يُراجع في Git، بما في ذلك تعليقات الدروس والمستودع.

ماذا يحدث داخليًا؟

forRoot() يحلّل الملف أثناء تسجيل الوحدة، ويدمج الناتج في بنية خاصة يقرأها ConfigService لاحقًا. المفاتيح التي لم تُذكر في الملف تبقى آتية من بيئة العملية: PATH و HOME وغيرهما.

إن غاب الملف ولم يُضبط ignoreEnvFile، الإقلاع لا يتوقف لهذا السبب وحده. النقص يظهر حين تطلب الخدمة مفتاحًا غير موجود. درس التحقق يجعل النقص يفشل الإقلاع.

مثال عملي

مطوّر جديد ينسخ .env.example إلى .env، يملأ DATABASE_URL لقاعدة PostgreSQL محلية، ويشغّل npm run start:dev. زميله يملك ملفًا مختلفًا على جهازه. خادم الإنتاج لا يحتوي أيًا من الملفين: المنصة تضبط PORT و DATABASE_URL، ويمكن للتطبيق أن يمرّر ignoreEnvFile: true هناك حتى لا يلتقط ملفًا نُسي داخل الصورة.

قيمة مثل SUPPORT_EMAIL=desk@${LIBRARY_DOMAIN} تعمل بعد expandVariables: true. من غير الخيار تبقى السلسلة حرفية وفيها ${...}.

أخطاء شائعة

  • رفع .env بعد git add . لأن الاستثناء نُسي.
  • وضع سر الإنتاج داخل .env.example «ليعمل بسرعة».
  • الاعتماد على ترتيب المصفوفة من غير تجربته: الأول يربح، لا الأخير.
  • افتراض أن ملف .env يُحمَّل في اختبار Jest تلقائيًا كما في nest start.

متى نستخدمه؟

لتطوير محلي واختبارات على جهازك، مع مثال بالمفاتيح فقط.

متى لا نستخدمه؟

كمخزن أسرار الإنتاج داخل صورة Docker أو المستودع. المنصة أو مدير أسرار يحقن البيئة عند التشغيل.

مقارنة

.env .env.example بيئة الإنتاج
قيم حقيقية محلية أسماء، وقيم غير سرية قيم حقيقية خارج Git
في .gitignore يُراجع في Git غالبًا بلا ملف

تمارين

تمرين سهل

ماذا تضع في .env.example لمفتاح JWT_SECRET؟

الحل

اسم المفتاح وقيمة فارغة أو وصفًا، مثل JWT_SECRET=. السر الحقيقي يبقى في .env المحلي أو في مدير الأسرار.

تمرين متوسط

PORT موجود في .env بالقيمة 3000 وفي الصدفة بالقيمة 4000. ماذا يقرأ ConfigModule.forRoot() افتراضيًا؟

الحل

4000. بيئة التشغيل تربح. override: true يجعل ملف .env يربح.

تمرين متقدم

لماذا قد تحتاج nest start --env-file .env حتى بعد تسجيل ConfigModule؟

الحل

بعض القراءات تحدث قبل تهيئة الوحدة، مثل خيار يُمرَّر إلى NestFactory.create. علم CLI يحمّل الملف إلى process.env قبل إقلاع التطبيق. بعد الإقلاع تبقى قراءة الخدمات عبر ConfigService.

أسئلة مراجعة

  • أي ملف يُرفع، وأي ملف يبقى على الجهاز؟
  • من يربح عند تعارض المفتاح بين الصدفة و .env؟
  • ماذا يفعل ignoreEnvFile؟

الخلاصة

ملف .env أداة تطوير. المثال يوثّق المفاتيح، والاستثناء يمنع الأسرار، والإنتاج يحقن البيئة من خارج المستودع.

ماذا بعد؟

ConfigModule يسجّل هذا التحميل كوحدة Nest ويقرّر إن كانت عامة.
