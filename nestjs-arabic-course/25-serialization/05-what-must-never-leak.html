ما لا يجوز أن يخرج

الهدف من هذا الدرس

تثبيت قائمة ما يبقى داخل الخادم لمكتبة المقالات، وكيف نمنع تسربه في JSON والسجلات والوثيقة.

المشكلة التي يحلها

فريق أخفى password ونسي أن العمود صار passwordHash. أو أخفى الجسم وأعاد التجزئة في رسالة 409 عند تكرار البريد. أو وضع الرمز في مثال Swagger. أو سجّل dto بعد الدمج مع الصف. العميل أو ملف السجل يصبح نسخة من أسرار الدخول.

الفكرة ببساطة

لا يغادر الشبكة: كلمة المرور، passwordHash، رمز الجلسة الخام، تجزئة رمز الجلسة، رمز التحديث الخام، مفتاح HMAC، ومفتاح تشفير الملاحظات. يخرج: id و email و role وبيانات المقال العامة. المنع طبقات: select، صنف استجابة، @Exclude أو مخطط، وثيقة بلا الحقل، وسجل لا يطبع الصف.

التعريف التقني

السر أين يعيش ماذا يرى العميل
password طلب الدخول فقط لا شيء بعد المعالجة
passwordHash عمود المستخدم غائب عن JSON
__Host-sid كعكة HttpOnly لا جسم يعيدها
تجزئة الجلسة مخزن الجلسات غائبة
refresh الخام قناة الجوال عند الإصدار مرة واحدة في استجابة الدخول المخصصة، لا في GET
مفتاح AES بيئة أو مدير أسرار غائب

استجابة الدخول للجوال التي تصدر accessToken و refresh هي العقد الذي صممته في المصادقة، لا استثناءً عشوائيًا. لا تعِد تلك الرموز من GET /me. لا تضع refresh في JSON واجهة المتصفح إن كانت الجلسة بالكعكة.

select: { id: true, email: true, role: true }

هذا الجلب لا يحمّل التجزئة إلى Node. toResponse لا يملك ما ينسخه. إن احتاج verify التجزئة فذلك في signIn فقط، والناتج للعميل UserResponse زائد الكعكة أو الرموز عبر مسار الإصدار.

اختبار:

expect(res.body.passwordHash).toBeUndefined();
expect(JSON.stringify(res.body)).not.toContain("$scrypt$");

رسالة الخطأ من ConflictException نص ثابت مثل Email already registered. لا تمرّر error.meta من Prisma إلى العميل. P2002 قد يتضمن حقولًا. المرشح يترجم الرمز إلى 409 بلا meta خام.

Swagger: UserResponse بلا الخاصية. لا example فيه سلسلة $scrypt. إضافة CLI على كيان كامل تُراجع مع @ApiHideProperty أو تُستبعد من type.

السجل: سجّل userId لا الصف. password في RegisterDto لا يدخل Logger.

Mental Model

أسرار في الجدول والبيئة والكعكة
عقد الشبكة أضيق
الاختبار يفشل إن ظهر $scrypt$
الخطأ العام بلا meta من Prisma

أبسط مثال

@Get("me")
me(@CurrentUser("id") id: string) {
  return this.users.findPublic(id);
}

شرح المثال

findPublic يجلب select الضيق. حتى لو تعطّل الاعتراض، الجسم بلا تجزئة. @CurrentUser() قد يكون الكائن الذي حمّله validate. تأكد أن ذلك الكائن نفسه لا يُعاد إن كان يحمل التجزئة. أعد التحميل بـ select أو انسخ الحقول العامة. إرجاع نتيجة validate مباشرة سبب تسريب متكرر.

ماذا يحدث داخليًا؟

JSON.stringify ينشر المفاتيح القابلة للعد. undefined تُحذف، لذا @Exclude ينجح. قيمة null تبقى مفتاحًا. لا تضع passwordHash: null كتمويه. احذف المفتاح. رؤوس الاستجابة ليست مكانًا للتجزئة أيضًا. Set-Cookie للجلسة يضبطه SignInService بقيمة عشوائية لا بـ userId.

ملف HAR من المتصفح فيه الكعكة إن سجّل المطوّر الشبكة. ذلك سر جلسة. لا ترفق HAR في تذكرة.

مثال عملي

راجع أربعة مخارج: جسم POST /users، جسم GET /me، جسم خطأ التكرار، وسطر السجل في signIn. كل منها يفشل الاختبار إن احتوى password أو passwordHash أو بادئة $scrypt$. راجع GET /posts/:id مع include للمؤلف. ثم راجع api-json بالبحث عن passwordHash. النتيجة الفارغة هي المطلوبة.

مسار إصدار الرمز للجوال يُختبر وحدَه: الرمز حاضر هناك وغائب في الطلب التالي لـ GET /me.

أخطاء شائعة

  • إخفاء password والإبقاء على passwordHash.
  • throw new ConflictException(user).
  • إرجاع مستخدم validate() كما حُمّل.
  • مثال OpenAPI واقعي لسر.
  • console.log(dto) في التسجيل.

متى نستخدمه؟

القائمة تطبق على كل مسار جديد قبل دمجه، لا بعد بلاغ.

متى لا نستخدمه؟

لإخفاء مقال مسودة عن غير صاحبه عبر حذف JSON فقط. الاستعلام لا يجلب المسودة لغير المالك. التسلسل لا يصلح قرار الوجود.

مقارنة

select ضيق @Exclude فقط
السر لا يدخل الذاكرة للمسار السر يُنسخ ثم يُحذف
يحمي إن سقط الاعتراض يحمي شكل JSON عند تفعيل الاعتراض
لا يغطّي السجل إن سجّلت صفًا آخر لا يغطّي السجل

تمارين

تمرين سهل

أي بادئة في JSON تعني أن تجزئة scrypt خرجت؟

الحل

$scrypt$. الاختبار يبحث عنها في النص المسلسل.

تمرين متوسط

لماذا ConflictException لا تحمل كائن المستخدم؟

الحل

جسم الخطأ يذهب إلى العميل. النص الثابت يكفي. meta من Prisma قد يزيد على ذلك.

تمرين متقدم

validate تعيد المستخدم مع التجزئة لتتحقق من حالة الحساب، ثم يعيدها GET /me. ماذا تغيّر؟

الحل

لا تعد كائن التحقق. أعد UserResponse من حقول عامة أو أعد الجلب بـ select بلا passwordHash.

أسئلة مراجعة

  • ما الحقول العامة للمستخدم؟
  • أين يجوز أن يظهر refresh؟
  • ماذا تفعل select زيادة على الاعتراض؟

الخلاصة

أسرار الدخول والجلسة والمفاتيح لا تدخل JSON ولا السجل ولا أمثلة الوثيقة. الجلب الضيق وصنف الاستجابة والاختبار الذي يبحث عن $scrypt$ يغلقون المسار الذي تنساه المزخرفات.
