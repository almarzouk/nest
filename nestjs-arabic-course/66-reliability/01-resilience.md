# Resilience

## الهدف من هذا الدرس

وضع حد زمني وقاطع وبديل حول نداء رف إلى فهرس أو شريك بطيء، عبر `@nestjs/resilience`، من غير إعادة `POST` مالي بلا مفتاح.

## المشكلة التي يحلها

`publish` ينتظر اقتباس الشحن حتى تنتهي مهلة المتصفح. أو يعيد المحاولة خمس مرات على خصم رصيد فيتكرر الخصم. عندما يسقط الشريك تبقى كل الطلبات معلقة خلفه.

## الفكرة ببساطة

الحزمة تضع سياسات على مداخل التطبيق: مهلة، إعادة، قاطع، حاجز تزامن، وبديل. المهلة على HTTP تصبح 504. القاطع المفتوح 503 مع `Retry-After`. إعادة `POST` الذي له أثر تكون مع `@Idempotent` من الحزمة المجاورة لا وحدها. داخل الخدمة نفس السياسات ككائنات لا كديكور فقط.

## التعريف التقني

`npm i @nestjs/resilience` ثم `ResilienceModule`. الديكورات من الحزمة: `@Timeout` و `@Retry` و `@Fallback` و `@Bulkhead` مع `@Resilience`. `@Timeout` يجيب 504. القاطع المفتوح 503. `@Fallback` يقدر أن يعيد تقديرًا ثابتًا عند `CircuitOpenError`. الديكور على المتحكم والـ resolver ورسائل الخدمات المصغرة والبوابة. `ResilienceService` يبني سياسة للكود داخل الخدمة. لا تضعوا السياسة على خصم Stripe بلا مفتاح idempotency.

## Mental Model

```text
نداء شريك
  مهلة → 504
  أخطاء متكررة → قاطع → 503
  POST مالي → لا إعادة بلا مفتاح
```

## أبسط مثال

```ts
import { Get } from '@nestjs/common';
import { Resilience, Timeout } from '@nestjs/resilience';

@Get('quote')
@Resilience(Timeout('2s'))
quote() {
  return this.carrier.quote();
}
```

## شرح المثال

- ثانيتان ميزانية للمدخل لا حلقة داخلية بلا سقف.
- انتهاء المهلة 504 لا 500 غامض.
- القراءة آمنة للإعادة أكثر من النشر.

## ماذا يحدث داخليًا؟

1. المعترض العام للحزمة يطبّق الديكور على المدخل.
2. إن تجاوز النداء المهلة يُلغى الانتظار ويُكتب 504.
3. إن تراكمت الأعطال يفتح القاطع ويرد 503 فورًا مع `Retry-After` حتى لا تُضرب الخدمة الميتة.
4. `@Fallback` يعمل عند فتح القاطع إن عرّفتم بديلًا.
5. `@Retry` يعيد النداء. على `POST` الذي ينشئ أثرًا اربطوه بـ `@Idempotent` كما تفعل صفحة Resilience في مثالها.

## مثال عملي

اقتباس شحن لغلاف رف ليس نشر الكتاب. إن فتح القاطع أعيدوا سعر شحن افتراضيًا معلنًا في العقد، ولا تنشروا المشروع بناءً على هذا الافتراض كأنه تأكيد الناقل.

```ts
import { CircuitOpenError, Fallback, Resilience, Timeout } from '@nestjs/resilience';

@Resilience(Timeout('2s'), Fallback(CircuitOpenError, () => ({ amount: 1500, estimated: true })))
```

`publish` نفسه لا يُلف بإعادة عمياء. حالة المشروع تُكتب في قاعدتكم مرة.

## أخطاء شائعة

- `@Retry` على `POST /billing/checkout` بلا مفتاح.
- مهلة أطول من مهلة الموازن فيُقطع العميل والنداء يكمل.
- بديل القاطع يكتب `published`.
- وضع الديكور على دالة خاصة وظن أنه يعمل؛ الصفحة تخص المداخل، وداخل الخدمة استخدموا السياسة.

## متى نستخدمه؟

حول اعتمادية خارجية قد تبطؤ أو تسقط، على مدخل واضح.

## متى لا نستخدمه؟

لا تستبدلوا به عزل المستأجر ولا توقيع الويب هوك. ولا تعيدوا أثرًا غير مكرر.

## مقارنة

| السياسة | رد HTTP النموذجي | على النشر المالي |
| --- | --- | --- |
| Timeout | 504 | ميزانية انتظار لا تكرار أثر |
| قاطع مفتوح | 503 و `Retry-After` | لا تفعيل خطة |
| Retry | نفس المسار | مع `@Idempotent` فقط |
| Fallback | جسم بديل | قراءة لا كتابة حالة |

## تمارين

### تمرين سهل

ماذا يرى العميل عندما تتجاوز مهلة الاقتباس؟

<details>
<summary>الحل</summary>

504. القاطع المفتوح لاحقًا 503 مع `Retry-After`.

</details>

### تمرين متوسط

لماذا إعادة Checkout بلا مفتاح خطر؟

<details>
<summary>الحل</summary>

كل محاولة قد تنشئ جلسة أو أثرًا جديدًا. الصفحة تربط إعادة `POST` الآمنة بـ `@Idempotent`.

</details>

### تمرين متقدم

البديل أعاد `estimated: true`. هل `PlanPolicy` تعتبر الخطة `active`؟

<details>
<summary>الحل</summary>

لا. البديل اقتباس عرض. حالة الاشتراك تبقى من الحدث الموقّع. لا تكتبوا `active` من مسار الاحتياطي.

</details>

## أسئلة مراجعة

- أي حزمة؟
- ما رمز المهلة ورمز القاطع؟
- أين تعمل الديكورات؟
- متى تُمنع الإعادة؟

## الخلاصة

`@nestjs/resilience` يحد النداء الخارجي بمهلة وقاطع وبديل. 504 و 503 ردود مدخل لا أسرار. الأثر المالي لا يُعاد بلا مفتاح.

## ماذا بعد؟

المفتاح الذي يجعل الإعادة آمنة هو درس `@nestjs/idempotency` على مسار رف.
