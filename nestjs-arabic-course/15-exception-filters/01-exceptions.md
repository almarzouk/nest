# Exceptions

## الهدف من هذا الدرس

معرفة ماذا يحدث لاستثناء لم تمسكه أنت داخل تطبيق Nest، وماذا يحدث لاستثناء ابتلعته.

## المشكلة التي يحلها

`throw new Error('seat')` في الخدمة يخرج من العملية كصفحة HTML أو كاتصال مقطوع إن لم توجد طبقة ترد JSON. وفي الجهة الأخرى `try/catch` فارغ يخفي العطل ويرجع `200`.

## الفكرة ببساطة

الاستثناء غير الممسوك يصل إلى طبقة الاستثناءات. `HttpException` يُترجم إلى رمزه. الخطأ غير المعروف يصبح `500` بجسم عام. الاستثناء الذي تمسكه بنفسك لا يصل إلى الفلتر.

## التعريف التقني

Nest يملك فلترًا عامًا مدمجًا. يتعامل مع `HttpException` وفئاتها. غير ذلك الرد الافتراضي:

```json
{
  "statusCode": 500,
  "message": "Internal server error"
}
```

تلميح الصفحة: أخطاء مكتبة `http-errors` التي تحمل `statusCode` و `message` بالشكل الذي تعرفه الطبقة تُعاد بتلك القيم بدل `500` الأعمى.

الفلاتر التي تكتبها أنت لاحقًا تشارك هذه الطبقة. هذا الدرس لا يكتب `@Catch` بعد. يثبت القاعدة: ما لم يُلتقط يصعد، وما التُقط لا يصعد.

دورة الطلب تقول: الفلاتر تعمل عند استثناء غير ممسوك أثناء معالجة الطلب. `try/catch` الذي لا يعيد الرمي يمنع الفلتر. عند أول استثناء غير ممسوك تُتخطى بقية الدورة نحو الفلتر.

مكان الرمي يغيّر أي فلتر يراه:

- من Middleware: الفلاتر العامة فقط، لأن المعالج لم يُختر.
- من حارس أو أنبوب أو متحكم أو خدمة: من فلتر المسار إلى المتحكم إلى العام.

الخدمة التي ترمي والخادم الذي يمسك في المتحكم يقطع الطريق. الفلتر يرى ما يخرج من المتحكم لا ما حدث داخل `catch`.

## Mental Model

```text
throw في الخدمة
  try/catch في المتحكم يعيد قيمة → الفلتر لا يرى شيئًا
  لا catch → فلتر المسار أو المتحكم أو العام
throw في Middleware → فلتر عام فقط
```

## أبسط مثال

```ts
@Get(':id')
find(@Param('id') id: string): never {
  throw new Error(`missing ticket ${id}`);
}
```

من غير `HttpException`، العميل يرى `500` والرسالة العامة، لا نص `missing ticket`، لأن الفلتر المدمج لا ينشر خطأً غير معروف. هذا حماية. التشخيص يبقى في السجل لا في JSON.

```ts
@Get(':id')
findSoft(): { ok: true } {
  try {
    throw new Error('missing ticket');
  } catch {
    return { ok: true };
  }
}
```

هنا الفلتر لا يعمل. العميل يرى نجاحًا كاذبًا.

## شرح المثال

- `never` في الأول يوثّق أن الدالة لا ترجع. الرمي هو المخرج.
- الرسالة داخل `Error` لا تصبح `message` في الرد الافتراضي لخطأ غير معروف.
- `catch` الفارغ يبتلع الطبقة كلها. إن أردت شكلًا مختلفًا فأعد الرمي كـ `HttpException` أو اترك الخطأ يصعد إلى فلتر كتبته.
- Middleware الذي يرمي `Error` عاديًا ما زال `500` عبر الفلتر العام فقط.

## ماذا يحدث داخليًا؟

الرمي يرفض وعد الدالة أو يقطع المكدس حتى منطقة الاستثناءات التي يلف Nest بها المسار. الفلتر المدمج يفحص نوع الخطأ. `HttpException` يعرف `getStatus()`. غيره يُكتب `500` من غير تسريب `stack` إلى العميل.

الصفحة تذكر أن `HttpException` يرث `IntrinsicException` وأن الفلتر المدمج لا يسجّل هذه العائلة في الطرفية لأنها جزء من التدفق العادي. `Error` غير المعروف يُسجَّل كعطل. لذلك اختيار النوع يغيّر الضجيج لا الرمز فقط.

`try/catch` في المعترض عبر `catchError` الذي يرجع قيمة يبتلع أيضًا: الفلتر لا يرى خطأ التيار الذي صار نجاحًا.

## مثال عملي

`TicketsService.find` ترمي `Error` حين يغيب الصف. التجربة الأولى: الرد `500` والواجهة تعرض عطل خادم رغم أن المعنى «لا تذكرة». التجربة الثانية: المتحكم يمسك ويرجع `{ ok: true }` فيختفي العطل من المراقبة. الاتجاه: ارمِ استثناء HTTP بمعنى صحيح في الدرس التالي، واتركه يصعد، ودع الفلتر المدمج أو فلترك يكتب الجسم. لا تبتلع في المتحكم إلا لتترجم إلى رمي أوضح.

## أخطاء شائعة

- اعتبار كل استثناء `500` حتى غياب السجل.
- `catch` يسجّل ثم يرجع `null` فيصير الرد فارغًا ناجحًا.
- توقع فلتر على المتحكم أن يرى رمي Middleware.
- نشر `error.stack` في JSON للعميل.

## متى نستخدمه؟

افهم القاعدة قبل أي فلتر مخصص: الصعود لغير الممسوك، والترجمة حسب النوع، والصمت حين تبتلع.

## متى لا نستخدمه؟

لا تترك `Error` عامًا لغياب تذكرة. ولا تبتلع لتوحيد الرد. الترجمة رمي `HttpException` أو فلتر يميّز الأنواع.

## مقارنة

| | غير ممسوك `Error` | غير ممسوك `HttpException` | ممسوك ولا يُعاد رميه |
| --- | --- | --- | --- |
| العميل | `500` عام | رمز الاستثناء | ما رجعته أنت |
| الفلتر | يعمل | يعمل | لا يرى |
| Middleware | عام فقط | عام فقط | لا شيء إن ابتُلع هناك |

## تمارين

### تمرين سهل

ماذا يرى العميل عند `throw new Error('x')` من الخدمة من غير فلتر مخصص؟

<details>
<summary>الحل</summary>

`500` ورسالة `Internal server error`. نص `x` لا يُنشر في الجسم الافتراضي.

</details>

### تمرين متوسط

لماذا لا يعدّل فلتر المسار رد `findSoft`؟

<details>
<summary>الحل</summary>

الاستثناء ممسوك داخل الدالة ولا يُعاد رميه. الطبقة لا تُستدعى. الرد هو `{ ok: true }`.

</details>

### تمرين متقدم

رمي من `BoxPassGuard` ورمي من Middleware كلاهما `HttpException`. أيهما يستطيع فلتر على `TicketsController` تشكيله؟

<details>
<summary>الحل</summary>

رمي الحارس، لأن المسار مختار. رمي Middleware تراه الفلاتر العامة فقط.

</details>

## أسئلة مراجعة

- متى تعمل طبقة الاستثناءات؟
- ماذا يصبح الخطأ غير المعروف؟
- ماذا يفعل `try/catch` الذي لا يعيد الرمي؟
- لماذا لا يُسرَّب المكدس في الرد الافتراضي؟

## الخلاصة

غير الممسوك يصل إلى الفلتر: `HttpException` برمزه، وغيره `500` عام. الممسوك داخل الدالة أو المحوَّل إلى قيمة نجاح لا يصل. مكان الرمي يحدد إن كان فلتر المسار مشاركًا.

## ماذا بعد؟

الدرس التالي صنف `HttpException`: الرسالة والرمز و `cause` وجسم JSON.
