# Internationalization

## الهدف من هذا الدرس

إرجاع رسالة تأكيد مسودة رف بلغة القارئ عبر `@nestjs/i18n`، مع بقاء الخدمات singleton.

## المشكلة التي يحلها

نص عربي ثابت في `NotFoundException` يظهر لقارئ إنجليزي. أو تمرير `req` إلى كل خدمة لقراءة `Accept-Language`. أو مجلد ترجمة زائد يصبح لغة بلا قرار. أو مفتاح خاطئ لا يظهر إلا في الإنتاج.

## الفكرة ببساطة

الحزمة official اسمها `@nestjs/i18n`. كتالوجات JSON، مجلد لكل locale، واسم الملف فضاء مفاتيح مثل `projects.notFound`. `I18nModule.forRoot` يركّب وسيطًا يحل اللغة مرة لكل طلب ويحفظها في `AsyncLocalStorage`. `I18nService.t` يقرأها بلا تمرير الطلب. المحلّلات بالترتيب: استعلام، ترويسة، ثم `Accept-Language`. اللغة المحفوظة في عضوية المكتبة تتقدم على لغة المتصفح بمحلّل خاص. هذه ميزة منصة تُضاف حين تتعدد لغات الواجهة، لا شرطًا لمسار رف الأساسي.

## التعريف التقني

`npm i @nestjs/i18n`. فعّلوا `resolveJsonModule` حتى يُشتق نوع المفاتيح من JSON الإنجليزي. انسخوا JSON إلى `dist` عبر `compilerOptions.assets` مثل `i18n/**/*.json` و `watchAssets`. التسجيل:

```ts
I18nModule.forRoot({
  defaultLocale: 'ar',
  supportedLocales: ['ar', 'en'],
  loader: new JsonI18nLoader({
    path: join(import.meta.dirname, 'i18n'),
  }),
  resolvers: [
    new QueryLocaleResolver('lang'),
    new HeaderLocaleResolver('x-lang'),
    new AcceptLanguageLocaleResolver(),
  ],
});
```

الاستيراد من `@nestjs/i18n` و `join` من `node:path`. الوحدة عامة. أول مرشح يطابق `supportedLocales` يفوز. `pl-PL` يلحق `pl` بلا إعداد. `fallbacks` يبقي منطقة كلغة تنسيق، مثل `de-AT` نحو رسائل `de`. بلا طلب (مهمة أو طابور) تُستخدم `defaultLocale`. الوسيط يضع `Content-Language` و `Vary` ما لم `responseHeaders: false`. `declare module '@nestjs/i18n'` يربط شكل الكتالوج حتى يفشل `projects.notFund` عند الترجمة.

## Mental Model

```text
?lang= أو x-lang أو Accept-Language
→ locale في AsyncLocalStorage
→ t('projects.confirmed') من أي singleton
```

## أبسط مثال

```ts
import { Injectable } from '@nestjs/common';
import { I18nService } from '@nestjs/i18n';

@Injectable()
export class ProjectsService {
  constructor(private readonly i18n: I18nService) {}

  confirmed(id: string, count: number) {
    return this.i18n.t('projects.confirmed', { args: { id, count } });
  }
}
```

`projects.json` الإنجليزي مصدر النوع. العربي في `src/i18n/ar/projects.json` بنفس المفاتيح، والجمع عبر `one` و `other` كما في دليل الصفحة.

## شرح المثال

- الخدمة لا تستقبل `Request`. اللغة في المخزن طوال الطلب.
- `defaultLocale: 'ar'` يناسب رف حين يغيب الترويسة. واجهة إنجليزية ترسل `Accept-Language: en`.
- `supportedLocales` يمنع مجلدًا شاردًا من أن يصبح لغة.

## ماذا يحدث داخليًا؟

1. الوسيط يعمل قبل الحارس والأنبوب والمتحكم.
2. المحلّلات تُرجع مرشحين بالترتيب المسجّل.
3. `Accept-Language` يُرتَّب حسب `q` ويتخطى لغة غير مدعومة.
4. `t` يبحث في كتالوج اللغة ثم الاحتياط.
5. الاستجابة تعلن `Content-Language` حتى لا تخزن ذاكرة وسيطة نسخة واحدة لكل القراء. أضيفوا الترويسات التي تقرأونها إلى منطق `Vary` الذي تضعه الحزمة.

## مثال عملي

عضو دار النيل حفظ `locale: 'en'` في صف العضوية. محلّل يطبق `LocaleResolver` من الحزمة يقرأ `request.user` بعد الحارس ويعيد `en` قبل `AcceptLanguageLocaleResolver`. صفحة i18n تضع هذا النمط في «Use the customer's saved language»: لغة الحساب تتقدم على لغة المتصفح. رسالة «المشروع غير موجود» المترجمة لا تغيّر رمز 404 ولا شكل الخطأ من فصل التصميم. مفتاح التحقق `i18nValidationMessage` يبقى لرسائل `class-validator` حين تفعّلونها، لا بديلًا عن رمز الخطأ الثابت `code`.

## أخطاء شائعة

- نسيان `assets` فتُفقد JSON في `dist`.
- ترجمة نص الاستثناء وتغيير `statusCode` معه.
- لغة من جسم `POST` يرسلها العميل بلا مطابقة لقائمة مدعومة.
- جعل كل المزودات `Scope.REQUEST` لأجل اللغة. الحزمة تبقيهم singleton عبر `AsyncLocalStorage`.

## متى نستخدمه؟

حين تخدم رف قراءًا بلغات متعددة في نفس المسارات: تأكيد، تحقق، وحقول واجهة.

## متى لا نستخدمه؟

لا تستبدلوا به عزل المنظمة. لغة العرض ليست `tenantId`. ولا تترجموا حدث Stripe أو توقيع الويب هوك.

## مقارنة

| المصدر | متى يفوز في المثال |
| --- | --- |
| لغة العضوية المحفوظة | بعد المصادقة، عبر محلّل مخصص |
| `?lang` و `x-lang` | قبل `Accept-Language` إن سُجّلا أولًا |
| `defaultLocale` | مهمة بلا طلب |

## تمارين

### تمرين سهل

أين تُحفظ اللغة أثناء الطلب؟

<details>
<summary>الحل</summary>

في `AsyncLocalStorage` بعد وسيط `I18nModule`. الخدمة تنادي `t` بلا كائن الطلب.

</details>

### تمرين متوسط

لماذا `supportedLocales` مع أن المجلدات موجودة؟

<details>
<summary>الحل</summary>

حتى لا يصبح مجلد زائد لغة. التثبيت في الخيارات قرار تطبيق لا اكتشاف صامت.

</details>

### تمرين متقدم

`Content-Language` غائب عن الاستجابة وذاكرة CDN تعرض العربية لطلب إنجليزي. ماذا تفحصون؟

<details>
<summary>الحل</summary>

`responseHeaders` لم يُطفأ بلا سبب، و `Vary` يشمل `Accept-Language` أو `x-lang`. بلا `Vary` قد تُخزَّن نسخة اللغة الأولى لكل القراء.

</details>

## أسئلة مراجعة

- ما اسم الحزمة والوحدة؟
- ما ترتيب المحلّلات في المثال؟
- كيف يفشل المفتاح الخاطئ مبكرًا؟
- ماذا تُرجع مهمة بلا طلب؟

## الخلاصة

`@nestjs/i18n` يحل لغة رف مرة لكل طلب ويبقي الخدمات singleton. الكتالوج JSON يُنسخ مع البناء. اللغة المحفوظة للحساب تتقدم على ترويسة المتصفح حين تكتبون محلّلًا بذلك.

## ماذا بعد؟

بعد النشر قد يخرج بريد تأكيد. الدرس التالي `@nestjs/mail`، واللغة فيه ملف قالب لا مفتاحًا واحدًا فقط.
