Auth

الهدف من هذا الدرس

فتح حساب في رف بكلمة مرور، وإصدار إثبات للطلبات التالية، على @nestjs/authentication من غير خلط وصفة Passport في نفس المسار.

المشكلة التي يحلها

كلمة المرور تُحفظ كما كُتبت. أو المسار يعيد المستخدم ومعه التجزئة. أو يُركَّب AuthGuard('local') بجانب الحزمة الرسمية فيتنازع الحارسان. التسجيل ينشئ منظمة كاملة في هذا الدرس فيصعب اختبار الهوية وحدها.

الفكرة ببساطة

POST /auth/register ينشئ User بتجزئة. POST /auth/login يتحقق ويصدر جلسة أو زوج رموز عبر TokenService كما في فصل المصادقة. اختاروا قناة واحدة للجولة الأولى: جلسة للمتصفح أو refresh للجوال، لا الاثنين في نفس الأسبوع إن ضاق الوقت. Passport يبقى وصفة إن بنيتم المشروع عليها وحدها.

التعريف التقني

الحزمة تتولى التجزئة والجلسة أو الرموز عندما تسجّلون المخزن. لا SHA عارٍ لكلمة المرور. @Public() على التسجيل والدخول. الحارس العام يغلق الباقي. validate يحمّل المستخدم بلا passwordHash. الرد لا يحتوي التجزئة. لا Google في هذه الشريحة؛ OIDC درس سابق يمكن إضافته بعد ما يعمل البريد. المنظمة في الدرس التالي حتى لا يفشل التسجيل إن فشل إنشاء المكتبة.

Mental Model

register → User + hash
login    → إثبات بلا hash
الطلبات  → حارس يضع user.id

أبسط مثال

@Public()
@Post('register')
@HttpCode(201)
register(@Body() body: { email: string; password: string }) {
  return this.auth.register(body.email, body.password);
}

أضيفوا الاستيراد من @nestjs/common و Public من @nestjs/authentication. 201 لأن الحساب خُلق.

شرح المثال

  • جسم الدخول ليس 201. الدخول 200 مع الإثبات.
  • كلمة المرور لا تُسجَّل.
  • الخدمة ترفض البريد المكرر بـ 409 لا بـ 500.

ماذا يحدث داخليًا؟

  1. الأنبوب يتحقق من شكل البريد وطول كلمة المرور.
  2. المستودع يحفظ التجزئة ولا يعيدها.
  3. الدخول يقارن عبر أدوات الحزمة.
  4. الإثبات يُسلَّم. الطلب التالي يملأ user.
  5. لا organizationId بعد. الطلبات المحمية التي تحتاج مكتبة تنتظر الدرس التالي.

مثال عملي

async register(email: string, password: string) {
  const existing = await this.users.findByEmail(email);
  if (existing) throw new ConflictException('email taken');
  const user = await this.users.create(email, password);
  return { id: user.id, email: user.email };
}

create يستدعي التجزئة داخل المستودع. الاختبار يتوقع غياب passwordHash في الكائن المرجع. لا تنشئوا Project هنا.

أخطاء شائعة

  • 200 على التسجيل مع إعادة كلمة المرور.
  • حارسان: Passport و @nestjs/authentication.
  • جعل التسجيل ينشر كتابًا تجريبيًا.
  • تخزين JWT في جدول بلا تجزئة لرمز التحديث إن اخترتم الرموز. الحزمة تخزّن التحديث مجزأ عندما تستخدمون مخزنها.

متى نستخدمه؟

بعد الأساسات وقبل أي مسار مكتبة. بلا إثبات لا عضوية.

متى لا نستخدمه؟

لا تضيفوا العامل الثنائي في هذه الشريحة. ولا تربطوا Stripe بالتسجيل.

تمرين سهل

ماذا يغيب عن JSON التسجيل؟

الحل

password و passwordHash. يظهر id و email فقط.

تمرين متوسط

لماذا لا تُنشأ المنظمة داخل register في رف هذه الدورة؟

الحل

حتى يُختبر الحساب وحده، ويستطيع الشخص لاحقًا امتلاك أكثر من مكتبة. الدرس التالي معاملة منظمة + مالك.

تمرين متقدم

اخترتم الرموز لا الجلسة. ماذا لا تضعون في claims؟

الحل

الدور والـ organizationId الدائم إن كان الشخص سينتقل بين المكتبات. الدور يُحمَّل من العضوية بعد اختيار المستأجر. الرمز القصير إثبات شخص.

أسئلة مراجعة

  • أي حزمة للشريحة؟
  • لماذا Passport ليست طبقة ثانية؟
  • ما رمز البريد المكرر؟
  • ماذا لا يُنشأ في التسجيل؟

الخلاصة

التسجيل 201 بحساب مجزّأ بلا سر في الرد. الدخول يصدر إثباتًا واحد القناة. المنظمة ليست داخل هذا المسار.

ماذا بعد؟

الحساب يحتاج مكتبة يملكها. الدرس التالي المستخدم والمنظمة.
