# RBAC

## الهدف من هذا الدرس

ربط الأدوار بأفعال مسموحة: Role-Based Access Control، كجدول يمكن قراءته قبل كتابة سياسة.

## المشكلة التي يحلها

`if (isEditor)` داخل النشر وداخل الحذف وداخل إخفاء التعليق يتكرر ويتناقض. محرر جديد لا يعرف ماذا يستطيع. إضافة دور `moderator` يلمس كل شرط.

## الفكرة ببساطة

RBAC يقول: الدور يملك مجموعة أفعال. الفعل اسم مثل `post:publish`. المستخدم يستطيع الفعل إن كان أحد أدواره يملكه. الفحص دالة واحدة `can(user, action)`. الملكية الخاصة بصف مقال ليست في هذا الجدول. RBAC هنا أفعال عامة على نوع المورد.

## التعريف التقني

جدول الدورة:

| الدور | أفعال |
| --- | --- |
| `reader` | `post:read` |
| `editor` | `post:read`، `post:publish`، `comment:remove` |

```ts
const grants: Record<Role, readonly string[]> = {
  reader: ["post:read"],
  editor: ["post:read", "post:publish", "comment:remove"],
};

export function roleCan(user: { roles: Role[] } | null, action: string): boolean {
  if (!user) return false;
  return user.roles.some((role) => grants[role].includes(action));
}
```

الضيف `false`. لا استثناء `401` داخل الدالة. من يستدعيها يقرر الرمز: إن لم يوجد مستخدم أصلًا فالحارس أعاد `401` قبل النداء على مسار مغلق.

هذا ليس `@nestjs/authorization` بعد. هو النموذج الذهني الذي ستترجمه سياسات الحزمة إلى دوال ترجع `true` حرفيًا. الحزمة لا تستخدم سلاسل `post:publish` كأسماء جاهزة. أنت تسمي دوال السياسة. أبقِ أسماء الجدول قريبة من أسماء الدوال حتى لا تظهر لغتان.

Nest لا يفرض RBAC مدمجًا بهذا الشكل. الصفحة الحالية تبني السياسات مباشرة. الدرس يبرر لماذا السياسة أوضح من شروط مبعثرة، ثم الدرس التالي يفرّق الصلاحية عن الادعاء داخل الرمز.

## Mental Model

```text
editor -> post:publish, post:read, comment:remove
reader -> post:read
roleCan(user, "post:publish")
```

## أبسط مثال

```ts
export function assertRole(user: { roles: Role[] }, action: string) {
  if (!roleCan(user, action)) {
    throw new ForbiddenException();
  }
}
```

## شرح المثال

`ForbiddenException` هنا `403` لأن الدالة استقبلت مستخدمًا موجودًا. لو استقبلت `null` لكان الخلط مع `401` سهلًا. على مسار مغلق بالحارس، المستخدم موجود والرفض تفويض.

`assertRole` ما زال لا يرى المقال. نشر مسودة الغير قد يكون ممنوعًا حتى على `editor` في منتجكم. لا تضف `post.authorId` إلى هذه الدالة. ذلك يخرجها من RBAC العام إلى سياسة السجل.

## ماذا يحدث داخليًا؟

الفحص في الذاكرة على مصفوفة صغيرة. لا استعلام لكل فعل إن كانت الأدوار محمّلة مع `PublicUser`. إن كبر الجدول إلى مئات الصلاحيات من قاعدة، حمّله مع المستخدم مرة في `validate` لا في كل `if`.

تغيير `grants` إصدار سلوك. ضعه حيث يراجعه الفريق، لا منسوخًا في المتحكم.

## مثال عملي

`POST /posts/:id/publish` يستدعي `assertRole(user, "post:publish")` ثم يحدّث `published`. قارئ معروف يأخذ `403`. محرر يأخذ تحديثًا. ضيف لا يصل إلى الدالة لأن المصادقة أعادت `401`. حذف تعليق يستخدم `comment:remove` من الجدول نفسه، لا شرط `isEditor` جديد في `CommentsService`.

## أخطاء شائعة

- نسخ قائمة الأفعال داخل كل خدمة.
- `401` عند نقص الدور.
- وضع ملكية الصف داخل `roleCan` حتى تصبح الدالة تعرف Prisma.
- دور بلا اسم في النوع، يُكتب `"Editor"` بحرف كبير في مكان واحد.

## متى نستخدمه؟

حين تُمنح القدرات لفئات لا لصفوف بعينها، والقائمة قصيرة وثابتة.

## متى لا نستخدمه؟

كحل أخير لكل قاعدة. «صاحب التعليق يحذف تعليقه» ليست دورًا. ستحتاج سجلًا في السياسة حتى لو بقي RBAC للأفعال العامة.

## مقارنة

| شروط `isEditor` | جدول `grants` |
| --- | --- |
| الفعل مخفي في الكود | الفعل اسم في الجدول |
| دور جديد يلمس الملفات | دور جديد يلمس الجدول |
| سهل التناقض | مصدر واحد |

## تمارين

### تمرين سهل

هل `reader` يستطيع `post:publish` في جدول هذا الدرس؟

<details>
<summary>الحل</summary>

لا. الجدول يعطيه `post:read` فقط.

</details>

### تمرين متوسط

لماذا `assertRole` ترمي `403` لا `401`؟

<details>
<summary>الحل</summary>

لأنها تُستدعى بعد وجود مستخدم. نقص الفعل تفويض. غياب الهوية قرار الحارس قبلها.

</details>

### تمرين متقدم

منتج يريد أن يحذف المحرر أي تعليق، والقارئ يحذف تعليقه فقط. أي جزء يبقى في RBAC، وأي جزء يخرج منه؟

<details>
<summary>الحل</summary>

`comment:remove` للمحرر يبقى فعل دور. حذف القارئ لتعليقه يحتاج مقارنة `comment.authorId` بالشخص، وهذا شرط سجل لا سطر في `grants`.

</details>

## أسئلة مراجعة

- ماذا يربط RBAC؟
- أين لا تكفي قائمة الأفعال؟
- أي رمز لنقص الدور بعد المصادقة؟

## الخلاصة

RBAC جدول أدوار إلى أفعال عامة ودالة فحص واحدة. ملكية الصف تبقى خارج الجدول. السياسة لاحقًا تجمع الاثنين في دوال صريحة.
