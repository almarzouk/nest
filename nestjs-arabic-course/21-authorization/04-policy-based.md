# Policy-based Authorization

## الهدف من هذا الدرس

جمع قواعد السماح في دوال سياسة: كل دالة تجيب عن فعل واحد، وقد ترى المستخدم والصف معًا.

## المشكلة التي يحلها

RBAC يقول إن المحرر ينشر، لكن مسودة Ada ليست للمحرر إن كان المنتج «صاحب المسودة فقط، والمحرر يرى المنشور». الشرط يتوزع بين الحارس والخدمة فيختلف `GET` عن `PATCH`. سياسة واحدة تُستدعى من الاثنين.

## الفكرة ببساطة

السياسة كائن دوال. الاسم فعل: `publish`، `update`، `read`. المدخلات المستخدم وربما المقال. المخرج الذي يسمح هو قرار موجب واضح. الفحص الذي لا يحتاج صفًا يمكن أن يعيش على المسار. الفحص الذي يحتاج المقال يحدث بعد تحميل الصف في الخدمة، حتى لا يُجلب السجل مرتين بطريقة مختلفة.

## التعريف التقني

هذا الدرس ما زال بلا مزخرفات الحزمة. الشكل الذي ستطابقه الصفحة:

```ts
export class PostPolicy {
  publish(user: PublicUser | null, post: { authorId: number; published: boolean }) {
    if (!user) return false;
    return user.roles.includes("editor") || user.id === post.authorId;
  }

  read(_user: PublicUser | null, post: { published: boolean }) {
    return post.published;
  }
}
```

في منتج المكتبة قد يكون النشر للمحرر فقط. المثال يجمع الاحتمالين حتى ترى أن السياسة مكان الشرط المركب. ثبّت قاعدة واحدة في الكود الحقيقي ولا تترك الاحتمالين معًا.

الضيف يقرأ المنشور فقط إن كانت الدالة تسمح. المسودة ترجع `false` للضيف. الحارس العام للمصادقة قد يمنع الوصول قبل السياسة. إن كان الكتالوج `@Public()` أو اختياريًا، السياسة ترى `null`.

الفشل بعد معرفة المستخدم `403`. الفشل لأن المقال غير موجود `404` قبل السياسة أو بعدها حسب ما تعد به: كثير من واجهات ترجع `404` للمسودة حتى لا تكشف وجودها. ذلك قرار منتج داخل الخدمة حول نتيجة السياسة، لا داخل جدول الأدوار.

الحزمة لاحقًا تشترط أن `true` الحرفي فقط يسمح، وأي قيمة أخرى تمنع. اكتب الدوال لذلك من الآن: لا ترجع كائن المقال كأنه «حقيقة».

## Mental Model

```text
PostPolicy.publish(user, post) -> true أو false
        |
 مسار بلا صف: فعل عام مثل create
 خدمة بعد التحميل: فعل على هذا المقال
```

## أبسط مثال

```ts
@Injectable()
export class PostPolicy {
  update(user: PublicUser | null, post: { authorId: number }) {
    return !!user && user.id === post.authorId;
  }
}
```

## شرح المثال

التعديل لصاحب المعرّف فقط، ولو كان محررًا. هذا متعمَّد في المثال ليختلف عن RBAC الذي يعطي المحرر كل شيء. إن أراد المنتج أن يعدّل المحرر أي مقال، الشرط يتغير هنا لا في عشرة متحكمات.

`@Injectable()` يجهّز الحقن حين تنتقل السياسة إلى وحدة Nest في الدرس التالي. اليوم يمكن اختبار `new PostPolicy().update(ada, post)` من غير HTTP.

## ماذا يحدث داخليًا؟

الخدمة تحمّل المقال بـ `findOne`. إن غاب، `404`. إن وُجد، تنادي السياسة. عند `false` ترمي `ForbiddenException` إن كان المستخدم معروفًا والمقال ظاهرًا له، أو `NotFoundException` إن كنت تخفي المسودات. ثم تنفّذ `update`. لا تكتب ثم تفحص.

اختبار السياسة جدول: صاحب، غير صاحب، `null`، محرر إن أضفت فرعه. من غير قاعدة ومن غير رمز.

## مثال عملي

Ada صاحبة المقال `3` تعدّل العنوان فتنجح. Basil القارئ على المقال نفسه يأخذ رفضًا. ضيف على `GET` لمقال `published: false` لا يرى الجسم. محرر ينشر عبر `publish` إن أضفت شرط الدور هناك فقط. `CommentsService` لا تنسخ شرط صاحب المقال. إن احتاجت الحذف، فسياسة تعليق أو دالة على `PostPolicy` تُستدعى بالاسم.

## أخطاء شائعة

- السياسة تكتب في Prisma. هي قرار، والخدمة تكتب.
- شرط في الحارس وشرط مختلف في الخدمة للفعل نفسه.
- إرجاع المقال من الدالة بدل منطقي.
- `404` و `403` بلا قرار موحّد للمسودة.

## متى نستخدمه؟

حين يجتمع دور وملكية وحالة صف في قاعدة واحدة تُعاد من أكثر من مسار.

## متى لا نستخدمه؟

لفعل لا قاعدة له بعد، مثل قراءة عامة بلا تمييز. حارس المصادقة يكفي حتى تظهر قاعدة حقيقية.

## مقارنة

| RBAC | سياسة |
| --- | --- |
| فعل عام للدور | فعل قد يرى الصف |
| جدول ثابت | دالة |
| لا يعرف `authorId` | مكان `authorId` |

## تمارين

### تمرين سهل

أين يُفحص تعديل المقال، قبل التحميل أم بعده؟

<details>
<summary>الحل</summary>

بعد تحميل الصف، لأن القرار يحتاج `authorId`. الغياب `404` قبل النداء أو إن لم يوجد صف.

</details>

### تمرين متوسط

لماذا لا تُحدَّث القاعدة في `PostPolicy.update`؟

<details>
<summary>الحل</summary>

السياسة تجيب بنعم أو لا. الكتابة في `PostsService` بعد القرار، حتى تُختبر السياسة بلا Prisma.

</details>

### تمرين متقدم

مسودة لغير صاحبها. متى تختار `404` بدل `403`؟

<details>
<summary>الحل</summary>

حين لا تريد أن يؤكد الوجود لشخص لا يحق له الرؤية. صاحب المسودة يمكن أن يأخذ `403` على فعل لا يملكه أو أن ينجح في `update`. القرار يُكتب بجانب النداء في الخدمة ويُختبر.

</details>

## أسئلة مراجعة

- ماذا ترجع دالة السياسة؟
- أي القواعد لا يعبّر عنها الدور وحده؟
- من ينفّذ الكتابة؟

## الخلاصة

السياسة دالة لكل فعل، ترى المستخدم وربما الصف، وتُستدعى من الخدمة حين يلزم السجل. الدور يبقى أحد المدخلات لا المكان الوحيد للشرط.
