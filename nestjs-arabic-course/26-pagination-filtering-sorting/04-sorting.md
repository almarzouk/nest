# Sorting

## الهدف من هذا الدرس

قبول الترتيب من قائمة مفاتيح ثابتة، مع فاصل تعادل يجعل الصفحات والمؤشر مستقرة.

## المشكلة التي يحلها

`orderBy` المبني من نص `sort` الحر يصل إلى عمود بلا فهرس أو إلى حقل لا يخص العقد. فصل المقالات سمح بـ `id` و `title`. التعميم ينسخ القائمة في كل خدمة وينسى فاصل `id`، فيتكرر صف عند تساوي العناوين بين صفحة وأخرى. مؤشر الترقيم يحتاج نفس المفاتيح.

## الفكرة ببساطة

DTO تقبل `sort` و `order` عبر `@IsIn`. الخدمة لا تمرّر النص إلى SQL. تختار كائن `orderBy` من خريطة كتبتها. كل ترتيب ينتهي بـ `id` حتى يكون الترتيب كليًا. القيم الخارجة عن القائمة `400`.

## التعريف التقني

```ts
@IsOptional()
@IsIn(["id", "title"])
sort: "id" | "title" = "id";

@IsOptional()
@IsIn(["asc", "desc"])
order: "asc" | "desc" = "asc";
```

الخريطة:

```ts
const orders = {
  id: (order: "asc" | "desc") => [{ id: order }],
  title: (order: "asc" | "desc") => [{ title: order }, { id: "asc" }],
} as const;

export function orderByPosts(sort: keyof typeof orders, order: "asc" | "desc") {
  return orders[sort](order);
}
```

Prisma يقبل مصفوفة `orderBy`. العنوان أولًا ثم `id` تصاعديًا يكسر التعادل. حين يكون الفرز `id` وحده فالمفتاح فريد.

اتجاه الفاصل ثابت `asc` حتى لا ينقلب مع `order` فيربك المؤشر. إن تبع الفاصل اتجاه العميل، فالمؤشر يخزّن الاتجاه أيضًا.

التعليقات في خيط زمني تفرز `id` فقط. لا تعلن `title` على DTO التعليق. ملف مشترك يصدّر مفاتيح المقالات:

```ts
export const POST_SORTS = ["id", "title"] as const;
```

`@IsIn(POST_SORTS)` يبقى مع الخريطة. مفتاح في المصفوفة وغائب عن الكائن لا يُترجم لأن النوع يفرض فرعًا.

لا `ORDER BY ${sort}` في `$queryRawUnsafe`. في SQL الخام الأعمدة من الخريطة والنص الذي يُرسل ثابت.

المؤشر لفرز `title` ثم `id` يحمل القيمتين. فرز `id` فقط يحمل المعرّف. تغيير `sort` مع `cursor` قديم يبدأ من الأول أو يُرفض.

## Mental Model

```text
@IsIn يضيق النص
الخريطة تبني orderBy
آخر مفتاح فريد
المؤشر يخزن مفاتيح الخريطة
```

## أبسط مثال

```ts
orderBy: orderByPosts(query.sort, query.order),
```

## شرح المثال

سطر واحد في `findMany`. `count` لا يحتاج ترتيبًا. اختبار وحدة بلا قاعدة يتوقع عنصرين عند `title`. الافتراضي `id` تصاعديًا يبقي سلوك قائمة الفصل 19 مستقرًا بعد استخراج الخريطة.

حذف مفتاح يتم من `POST_SORTS` ومن `orders` معًا. OpenAPI يعرض التعداد نفسه بـ `enumName` حتى لا يولّد العميل قيمًا زائدة.

## ماذا يحدث داخليًا؟

Prisma يكتب `ORDER BY "title" ASC, "id" ASC`. من غير العمود الثاني، صفان بعنوان واحد بلا ترتيب مضمون، فينتقل صف عبر `OFFSET` إلى صفحة مجاورة بين طلبين. مع `id` الترتيب كلي على المفتاح الأساسي.

الفهرس المفيد يغطي أعمدة الترتيب بعد أعمدة المساواة في `WHERE`. فرز بلا فهرس على جدول كبير يرتب في الذاكرة حتى لو كانت القائمة آمنة من الحقن.

اتجاه `desc` على `id` يعيد الأحدث أولًا. التعليقات التصاعدية أبسط لمؤشر «بعد هذا المعرّف».

## مثال عملي

اختبار DTO يرفض `sort=passwordHash` و `order=DROP`. اختبار الخريطة يتوقع مفتاحين عند `title`. اختبار صفحات: ثلاثة مقالات بعنوان واحد ومعرّفات متتالية، `pageSize=2`، والصفحة الثانية تبدأ حيث انتهت الأولى بلا تكرار. الواجهة تبدّل الفرز ضمن `POST_SORTS` فقط.

## أخطاء شائعة

- تمرير `query.sort` كنص حر إلى قالب SQL.
- تعادل بلا `id`.
- قائمة `@IsIn` أوسع من الخريطة.
- مؤشر يختزن معرّفًا والفرز على العنوان.
- اتجاه فاصل يتغير بين طلبين لنفس المؤشر.

## متى نستخدمه؟

حين تعرض الواجهة مبدّل ترتيب، وعلى أي مؤشر يعتمد على موضع مرتب.

## متى لا نستخدمه؟

لفرز من أي عمود يختاره العميل على `GET` عام. تقرير داخلي يكتب خريطته بعد مراجعة الفهارس، بعقد منفصل.

## مقارنة

| خريطة ثابتة | نص إلى `ORDER BY` |
| --- | --- |
| `@IsIn` ثم كائن | القيمة قد تصبح SQL |
| فاصل `id` ظاهر | التعادل غير مضمون |
| يطابق فهرسًا تعرفه | قد يرتب عمودًا بلا فهرس |

## تمارين

### تمرين سهل

أي مزخرف يحصر `sort` في `id` و `title`؟

<details>
<summary>الحل</summary>

`@IsIn(["id", "title"])` أو `@IsIn(POST_SORTS)`.

</details>

### تمرين متوسط

لماذا تُضاف `id` بعد `title`؟

<details>
<summary>الحل</summary>

العناوين تتساوى. `id` فريد فيصبح ترتيب الصفحتين ثابتًا بلا تكرار.

</details>

### تمرين متقدم

كيف تمنع مفتاحًا في `@IsIn` من غير فرع في الخريطة؟

<details>
<summary>الحل</summary>

كائن `orders` يغطي الاتحاد، والدالة تأخذ `keyof typeof orders`. المفتاح الجديد لا يُترجم حتى يُكتب الفرع.

</details>

- ماذا يحمل مؤشر فرز العنوان؟
- هل `count` يحتاج `orderBy`؟

## الخلاصة

الفرز قائمة مفاتيح وخريطة إلى `orderBy` تنتهي بمفتاح فريد. النص لا يدخل SQL. المؤشر يحفظ المفاتيح نفسها.
