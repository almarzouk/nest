# Filtering

## الهدف من هذا الدرس

بناء `where` من حقول استعلام مسموحة فقط، مع نطاق يفرضه الخادم ولا يفتحه العميل.

## المشكلة التي يحلها

فصل المقالات قبل `published` كنص. تعميم ذلك بقبول `filter` كـ JSON يتحول إلى `where` يتيح طلب `passwordHash` أو عمودًا بلا فهرس أو شرطًا ينفي الملكية. `"false"` مع تحويل منطقي ساذج يصبح `true` لأن النص غير الفارغ حقيقة في JavaScript. ذلك الفخ ظهر في الفصل 19 ويبقى قائمًا في أي DTO مشترك.

## الفكرة ببساطة

كل مرشح حقل على DTO بمزخرفات، لا كائن حر. الخدمة تنسخ الحقل إلى `where` إن وُجد. ما لا تعرفه DTO يرفضه `forbidNonWhitelisted`. نطاق الرؤية، مثل «المنشور أو ما أملكه»، يُضاف في الخدمة من `@CurrentUser()` ولا يُقرأ من الاستعلام كعمود خام.

## التعريف التقني

مرشحات المقالات التي يعرفها العقد:

```ts
published?: boolean;
authorId?: number;
```

تحليل المنطقي كما ثُبّت للقائمة الأولى: `"true"` و `"false"` فقط، وأي قيمة سواهما `400`. لا `enableImplicitConversion` على هذا الحقل.

```ts
function andWhere<T extends Record<string, unknown>>(
  base: T,
  extra: Record<string, unknown>,
) {
  return { ...base, ...extra };
}
```

`base` نطاق الخادم. `extra` ما سمح به الاستعلام بعد التحقق. للزائر:

```ts
const base = { published: true };
```

للمستخدم الداخل الذي يطلب مسوداته، الخدمة تستطيع توسيع النطاق إلى مقالات يملكها حتى لو `published` كاذبة، بشرط `authorId` من الجلسة لا من طلب يستطيع تزويره لشخص آخر. إن سمح المنتج بـ `authorId` في الاستعلام للوحة المحررين فقط، فالسياسة تسبق الدمج. مرشح الاستعلام لا يلغي `@Can`.

التعليقات مرشحها الثابت `postId` من المسار، كما في مورد التعليقات. لا حقل `postId` في الاستعلام يغيّر المسار.

القائمة الفارغة بعد مرشح ضيق `200` و `total: 0`. المرشح والعد يستخدمان الكائن نفسه.

Prisma `findMany({ where })` يربط القيم كمعاملات. لا تبنِ المرشح بلصق SQL. درس الحقن ما زال ساريًا إن كتب أحدهم بحثًا خامًا.

بحث `q` على العنوان، إن أضفته، يذهب إلى `contains` مع حد طول في DTO، لا إلى `OR` يفتح كل الأعمدة.

## Mental Model

```text
استعلام مسموح -> extra
جلسة وسياسة -> base
where = base ثم extra
JSON حر لا يدخل Prisma
```

## أبسط مثال

```ts
const where = {
  ...visibility(user),
  ...(query.authorId !== undefined ? { authorId: query.authorId } : {}),
};
```

## شرح المثال

`visibility` دالة واحدة تختبرها بلا HTTP. للزائر تعيد `{ published: true }`. إن مرّر الزائر `published=false` تقرر المنتج: إما `400` لأنه خارج النطاق، أو تجاهل القيمة لأن `base` يفرض `true`. الأصرح رفض التناقض بـ `400` حتى لا يظن العميل أنه رأى المسودات. المحرر الذي يطلب مسوداته لا يرسل `published=false` لتجاوز ملكية غيره. `authorId` في `extra` يُقبل بعد أن تتحقق السياسة أنه يطلب نفسه أو أنه يملك صلاحية اللوحة.

## ماذا يحدث داخليًا؟

الأنبوب يحوّل الاستعلام إلى DTO. الخدمة تبني كائنًا عاديًا. Prisma يولّد `AND` بين الحقول. فهرس يطابق الحقول الشائعة يجعل الخطة رخيصة، وذلك درس الأثر. شرط غير مفهرس على جدول كبير يمسح الصفوف حتى لو كان العقد صحيحًا.

حقل زائد في الاستعلام يسقط أو يُرفض قبل هذه الدالة. لذلك لا يصل `passwordHash` إلى `where`.

## مثال عملي

اختبار زائر مع `published=false` يتوقع `400` أو قائمة منشورات فقط، حسب القرار الذي تكتبه مرة في `visibility`. اختبار محرر يرى مسودته ولا يرى مسودة غيره حتى مع `authorId` لغيره. اختبار `"false"` يتوقع `false` لا `true`. `count` و `findMany` في الاختبار يستقبلان الكائن نفسه. مورد التعليقات يتجاهل أي `published` لأن الحقل غير موجود على DTO التعليق فيرفضه الأنبوب.

## أخطاء شائعة

- `JSON.parse` للاستعلام داخل `where`.
- `Boolean("false")` أو تحويل ضمني.
- مرشح عميل يستبدل شرط الملكية.
- `postId` من الاستعلام يختلف عن المسار.
- عدّ بلا المرشح.

## متى نستخدمه؟

لكل قائمة قابلة للتضييق بحقول تعرفها وتقدر فهرستها.

## متى لا نستخدمه؟

كواجهة عامة لكل أعمدة القاعدة. التقرير الحر أداة داخلية بعقد مختلف وصلاحية أضيق، لا `GET` عام. ولا تستبدل السياسة بمرشح.

## مقارنة

| حقول DTO | `where` من JSON |
| --- | --- |
| الأنبوب يرفض الزائد | العميل يختار الأعمدة |
| النطاق في الخدمة | النطاق قابل للاستبدال |
| `"false"` تُحلَّل صراحة | التحويل الضمني يخونها |

## تمارين

### تمرين سهل

أين يُفرض «الزائر يرى المنشور فقط»؟

<details>
<summary>الحل</summary>

في `where` الأساسي داخل الخدمة من نوع المستخدم، لا كثقة في `published` القادم من الاستعلام وحده.

</details>

### تمرين متوسط

ماذا يعيد نص الاستعلام `published=false` مع `Boolean(value)`؟

<details>
<summary>الحل</summary>

`true` لأن النص غير فارغ. الحل مقارنة صريحة بـ `"true"` و `"false"`.

</details>

### تمرين متقدم

محرر يمرّر `authorId` لمؤلف آخر. أين يُرفض؟

<details>
<summary>الحل</summary>

في السياسة أو في `visibility` قبل الدمج: إما `403` أو إجبار `authorId` من الجلسة. المرشح لا يوسّع الملكية.

</details>

## أسئلة مراجعة

- لماذا لا يُقبل كائن `where` خام؟
- ماذا يشارك `count` مع `findMany`؟
- من أين يأتي `postId` لتعليقات المقال؟

## الخلاصة

المرشح حقل مسموح يُدمَج فوق نطاق الخادم. التحويل المنطقي صريح. السياسة لا تُلغى بمعامل استعلام.
