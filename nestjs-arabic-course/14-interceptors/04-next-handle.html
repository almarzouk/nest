next.handle

الهدف من هذا الدرس

فهم CallHandler.handle: من أين يأتي التيار، ومتى تُستدعى الدالة.

المشكلة التي يحلها

إرجاع next.handle() يبدو كأنه استدعاء الدالة فورًا. هو ليس كذلك. الدالة تعمل حين يشترك الإطار في التيار الذي رجعتَه. من يستدعي handle() مرتين أو يشترك بنفسه يشغّل الحجز مرتين.

الفكرة ببساطة

handle() ترجع Observable يمثّل بقية السلسلة: معترضات أقرب إلى الدالة، ثم أنابيب، ثم المتحكم. لا تصدر قيمة حتى الاشتراك. Nest يشترك في التيار الخارج من أبعد معترض.

التعريف التقني

صفحة المعترضات تقول: handle تستدعي معالج المسار. إن لم تنادِها في intercept، الدالة لا تُنفَّذ. استدعاؤها يسمونه نقطة القطع في لغة النواحي: المكان الذي يُدرج فيه منطقك.

بعد أن ترجع التيار، الاشتراك هو الذي يشغّل reserve. القيمة التي تصدر هي ما رجعه المعالج، وتمر في عوامل pipe التي ركّبتها أنت على هذا التيار.

return next.handle();

هذا تمرير بلا تعديل.

return next.handle().pipe(map((data) => ({ data })));

هذا تمرير مع عامل. map لا تعمل قبل أن يصدر المعالج.

لا تستدعِ handle() قبل أن تكون جاهزًا لربط الناتج. النداء نفسه يبني التيار. العمل الثقيل داخل الدالة ينتظر الاشتراك، لكن بناء سلسلة مكسورة سهل إن حفظت تيارين.

في طلب HTTP المعتاد يصدر التيار قيمة واحدة ثم يكتمل، أو يخطئ. لا حلقة مقاعد داخل handle.

Mental Model

  قد تقرأ context
  next.handle() يبني وصف البقية ولا يشغّل reserve بعد
  ترجع الوصف إلى Nest
Nest subscribe
  الآن reserve تعمل
  القيمة تصعد في pipe

أبسط مثال

import { type CallHandler, Injectable, type NestInterceptor } from '@nestjs/common';
import { type Observable } from 'rxjs';
import { map } from 'rxjs/operators';

@Injectable()
export class SeatEnvelopeInterceptor implements NestInterceptor {
  intercept(_context: unknown, next: CallHandler): Observable<{ data: unknown }> {
    return next.handle().pipe(map((seat) => ({ data: seat })));
  }
}

_context غير مستخدم في هذا الدرس حتى يبقى التركيز على handle. المعالج الذي يرجع { id: 't1' } يجعل الجسم { data: { id: 't1' } } بعد الاشتراك.

شرح المثال

  • سطر return لا ينتظر الحفظ في المخزن. لا await next.handle().
  • pipe يصف ما بعد الإصدار.
  • استدعاء next.handle() مرتين يرجع تيارين. إن اشترك أحد في الاثنين، قد يُحفظ المقعد مرتين. استدعها مرة واحدة.
  • تجاهل القيمة المرجعة من handle() وإرجاع of({ data: null }) يلغي التنفيذ. ذلك استبدال، وهو مقصود فقط في درس التخزين.

ماذا يحدث داخليًا؟

كل معترض أقرب إلى الدالة موضوع داخل هذا التيار. الاشتراك في الخارج يستدعي handle في المعترض الأبعد، والذي يستدعي التالي، حتى الدالة. لذلك الكود قبل return next.handle() في المعترض الخارجي يعمل قبل الكود المماثل في معترض أقرب، بينما عوامل pipe على الخارجي ترى القيمة بعد عوامل الداخلي. رسم الترتيب درس الربط. هنا حقيقة واحدة: handle وصف، والاشتراك تشغيل.

إن رمت الدالة، التيار يخطئ. map لا تُستدعى. catchError على هذا pipe تُستدعى.

إن رمى الأنبوب قبل الدالة، فالسلسلة التي بناها handle تخطئ أيضًا. المعترض الذي لفّ الأنبوب يرى الخطأ على التيار، كما تقول صفحة الدورة عن catchError.

مثال عملي

POST /tickets يرجع { id: 't1', seat: 4 } من الخدمة. SeatEnvelopeInterceptor على المتحكم يجعل العميل يرى data. اختبار يستدعي المعترض بكائن CallHandler مزيف يرجع of({ id: 't1', seat: 4 }) ثم subscribe ويتوقع الغلاف. لا تشغّل HTTP لتثبيت map. وتأكد أن الاختبار يشترك مرة واحدة.

أخطاء شائعة

  • const value = await next.handle(). النوع تيار لا وعد بالقيمة.
  • next.handle().subscribe() داخل intercept مع return للتيار نفسه بطريقة تسبب اشتراكين. أرجع التيار ودع Nest يشترك.
  • الاعتقاد أن سطر handle() قد نفّذ SQL فورًا لأن السطر ظهر في المصحح قبل انتهاء الدالة. البناء غير الإصدار.
  • نداء handle داخل فرع وبعده نداء ثانٍ في فرع آخر على الطلب نفسه.

متى نستخدمه؟

في كل معترض يريد تشغيل المتحكم: مرة واحدة، مع pipe إن لزم، وإرجاع التيار.

متى لا نستخدمه؟

حين يكون الرد جاهزًا من غير الدالة، مثل قيمة مخزّنة ترجعها of(...). عندئذ لا تنادِ handle. ذلك استثناء موثّق في درس التخزين لا الأسلوب الافتراضي.

مقارنة

النداء الدالة reserve
لا handle وأرجعت of(cached) لا تُستدعى
return next.handle() تُستدعى عند subscribe
handle() مرتين مع اشتراكين خطر استدعاء مزدوج
await handle() لا ينتظر جسم الدالة

تمارين

تمرين سهل

هل next.handle() ترجع مقعدًا أم تيارًا؟

الحل

تيارًا. المقعد يصدر لاحقًا حين يشترك الإطار.

تمرين متوسط

أين تعمل map بالنسبة إلى جسم reserve؟

الحل

بعد أن يصدر المعالج قيمة على التيار، لا قبل استدعاء الدالة.

تمرين متقدم

اختبار وحدة اشترك في التيار ثم استدعاه الاختبار مرة ثانية على ناتج handle() نفسه المحفوظ. لماذا قد يُنشأ حجزان؟

الحل

كل اشتراك على تيار المعالج البارد يعيد التشغيل. في الطلب الحقيقي Nest يشترك مرة. في الاختبار اشترك مرة واحدة أو استخدم مصدرًا لا يعيد الأثر.

أسئلة مراجعة

  • من يشترك في تيار المعترض الحي؟
  • ماذا يحدث للدالة إن لم تُستدعَ handle؟
  • لماذا await next.handle() لا يعيد المقعد؟
  • متى لا تُستدعى map رغم وجودها في pipe؟

الخلاصة

handle() تبني تيار بقية السلسلة. التشغيل عند اشتراك Nest مرة واحدة. العوامل بعد الإصدار. الاستدعاء المزدوج والاشتراك اليدوي يعيدان أثر الدالة.

ماذا بعد؟

الدرس التالي يضع كودًا قبل handle وكودًا داخل pipe بعد الإصدار، ويفرق أثر الاثنين.
