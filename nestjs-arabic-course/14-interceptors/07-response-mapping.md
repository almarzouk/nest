# تحويل شكل الاستجابة

## الهدف من هذا الدرس

تغليف القيمة التي يرجعها المعالج بشكل JSON موحد، مثل `{ data }`، باستخدام `map`.

## المشكلة التي يحلها

كل دالة تذاكر تكتب `{ data: ticket }` يدويًا. دالة جديدة ترجع المصفوفة عارية فينكسر عميل الواجهة. الغلاف سياسة مسار لا قاعدة حجز.

## الفكرة ببساطة

الدالة ترجع `ticket` أو `ticket[]`. المعترض يعمل `map((data) => ({ data }))`. الخدمة لا تعرف الغلاف. الحقول السرية تُحذف قبل ذلك في عقد الخارج، لا داخل `map` كقائمة سوداء متأخرة.

## التعريف التقني

الصفحة تبني `TransformInterceptor<T>` الذي يطبّق `NestInterceptor<T, Response<T>>` ويرجع `next.handle().pipe(map((data) => ({ data })))`.

معالج يرجع `[]` يصبح الجسم:

```json
{ "data": [] }
```

`map` على طريق الخروج. لا تغيّر الدخول.

تحذير الصفحة: التغليف لا يعمل مع أسلوب الرد الخاص بالمكتبة حين تحقن `@Res()` وتكتب الرد بنفسك، إلا مع `passthrough: true`.

مثال آخر في الصفحة: استبدال `null` بسلسلة فارغة عبر `map`. السياسة العامة للقيم الفارغة معترض أيضًا، بشرط أن يكون العقد واضحًا. في التذاكر سنغلّف فقط، ونترك `null` كما هو حتى لا نخترع معنى.

الغلاف لا يغيّر رمز الحالة. `POST` يبقى `201` إن كان الرمز من Nest. يتغير الجسم فقط.

## Mental Model

```text
service → Ticket
controller return Ticket
map → { data: Ticket }
عميل الواجهة يقرأ body.data
```

عقد الحقول ما زال `Ticket` داخل `data`.

## أبسط مثال

```ts
import { type CallHandler, type ExecutionContext, Injectable, type NestInterceptor } from '@nestjs/common';
import { type Observable } from 'rxjs';
import { map } from 'rxjs/operators';

export interface TicketEnvelope<T> {
  data: T;
}

@Injectable()
export class TicketEnvelopeInterceptor<T> implements NestInterceptor<T, TicketEnvelope<T>> {
  intercept(_context: ExecutionContext, next: CallHandler): Observable<TicketEnvelope<T>> {
    return next.handle().pipe(map((data: T) => ({ data })));
  }
}
```

`GET /tickets` الذي يرجع `[{ id: 't1' }]` يخرج `{ "data": [{ "id": "t1" }] }`.

## شرح المثال

- المعامل النوعي `T` يوثّق ما يصدره المعالج وما يغلَّف.
- `_context` غير لازم للغلاف الأعمى. معترض لاحق قد يقرأ المسار ليتخطى الغلاف.
- لا `tap` هنا. التغيير هو الغرض.
- الدالة تبقى `return tickets` لا `return { data: tickets }`. الغلاف مرتين ينتج `data.data`.

## ماذا يحدث داخليًا؟

بعد نجاح الدالة يصدر التيار القيمة. `map` تبني كائنًا جديدًا. Nest يسلسله. إن كانت القيمة `undefined`، السلوك الافتراضي للإطار قد يختلف عن كائن، فلا تعتمد على غلاف لعملية بلا رد. أرجع كائنًا من الدالة إن كان الغلاف مطلوبًا.

خطأ قبل الإصدار لا يدخل `map`. العميل يرى جسم الفلتر لا `{ data }`. هذا مرغوب: خطأ `400` ليس نجاحًا مغلفًا إلا إذا صممت ذلك عمدًا في الفلتر.

`ClassSerializerInterceptor` لاحقًا يصفّي حقولًا. إن رُبط مع هذا الغلاف، ترتيب الخروج يحدد إن كان الإخفاء على التذكرة الداخلية أو على الغلاف. فضّل أن الدالة ترجع عقد الخارج النظيف ثم يغلّف المعترض.

## مثال عملي

واجهة الشباك تقرأ `response.data` لكل مسارات `TicketsController`. المعترض على الصنف. `HealthController` يرجع `{ ok: true }` بلا غلاف لأن الزينة ليست عليه. اختبار عقد يتوقع `data` مصفوفة على `GET /tickets` ويتوقع غياب `data` على `GET /health`. دالة `reserve` ترجع التذكرة لا الغلاف، والاختبار الوحدة للخدمة يبقى بلا `data`.

## أخطاء شائعة

- تغليف داخل الخدمة وتغليف في المعترض.
- `@Res()` يكتب JSON بنفسه ثم الدهشة أن `data` غائبة.
- `map` ترجع `data` فقط من غير قوسين لكائن: `map(data => { data })` كتلة لا ترجع شيئًا. الصيغة `({ data })`.
- إخفاء `password` داخل `map` بدل عقد الرد. الغلاف ليس قائمة حقول.

## متى نستخدمه؟

لسياسة شكل عام على مجموعة مسارات: غلاف `data`، أو استبدال `null` إن وثّقت ذلك للعميل.

## متى لا نستخدمه؟

لمسار الصحة أو لملف ثنائي أو حين تكتب الرد بيديك. ولا لأخطاء HTTP. تلك فلاتر. ولا لتغيير `seat` قبل الحفظ.

## مقارنة

| | الدالة تغلّف | المعترض يغلّف |
| --- | --- | --- |
| الخدمة | تعرف JSON العميل | ترجع عقد النطاق |
| مسار جديد | قد ينسى الغلاف | يرث زينة الصنف |
| الصحة | سهلة الانفصال | تبقى خارج الصنف |
| الخطأ | لا يغلَّف تلقائيًا | لا يغلَّف عبر `map` |

### تمرين متوسط

### تمرين متقدم

`reserve` ترجع `{ data: ticket }` والدالة عليها المعترض أيضًا. ماذا يرى العميل، وكيف توحّد؟

<details>
<summary>الحل</summary>

</details>

## أسئلة مراجعة

- أي عامل يبدّل شكل الرد؟
- هل يتغير رمز `201` بسبب `map`؟
- متى يتعطّل التغليف مع `@Res()`؟
- هل خطأ `400` يمر في `map`؟

## الخلاصة

`map` على تيار `handle` تغلّف ناجح الدالة. الخدمة ترجع العقد الداخلي للرد، والمعترض يضع السياسة العامة. الأخطاء تبقى للفلتر، والصحة تبقى خارج الربط إن كان شكلها مختلفًا.

## ماذا بعد؟

الدرس التالي يقطع التيار بمهلة ويرجّع `408` حين يتأخر المعالج.
