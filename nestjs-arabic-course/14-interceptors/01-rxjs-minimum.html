الحد الأدنى من RxJS قبل Interceptors

الهدف من هذا الدرس

فهم Observable و subscribe و pipe و map و tap و catchError بما يكفي لقراءة معترض Nest.

المشكلة التي يحلها

next.handle() في المعترض ترجع Observable لا القيمة نفسها. من يقرأ pipe(map(...)) كأنها مصفوفة أو كأنها Promise.then يضع أثرًا جانبيًا في مكان لا يعمل، أو يبتلع خطأ المقعد.

الفكرة ببساطة

Observable وصف لعمل لا يبدأ حتى يوجد مشترك. subscribe هو الاشتراك. pipe يركب عوامل على الوصف. map يبدّل القيمة. tap ينظر إليها من غير تبديل. catchError يلتقط خطأ التيار. في Nest أنت ترجع الوصف، والإطار هو من يشترك.

التعريف التقني

القيمة قد تصل لاحقًا، مرة واحدة في طلب HTTP المعتاد، أو تفشل. التيار كسول: بناء of(1) لا يطبع شيئًا حتى subscribe.

import { of } from 'rxjs';
import { map, tap } from 'rxjs/operators';

of(2)
  .pipe(
    tap((n) => console.log('seen', n)),
    map((n) => n + 1),
  )
  .subscribe((n) => console.log('got', n));

الإخراج seen 2 ثم got 3. tap لا تغيّر 2. map ترجع 3 إلى المشترك التالي.

catchError تستلم الخطأ وترجع تيارًا بديلًا. إن أرجعت throwError(() => err) فالخطأ يكمل. إن أرجعت of(value) فالتيار ينجح بقيمة.

import { throwError } from 'rxjs';
import { catchError } from 'rxjs/operators';

throwError(() => new Error('seat'))
  .pipe(catchError(() => of({ seat: 0 })))
  .subscribe((value) => console.log(value));

هذا يبتلع الخطأ ويعطي { seat: 0 }. في معترض حقيقي نادرًا تريد ابتلاع خطأ أعمال. الدرس يوضح الأداة فقط.

العوامل دوال ترجع دوال. pipe يمرر التيار من عامل إلى الذي يليه من اليسار إلى اليمين.

لا حاجة هنا إلى Subject ولا إلى إلغاء معقّد. طلب HTTP في المعترض غالبًا قيمة واحدة ثم اكتمال، أو خطأ.

Mental Model

وصف كسول  pipe(tap, map, catchError)  وصف جديد
                 subscribe عند Nest
                      ↓
                 قيمة أو خطأ إلى الرد

إرجاع الوصف من دالة لا ينفّذ المعالج. الاشتراك ينفّذه حين يكون الوصف هو next.handle().

أبسط مثال

import { of } from 'rxjs';
import { map, tap } from 'rxjs/operators';

export function previewTicket(seat: number) {
  return of({ seat }).pipe(
    tap((ticket) => console.log('before map', ticket.seat)),
    map((ticket) => ({ data: ticket })),
  );
}

استدعاء previewTicket(4) لا يطبع وحده. الطباعة والقيمة { data: { seat: 4 } } تظهران عند:

previewTicket(4).subscribe((body) => console.log(body));

شرح المثال

  • of تيار يصدر كائنًا ثم يكتمل. هو أبسط مصدر، لا علاقة له بـ HTTP بعد.
  • tap للنظر. وضع { data } داخل tap لا يغيّر ما يراه subscribe.
  • map تبني كائنًا جديدًا. هذا شكل تغليف الرد الذي سيعاد في درس لاحق داخل معترض.
  • subscribe في هذا الملف تعليمي. داخل intercept لا تناديها أنت على handle() إن كنت ترجع التيار إلى Nest. الإطار يشترك مرة.

ماذا يحدث داخليًا؟

عند subscribe يشغّل المصدر إصدار القيمة. كل عامل يرى ناتج السابق. tap تستدعي دالتك وتمرر القيمة كما هي. map تستبدلها. إن رمت map، العوامل التالية لا ترى قيمة، و catchError إن وُجدت بعد الرمي في الـ pipe ترى الخطأ.

ترتيب pipe(tap, map) يعني النظر ثم التبديل. pipe(map, tap) ينظر إلى القيمة الجديدة. هذا الترتيب من اليسار إلى اليمين داخل التيار الواحد.

خطأ بعد map لا يرجع إلى tap السابقة. catchError تُوضع حيث تريد الالتقاط، غالبًا في آخر السلسلة أو بعد عامل قد يفشل مثل المهلة.

لا تحوّل التيار إلى Promise في هذا الدرس. المعترض سيرجع Observable. الخلط مع async/await على handle() يضيع العوامل.

مثال عملي

تخيّل ناتج GET /tickets/4 هو { seat: 4 } من المتحكم. قبل كتابة معترض، جرّب في ملف صغير أن map تلفه إلى { data: { seat: 4 } } وأن tap تعدّ المرات من غير أن تغيّر الجسم. حين تقرأ return next.handle().pipe(...) في الدرس التالي، handle() هي مصدر مثل of لكنها لا تصدر حتى يشترك Nest، والإصدار هو استدعاء المتحكم.

أخطاء شائعة

  • نسيان أن البناء كسول ثم القول إن tap لا تعمل. الاشتراك ناقص في تجربتك، أو أنك لم ترجع التيار إلى من يشترك.
  • تغيير القيمة داخل tap بتعديل تتوقعه من map. tap للآثار.
  • catchError ترجع of(null) فتختفي أخطاء المقعد ويصير الرد 200.
  • استدعاء subscribe داخل المعترض على التيار نفسه الذي ترجعه. الاشتراك المزدوج قد يشغّل المعالج مرتين.

متى نستخدمه؟

قبل أي معترض، وحين تقرأ pipe في التوثيق. العوامل الأربعة تكفي لهذا الفصل: map و tap و catchError، مع معرفة أن subscribe يحدث في الإطار.

متى لا نستخدمه؟

لا تبنِ كل منطق الحجز داخل map. الخدمة ترجع قيمة عادية، والمعترض يغلّفها. لا تستبدل الحارس بـ catchError.

مقارنة

الأداة الأثر على القيمة الأثر الجانبي
map يبدّلها لا يُقصد به
tap يمررها نعم
catchError تيار بديل أو خطأ جديد حسب ما ترجع
subscribe يستهلك يبدأ العمل

تمارين

تمرين سهل

لماذا لا يطبع tap عند استدعاء دالة ترجع التيار من غير subscribe؟

الحل

التيار كسول. الوصف لا يعمل حتى الاشتراك. في Nest الاشتراك داخل الإطار حين ترجع التيار من intercept.

تمرين متوسط

أين تضع تغليف { data } وأين تضع عدادًا لا يغيّر الجسم؟

الحل

التغليف في map. العداد في tap. pipe(tap(...), map(...)) ينظر إلى الأصل ثم يغلّف.

تمرين متقدم

catchError(() => of({ ok: true })) بعد فشل حجز. ماذا يصبح رمز النجاح الظاهري، ولماذا هذا فخ؟

الحل

التيار ينجح بقيمة، فالإطار قد يكتب 200 وجسم { ok: true } رغم فشل الحجز. التقاط الخطأ يجب أن يعيد رمي HttpException مناسبًا أو يترك الخطأ يكمل، لا أن يخترع نجاحًا.

أسئلة مراجعة

  • متى يبدأ Observable العمل؟
  • ما الفرق بين map و tap؟
  • ماذا يجب أن ترجع catchError حتى لا يختفي الخطأ؟
  • من ينادي subscribe على تيار المعترض في Nest؟

الخلاصة

التيار وصف كسول. pipe يركب tap للنظر و map للتبديل و catchError للخطأ. الاشتراك يشغّل الوصف. المعترض التالي سيرجع هذا الوصف إلى Nest بدل أن يشترك بنفسه.

ماذا بعد؟

الدرس التالي يسمي المعترض: طبقة تلتف حول الدالة بعد الحارس وقبل الأنبوب في طريق الدخول، وترى الناتج في طريق الخروج.
