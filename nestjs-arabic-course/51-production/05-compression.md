# Compression

## الهدف من هذا الدرس

تقليل حجم استجابات JSON النصية بالضغط، مع معرفة أن الوكيل العكسي غالبًا المكان الأنسب، وأن الملفات المضغوطة أصلًا لا تُضغط مرة ثانية.

## المشكلة التي يحلها

قائمة كتب كبيرة تستهلك عرض النطاق والوقت على العميل. الضغط يبدّل حجم الجسم مقابل دورة معالج على الخادم. على محول Express الحزمة `compression` وسيط على التطبيق. Fastify يستعمل `@fastify/compress`. إن كان Nginx أمام التطبيق، ضغطه هناك يمنع دفع الثمن مرتين.

## الفكرة ببساطة

الوسيط يرى ترويسة `Accept-Encoding` ويرد `Content-Encoding: gzip` أو `br` عندما يستحق الحجم. العتبة تتجاوز الأجسام الصغيرة لأن الترويسة قد تكبرها. الصور و PDF المضغوطة تُستثنى. لا تضغط مسارًا فيه سر في عنوان إن كان السجل سيسجل العنوان، والضغط لا يخفي المحتوى عن من يملك TLS.

## التعريف التقني

على Express كما في أسلوب Nest للوسيط:

```ts
import compression from 'compression';
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module.js';

const app = await NestFactory.create(AppModule);
app.use(compression());
await app.listen(process.env.PORT ?? 3000, '0.0.0.0');
```

هذا `app.use` لمحول Express. على Fastify سجّل الإضافة الخاصة به لا حزمة Express. راجع محولك قبل النسخ.

Nginx:

```nginx
gzip on;
gzip_types application/json text/plain application/javascript;
```

إن فعّلت الاثنين فقد يضغط Nginx جسمًا مضغوطًا أو يكرر العمل. اختر طبقة واحدة. الوكيل يرى كل الاستجابات ويملك عتادًا مناسبًا. التطبيق يضغط إن لم يوجد وكيل أو إن كان الوكيل يمرر الجسم كما هو.

العتبة الافتراضية في `compression` تتجاوز الاستجابات الصغيرة. ارفعها إن كانت قوائمك الكبيرة فقط هي المقصودة.

HTTPS لا يلغي الفائدة. الضغط على النص قبل التشفير يقلل ما يُنقل. لا تضغط وتخزّن أسرارًا في وسيط مشترك بلا سياسة.

قياس: قارن حجم الجسم ووقت المعالج قبل التعميم. مسار يعيد 200 بايت لا يحتاج gzip.

## Mental Model

```text
عميل يرسل Accept-Encoding
طبقة واحدة تضغط JSON
الصورة والPDF تمر
لا ضغط مزدوج مع Nginx
```

## أبسط مثال

`app.use(compression())` خلف محول Express، والوكيل بلا `gzip` حتى تقيس. اطلب `GET /books` مع الترويسة وراقب `Content-Encoding`. ثم انقل الإعداد إلى Nginx واحذف وسيط التطبيق إن أصبح الوكيل هو الطبقة.

## شرح المثال

الوسيط يغلّف الاستجابة. الأجسام التي يكتبها Nest كـ JSON مؤهلة. تدفق ملف خام قد لا يناسب الوسيط نفسه. رفع الملفات مسار مختلف ولا يُضغط كأنه JSON.

## ماذا يحدث داخليًا؟

1. الطلب يعلن الخوارزميات المقبولة.
2. الوسيط أو Nginx يختار واحدة.
3. الجسم يُضغط ثم يُرسل مع الترويسة.
4. العميل يفك الضغط.
5. طبقة ثانية قد تفسد الجسم أو تضيع المعالج.
6. العتبة تترك الأجسام الصغيرة كما هي.

## مثال عملي

قائمة بحث كبيرة: ضغط JSON على Nginx `gzip_types application/json`. صور الغلاف من مخزن كائنات تُخدم كما هي. عطّل الضغط على `image/jpeg`. راقب CPU النسخة قبل إضافة Brotli. إن كان المعالج مشبعًا فالضغط في الوكيل على آلة منفصلة أرحم لحدث Node.

## أخطاء شائعة

- ضغط في Nest و Nginx معًا.
- ضغط JPEG.
- افتراض أن Fastify يقبل `compression` الخاصة بـ Express.
- تفعيل على جسم 100 بايت وتوقع ربحًا.
- اعتبار الضغط تشفيرًا.

## متى نستخدمه؟

JSON نصي كبير على مسار عام، في طبقة واحدة.

## متى لا نستخدمه؟

ملفات مضغوطة أصلًا، وأجسام صغيرة، ومسار المعالج مشبع والوكيل يستطيع الحمل.

## مقارنة

| الطبقة | متى |
| --- | --- |
| `compression` على Express | لا وكيل أو الوكيل يمرر |
| `@fastify/compress` | محول Fastify |
| `gzip` في Nginx | الوكيل ينهي الاتصال للعميل |

## أسئلة مراجعة

- أي حزمة لمحول Express؟
- لماذا طبقة واحدة؟
- ماذا لا يفعله الضغط للأسرار؟

## الخلاصة

اضغط JSON الكبير في Nginx أو في وسيط المحول، لا في الاثنين. استثنِ الوسائط المضغوطة، وقِس المعالج قبل تعميم Brotli.
