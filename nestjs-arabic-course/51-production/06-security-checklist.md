# قائمة الأمن

## الهدف من هذا الدرس

مراجعة قصيرة قبل النشر: ترويسات، CORS، تحقق المدخلات، أخطاء بلا مكدس، أسرار، وكوكيز، من غير ادّعاء أن القائمة شهادة.

## المشكلة التي يحلها

تطبيق يعمل وظيفيًا ويفتح `cors: true` مع `helmet` مطفأ ويرد بمكدس TypeError. القائمة تذكّر بقرارات التوثيق الشائعة حتى لا يُنشر القالب كما هو. التفاصيل في فصول CORS والتحقق السابقة. هنا تجميع إنتاج.

## الفكرة ببساطة

فعّل `helmet` لترويسات آمنة افتراضية. حدد أصول CORS التي تعرفها. `ValidationPipe` مع `whitelist`. لا تُرجع المكدس للعميل. لا ترفع `.env`. ضع أعلام الكوكي `httpOnly` و `secure` و `sameSite` عندما تستخدم كوكي جلسة. قيّد المعدل على تسجيل الدخول. إن كنت خلف وكيل ففعّل `trust proxy` بعدد قفزات تعرفه حتى لا يُزوَّر عنوان العميل.

## التعريف التقني

```ts
import helmet from 'helmet';

const app = await NestFactory.create(AppModule);
app.use(helmet());
app.enableCors({ origin: ['https://shop.example'] });
```

```ts
app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,
    forbidNonWhitelisted: true,
    transform: true,
  }),
);
```

الفلتر العام في الإنتاج يسجل الخطأ ويرد `{ message: 'تعذر إكمال الطلب' }` مع رمز مناسب، بلا `stack`.

Swagger إن وُجد على مسار داخلي أو خلف صلاحية، لا على الإنترنت بلا حماية.

`trust proxy` على Express عندما TLS ينتهي عند Nginx:

```ts
const expressApp = app.getHttpAdapter().getInstance();
expressApp.set('trust proxy', 1);
```

الرقم `1` يعني وكيلًا واحدًا. رقم أكبر من الواقع يثق بترويسة يزوّرها العميل.

حد المعدل على `POST /auth/login` عبر الحارس أو الوكيل. لا تترك المحاولات بلا سقف.

هذه القائمة لا تغطي عزل المستأجرين ولا مراجعة اعتماديات `npm audit` الدورية. أضفها إلى عملية النشر لا إلى هذا الملف فقط.

## Mental Model

```text
helmet + CORS محدد
مدخلات مبيّضة
خطأ عام للعميل وسجل عندك
أسرار في البيئة
وكيل موثوق بعدد قفزات صحيح
```

## أبسط مثال

عطّل في مراجعة النشر أي `enableCors()` بلا خيارات إن كان المتصفح من أصل معروف. أصل واحد في المصفوفة يكفي للمتجر. التطبيقات المحلية تُضاف في التطوير لا في إنتاج عام.

## شرح المثال

`origin: true` أو انعكاس الأصل يطلبه المتصفح يعني أن أي موقع يستطيع استدعاء API ببيانات اعتماد إن جمعت ذلك مع `credentials`. حدد الأصل. `helmet` لا يستبدل التحقق من JWT. هو يغلق ترويسات المتصفح الشائعة.

## ماذا يحدث داخليًا؟

1. `helmet` يضع ترويسات على الاستجابة.
2. CORS يقرر قبل أن يكمل المتصفح الطلب الفعلي.
3. الأنبوب يحذف الحقول غير المزينة أو يرفضها.
4. الفلتر يبتلع شكل الاستثناء الداخلي.
5. الوكيل يمرر `X-Forwarded-*` و `trust proxy` يفسرها.
6. الكوكي بلا `secure` تسير على HTTP إن أخطأ الوكيل.

## مثال عملي

قائمة تحقق لسحب النشر: لا `.env` في Git، و `helmet`، وأصل الواجهة فقط، و `whitelist`، وفلتر بلا مكدس، وحد لمسار الدخول، و `trust proxy` إن وُجد Nginx، وSwagger مقيد. راجعها على البيئة لا على الذاكرة.

## أخطاء شائعة

- `cors: { origin: '*' }` مع كوكي اعتماد.
- `trust proxy` بقيمة `true` غير محدودة.
- مكدس في JSON.
- سر في صورة Docker.
- اعتبار Helmet بديلًا للصلاحيات على المسارات.

## متى نستخدمه؟

قبل كل نشر إنتاج وبعد إضافة مدخل جديد مثل رفع ملف أو كوكي.

## متى لا نستخدمه؟

لا تعطّل التحقق في الإنتاج لتمرير عميل قديم. أصلح العقد. ولا تفتح CORS للعالم لأن الواجهة على منفذ مختلف في التطوير. افصل إعداد التطوير.

## مقارنة

| البند | إنتاج |
| --- | --- |
| CORS | أصول معروفة |
| المدخل | `whitelist` |
| الخطأ | رسالة عامة |
| الكوكي | `httpOnly` و `secure` |
| الوكيل | `trust proxy` بعدد صحيح |

## أسئلة مراجعة

- ماذا لا يرجعه الفلتر للعميل؟
- أين تعيش الأسرار؟
- هل Helmet يغني عن Guard؟

## الخلاصة

أغلق الترويسات والأصول والمدخلات وأجسام الأخطاء والأسرار وقفزة الوكيل قبل النشر. القائمة بداية مراجعة لا نهاية التهديدات.

## ماذا بعد؟

Reverse Proxy و Nginx: أين ينتهي TLS وأين يقف Node.
