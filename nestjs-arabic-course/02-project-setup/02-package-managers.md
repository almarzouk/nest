# npm و pnpm و yarn و bun

## الهدف من هذا الدرس

معرفة ماذا يفعل مدير الحزم في مشروع Nest، وأي الأسماء يدعمها CLI الإصدار 12.

## المشكلة التي يحلها

الإطار مجموعة حزم على سجل npm. من غير مدير حزم تنسخ المجلدات يدويًا وتفقد القفل الذي يجعل تثبيت زميل المطابقة لتثبيت جهازك.

## الفكرة ببساطة

المدير يقرأ `package.json`، ينزّل الاعتماديات، ويكتب ملف قفل. npm يأتي مع Node. Nest CLI 12 يدعم أيضًا yarn و pnpm و bun.

## التعريف التقني

`package.json` يعلن الاسم والنسخة والسكربتات والاعتماديات. `dependencies` تلزم التشغيل. `devDependencies` للتطوير والاختبار والترجمة. ملف القفل (`package-lock.json` أو ما يقابله) يثبت النسخ الفعلية.

## Mental Model

```text
package.json   ماذا نريد
lockfile       ماذا ثُبّت بالضبط
node_modules   الملفات المحمّلة
```

## أبسط مثال

```bash
npm install
npm install @nestjs/common
```

## شرح المثال

بلا وسائط، `npm install` يثبّت ما في القفل أو في `package.json`. مع اسم حزمة يضيفها إلى `dependencies` ثم يثبّتها. `npm install -D` يضعها في `devDependencies`. pnpm أوامرها قريبة: `pnpm add`.

## ماذا يحدث داخليًا؟

المدير يحل شجرة الإصدارات، يتحقق من السجل، ويكتب `node_modules`. Nest لا تملك سجلًا خاصًا. `@nestjs/core` حزمة عامة. سكربتات `npm run start:dev` تقرأ مفتاح `scripts` الذي يولّده CLI.

## مثال عملي

في هذه الدورة الأمثلة تستخدم npm لأنه الافتراضي مع توثيق First steps. إن اختار الفريق pnpm فليبقَ القفل نفسه للجميع. لا تخلط مديرين في المستودع الواحد.

## أخطاء شائعة

- رفع `node_modules` إلى Git. القفل يكفي لإعادة التثبيت.
- حذف ملف القفل في كل تثبيت. تضيع قابلية التكرار.
- تثبيت حزمة Nest قديمة بنسخ مكتوبة في درس قديم من غير النظر إلى توثيق 12.

## متى نستخدمه؟

لإضافة `@nestjs/config` أو `class-validator` أو عميل قاعدة البيانات عندما يصل درسها.

## متى لا نستخدمه؟

لا تثبّت حزمة قبل الفصل الذي يشرحها كي لا يصبح المشروع كومة اعتماديات صامتة.

## مقارنة

| مدير | ملف قفل شائع | دعم Nest CLI 12 |
| --- | --- | --- |
| npm | package-lock.json | نعم |
| pnpm | pnpm-lock.yaml | نعم |
| yarn | yarn.lock | نعم |
| bun | bun.lock | نعم في CLI 12 |

## تمارين

### تمرين سهل

أي ملف تعلن فيه سكربت `start:dev`؟

<details><summary>الحل</summary>

`package.json` تحت المفتاح `scripts`.

</details>

### تمرين متوسط

لماذا يثبّت زميلك نسخة مختلفة من حزمة إذا لم يُرفع ملف القفل؟

<details><summary>الحل</summary>

`package.json` قد يسمح بمدى إصدارات. المدير يحل أحدث ما يطابق المدى يوم التثبيت. القفل يثبت الحل الذي اختُبر.

</details>

### تمرين متقدم

فرّق بين اعتمادية تشغيل مثل `@nestjs/core` واعتمادية تطوير مثل أداة الاختبار.

<details><summary>الحل</summary>

الأولى تبقى في الإنتاج لأن التطبيق يستوردها عند التشغيل. الثانية تُستخدم للبناء أو الاختبار ويمكن إسقاطها من تثبيت الإنتاج (`npm ci --omit=dev`) بعد وجود ناتج البناء.

</details>

## أسئلة مراجعة

- ماذا يثبت ملف القفل؟
- أين تعيش سكربتات npm؟
- أي مديري حزم يذكرهم مسار Nest 12 إضافة إلى npm؟

## الخلاصة

المدير يثبّت شجرة Nest من `package.json` والقفل. الزم الفريق على مدير واحد.

## ماذا بعد؟

CLI يستخدم المدير بعد أن ينشئ الملفات.
