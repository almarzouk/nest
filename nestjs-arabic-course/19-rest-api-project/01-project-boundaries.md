# حدود المشروع

## الهدف من هذا الدرس

رسم أصغر API منشورات يبقى داخل ما سبق: وحدات، DTO، أخطاء، و Prisma، بلا مصادقة ولا توثيق OpenAPI بعد.

## المشكلة التي يحلها

بناء «كل شيء» في ملف واحد يعيد HTTP و SQL والتحقق إلى دالة مسار. بناء عشر موارد قبل أن يعمل مورد واحد يؤخر أول طلب ناجح. الحدود تمنع إضافة أدوار وصلاحيات في الأسبوع نفسه الذي ما زال فيه شكل `User` غير مستقر.

## الفكرة ببساطة

ثلاثة موارد: `users` و `posts` و `comments`. كل مورد وحدة فيها متحكم وخدمة. القاعدة عبر `PrismaModule`. الجسم عبر DTO. الغياب `404`. التكرار `409`. القائمة تقبل صفحة وتصفية وترتيبًا بسيطين على المنشورات فقط. الهوية «من أنت» فصل لاحق. هنا نعرف كيف يُخزَّن المستخدم وكيف يُشار إليه.

## التعريف التقني

عقد القراءة والكتابة الذي سنثبّته:

| المسار | المعنى |
| --- | --- |
| `POST /users` | إنشاء مستخدم من بريد واسم وكلمة مرور ستُجزَّأ لاحقًا |
| `GET /users/:id` | مستخدم واحد بلا سر |
| `POST /posts` | منشور لمؤلف موجود |
| `GET /posts` | قائمة بصفحة ومرشّح وترتيب |
| `GET /posts/:id` | منشور واحد |
| `POST /posts/:postId/comments` | تعليق على منشور |
| `GET /posts/:postId/comments` | تعليقات ذلك المنشور |

الأرقام في المسار تُفحص بـ `ParseIntPipe` إن كان `id` عددًا صحيحًا كما في نماذج Prisma في الفصل السابق. كلمة المرور لا ترجع في JSON. الإخفاء الكامل بأدوات التسلسل في فصل `25`. هنا الخدمة تختار الحقول في `select`.

خارج الحدود: تسجيل الدخول، الأدوار، رفع الملفات، الكاش، GraphQL.

## Mental Model

```text
UsersModule     يملك User
PostsModule     يملك Post ويشير إلى authorId
CommentsModule  يملك Comment ويشير إلى postId
PrismaModule    مشترك
لا Guard هوية في هذا الفصل
```

## أبسط مثال

```prisma
model User {
  id           Int      @id @default(autoincrement())
  email        String   @unique
  name         String
  passwordHash String
  posts        Post[]
}

model Post {
  id        Int       @id @default(autoincrement())
  title     String
  body      String
  published Boolean   @default(false)
  author    User      @relation(fields: [authorId], references: [id])
  authorId  Int
  comments  Comment[]
}

model Comment {
  id      Int    @id @default(autoincrement())
  body    String
  post    Post   @relation(fields: [postId], references: [id])
  postId  Int
}
```

## شرح المثال

العلاقات مفاتيح أجنبية كما في فصل القاعدة. `passwordHash` عمود موجود لأن التسجيل سيحتاجها في فصل المصادقة، والاستجابة لا تضمّنه. `published` يسمح بتمرين التصفية. تعليق بلا منشور مرفوض من القيد.

الترحيل ملف جديد `add_posts_comments` بعد دمج المخطط، ثم `prisma generate`.

## ماذا يحدث داخليًا؟

طلب لا يعرفه الجدول يمر على Nest حتى الخدمة، والقاعدة ترفض المفتاح الأجنبي. لذلك «مؤلف موجود» يُفحص في الخدمة برسالة `404` قبل الكتابة حين نريد رسالة أوضح، والقيد يبقى للحالة المتزامنة.

لا توجد جلسة. أي عميل يستطيع `POST /users` في هذا الفصل. هذا متعمَّد حتى يُرى المورد قبل حارس الهوية. لا تنشر هذا الشكل على إنترنت مفتوح.

## مثال عملي

اكتب قائمة الملفات قبل الكود: `users.module.ts`، `users.service.ts`، `users.controller.ts`، ومثلها للمنشور والتعليق، و DTOs بجانب كل مورد. `AppModule` يستورد الوحدات الثلاث و `PrismaModule` و `ConfigModule`. إن لم تستطع تسمية الملف الذي سيحتوي قاعدة «لا تعليق على منشور محذوف»، فالحد ما زال ضبابيًا: القاعدة في `CommentsService`.

## أخطاء شائعة

- مورد واحد اسمه `AppController` لكل المسارات.
- إرجاع `passwordHash` مع المستخدم.
- بدء OAuth قبل أن ينجح `GET /posts/1`.
- ترقيم عام معقّد قبل أن تعمل صفحة واحدة. التعميم في الفصل `26`.

## متى نستخدمه؟

كهيكل أول API عملي في الدورة، وعلى أي تمرين يريد ثلاث موارد مترابطة.

## متى لا نستخدمه؟

كنسخة إنتاج فيها هوية وصلاحيات. تلك تُضاف في الفصول التالية على نفس الموارد، لا في مشروع ثانٍ.

## مقارنة

| داخل الحدود | مؤجَّل |
| --- | --- |
| وحدات المستخدم والمنشور والتعليق | تسجيل الدخول |
| DTO و `404` و `409` | الأدوار |
| `skip` و `take` على القائمة | عقد ترقيم مشترك |

## تمارين

### تمرين سهل

أي وحدة تملك كتابة `Comment`؟

<details>
<summary>الحل</summary>

`CommentsModule` عبر `CommentsService`. `PostsModule` لا تفتح جدول التعليقات مباشرة.

</details>

### تمرين متوسط

لماذا `passwordHash` في المخطط وليس في JSON الاستجابة؟

<details>
<summary>الحل</summary>

العمود لازم للتحقق لاحقًا. العقد العام لا يرسل السر. الخدمة تستخدم `select` بلا هذا الحقل إلى أن يأتي فصل التسلسل فيوحّد المنع.

</details>

### تمرين متقدم

صمّم مسارًا بديلًا `POST /users/:id/posts`. ماذا يبقى في `PostsService` رغم تغيّر الشكل؟

<details>
<summary>الحل</summary>

التحقق من وجود المؤلف، وكتابة `authorId` من المعامل لا من جسم غير موثوق إن كان المسار هو مصدر الهوية هنا. القاعدة «منشور لمؤلف موجود» لا تنتقل إلى المتحكم كـ SQL.

</details>

## أسئلة مراجعة

- ما الموارد الثلاثة؟
- ماذا لن نبني في هذا الفصل؟
- أين تعيش علاقة التعليق بالمنشور؟

## الخلاصة

المشروع ثلاثة موارد على Prisma بعقد HTTP صغير. الهوية والتوثيق والتسلسل فصول لاحقة على الهيكل نفسه.
