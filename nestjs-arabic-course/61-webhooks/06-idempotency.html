Idempotency

الهدف من هذا الدرس

جعل معالجة حدث الويب هوك في رف مرة واحدة لكل معرّف، سواء أعاد المزود الوارد أو أعاد عاملكم الصادر.

المشكلة التي يحلها

حفظتم الاشتراك active ثم انقطع الرد، فأعاد Stripe نفس evt_1 وطبّقتم «مدد الخطة شهرًا» مرتين. أو الشريك لم ير 2xx فاستلم book.published مرتين وأخرج شحنتين. التوقيع صحيح في المرتين لأن الجسم نفسه.

الفكرة ببساطة

مفتاح التكرار هو معرّف الحدث الذي يختاره المرسل ويبقى ثابتًا عبر المحاولات. قبل الأثر، أدرجوا صفًا فريدًا (source, eventId). النجاح الثاني يجد الصف ويعيد 200 بلا أثر جديد. الصادر يرسل نفس المعرّف في كل محاولة ويطلب من الشريك هذا العقد.

التعريف التقني

قيد فريد على eventId القادم من المزود. العملية: INSERT الحدث. إن خالف القيد، فالحدث شُوف سابقًا: ردوا 200 ولا تعيدوا تحديث الاشتراك. إن نجح INSERT، طبّقوا الأثر في نفس المعاملة إن أمكن ثم التزموا. سباق نسختين: واحدة تفوز بالقيد والأخرى ترى التعارض. هذا ليس Idempotency-Key الذي يولّده جوال لإنشاء كتاب، لكن الفكرة واحدة: مفتاح ثابت ونتيجة واحدة. للصادر، الترويسة مثل X-Raf-Event-Id جزء من العقد المكتوب للشريك.

Mental Model

evt_1 أول مرة → INSERT + أثر + 200
evt_1 مرة أخرى → القيد يمنع → 200 بلا أثر

أبسط مثال

export async function once(seen: Set<string>, eventId: string, effect: () => Promise<void>) {
  if (seen.has(eventId)) return { duplicate: true };
  seen.add(eventId);
  await effect();
  return { duplicate: false };
}

شرح المثال

  • Set في الذاكرة تختفي مع العملية فلا تكفي إنتاجًا. القيد في Postgres يبقى.
  • duplicate: true ما زال نجاحًا من جهة المزود (200) لا 409. المزود لا يستطيع «إصلاح» التكرار؛ هو متوقع.
  • الأثر لا يعمل في الفرع المكرر.

ماذا يحدث داخليًا؟

  1. التوقيع ينجح على rawBody.
  2. تقرأون id من JSON.
  3. تحاولون إدراج webhook_events بالمفتاح.
  4. P2002 يعني مكرر: التزموا بلا أثر إضافي وأرجعوا 200.
  5. الإدراج الجديد يحدّث الاشتراك في نفس المعاملة. فشل التحديث يتراجع عن الإدراج أيضًا حتى يعيد المزود المحاولة فعلًا.

مثال عملي

import { Prisma } from '@prisma/client';

export async function applyBillingEvent(tx: {
  webhookEvent: { create: (args: { data: { id: string } }) => Promise<unknown> };
  subscription: { update: Function };
}, event: { id: string; organizationId: string; status: string }) {
  try {
    await tx.webhookEvent.create({ data: { id: event.id } });
  } catch (error) {
    if (error instanceof Prisma.PrismaClientKnownRequestError && error.code === 'P2002') return;
    throw error;
  }
  await tx.subscription.update({
    where: { organizationId: event.organizationId },
    data: { status: event.status },
  });
}

إن كان organizationId من ربط عميل Stripe لا من جسم غير موثوق، كما في درس الوارد. المكرر يخرج بلا update ثانٍ.

أخطاء شائعة

  • 409 على المكرر فيعيد المزود إلى الأبد أو يوقف الأحداث.
  • فحص SELECT ثم INSERT بلا قيد فيمر سباق النسختين.
  • اعتبار كل إعادة جسمًا جديدًا لأن الطابع في الترويسة تغيّر.
  • مفتاح تكرار صادر يتغير مع attempts.

متى نستخدمه؟

على كل حدث وارد له أثر، وعلى عقد كل صادر تعدّون شريكًا عليه.

متى لا نستخدمه؟

لا تستبدلوا به التوقيع. المكرر بلا توقيع ما زال مرفوضًا. ولا تستخدموا عنوان IP كمفتاح.

مقارنة

المفتاح من يولّده التكرار
Idempotency-Key لإنشاء كتاب جوال رف نفس 201
event.id الوارد المزود 200 بلا أثر ثانٍ
X-Raf-Event-Id الصادر رف الشريك يطبّق مرة

تمارين

تمرين سهل

وصل evt_9 مرتين والتوقيع صحيح. كم مرة يُحدَّث الاشتراك؟

الحل

مرة. الثانية تصطدم بالقيد وترد 200 بلا update.

تمرين متوسط

لماذا يتراجع INSERT إذا فشل تحديث الاشتراك؟

الحل

حتى لا يُعلَّم الحدث منجزًا بلا أثر. المزود سيعيد، والمعاملة الجديدة تستطيع الإدراج من جديد. إن التزمتم الإدراج فقط فلن تُطبَّق الإعادة.

تمرين متقدم

نسختا API عالجتا evt_9 معًا. ما الذي يجعل واحدة فقط تكتب active؟

الحل

القيد الفريد على id. واحدة تُدرج وتحدّث، والأخرى تحصل على P2002 وتخرج. فحص الوجود في الذاكرة على كل عملية لا يكفي.

أسئلة مراجعة

  • ما مفتاح الوارد؟
  • لماذا الرد على المكرر 200 لا 409؟
  • لماذا القيد لا الاستعلام ثم الإدراج؟
  • ماذا يبقى ثابتًا في محاولات الصادر؟

الخلاصة

كل حدث ويب هوك له معرّف ثابت وقيد فريد. المعالجة الأولى تُحدث الأثر، والإعادة ترد نجاحًا بلا أثر ثانٍ. التوقيع يثبت المرسل، والمفتاح يثبت المرة الواحدة.

ماذا بعد؟

الوارد الأشيع في رف هو Stripe. الفصل التالي يضع حدود Checkout والاشتراك والويب هوك ومفتاح المزود نفسه.
