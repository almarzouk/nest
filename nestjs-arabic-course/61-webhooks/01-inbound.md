# Inbound Webhooks

## الهدف من هذا الدرس

استقبال إشعار HTTP من نظام خارجي إلى رف، مثل مزود دفع يقول إن الاشتراك تغيّر، والتعامل معه كمدخل غير موثوق حتى يُثبت.

## المشكلة التي يحلها

رف تنتظر أن يحدّث الموظف حالة الخطة يدويًا بعد الدفع. أو تفتح مسارًا داخليًا بجلسة المستخدم فيستدعيه المزود بلا كعكة فيفشل، أو ينجح أي شخص ينادي نفس المسار.

## الفكرة ببساطة

الويب هوك الوارد طلب `POST` يرسله المزود إلى عنوان عام عندكم. جسمه حدث. لا جلسة قارئ. إثباته توقيع على البايتات، ودرسه التاليان. هذا الدرس يضع المسار والمعنى: الحدث يُقبل ثم يُترجم إلى تحديث حالة، ولا يُوثق كتفاعل مستخدم.

## التعريف التقني

مسار مثل `POST /webhooks/billing` خارج حارس الجلسة (`@Public()` إن كان الحارس عامًا) وداخل حد خاص: تحقق توقيع ثم معالجة. الرد السريع 2xx بعد ما تحفظون الحدث أو ترفضون التوقيع بـ 400. لا تنتظروا عملًا طويلًا قبل الرد حتى لا يعيد المزود الإرسال ظنًا أنكم غبتم. صفحة Webhooks في Nest إطار لهذا النمط، وصفحة Raw body شرط حساب التوقيع. لا تثقوا بـ `organizationId` داخل JSON إن لم يربطه التوقيع ومعرّف الحدث بصف عندكم.

## Mental Model

```text
مزود → POST /webhooks/billing
     → تحقق (لاحقًا) → خزّن الحدث → حدّث الاشتراك
المتصفح ليس طرفًا هنا
```

## أبسط مثال

```ts
import { Controller, HttpCode, Post } from '@nestjs/common';
import { Public } from '@nestjs/authentication';

@Public()
@Controller('webhooks/billing')
export class BillingWebhookController {
  @Post()
  @HttpCode(200)
  receive() {
    return { received: true };
  }
}
```

## شرح المثال

- `@Public()` يزيل جلسة القارئ لا التحقق الخاص بالمزود. أضيفوا التحقق قبل أي تحديث.
- 200 السريع عقد مع المزود. المعنى «استلمنا» لا «نشرنا كل الأثر» إن كان الأثر في طابور بعد الحفظ.
- لا `@CurrentUser()` هنا. لا مستخدم جالس.

## ماذا يحدث داخليًا؟

1. المزود يرسل الحدث إلى العنوان المسجّل في لوحته.
2. Nest يوجه المسار إلى المتحكم العام.
3. قبل تغيير `Subscription` يجب أن يمر التوقيع ومفتاح التكرار.
4. التحديث يكتب الحالة المحلية التي يقرأها `PlanPolicy`.
5. صفحة نجاح المتصفح لا تستدعي هذا المتحكم نيابة عن المزود.

## مثال عملي

```ts
export function assertWebhookTenant(eventOrg: string | undefined, localOrg: string) {
  if (!eventOrg || eventOrg !== localOrg) {
    throw new Error('event is not bound to a local organization');
  }
}
```

اربطوا معرّف عميل Stripe المخزن عند إنشاء المنظمة بـ `organizationId` المحلي. لا تأخذوا المكتبة من حقل حر في JSON حتى لو كان التوقيع صحيحًا لحدث يخص عميلًا آخر لصقتم معرّفه.

## أخطاء شائعة

- المسار خلف حارس الجلسة فقط.
- تنفيذ النشر أو إلغاء الكتب من غير التحقق من نوع الحدث.
- الرد 500 بعد ما حدّثتم القاعدة فيعيد المزود فيتكرر الأثر.
- اعتبار الوارد بديلًا عن سجل التدقيق. يمكنكم تدوين «النظام: billing.updated» كفاعل نظام لا كمستخدم.

## متى نستخدمه؟

عندما تتغير حالة عند مزود ويجب أن تنعكس عندكم من غير أن يفتح المستخدم رف في تلك اللحظة.

## متى لا نستخدمه؟

لسحب دوري تستطيعون جدولته إن كان المزود بلا إشعارات وعدد المكتبات صغيرًا. ولا لاستقبال نماذج من متصفح القارئ؛ ذلك `POST` عادي بمصادقة.

## مقارنة

| | طلب قارئ | ويب هوك وارد |
| --- | --- | --- |
| من ينادي | تطبيق رف | مزود |
| الإثبات | جلسة أو Bearer | توقيع على الجسم |
| المستأجر | من الحل الموثوق | من ربط معرّف المزود بصفكم |

## تمارين

### تمرين سهل

لماذا `@Public()` لا يعني أن المسار مفتوح بلا سر؟

<details>
<summary>الحل</summary>

لأنه يتجاوز حارس المستخدم فقط. سر المزود أو التوقيع ما زال شرطًا قبل كتابة الاشتراك.

</details>

### تمرين متوسط

المزود أعاد الإرسال لأنكم تأخرتم في ضغط صورة داخل المتحكم. ماذا تغيّرون في ترتيب الرد؟

<details>
<summary>الحل</summary>

احفظوا الحدث وردوا 200 ثم عالجوا العمل الثقيل في مهمة. لا تبقوا الاتصال مفتوحًا على CPU.

</details>

### تمرين متقدم

حدث صحيح التوقيع فيه `organizationId` لمكتبة أخرى غير عميل Stripe المخزن. ماذا تحدّثون؟

<details>
<summary>الحل</summary>

لا شيء في مكتبة الجسم. اربطوا عميل المزود بالمنظمة التي خزّنتموها عند إنشاء الاشتراك. اختلاف الجسم عن هذا الربط يُرفض ويُسجَّل.

</details>

## أسئلة مراجعة

- من يبدأ الطلب الوارد؟
- لماذا الرد السريع جزء من العقد؟
- من أين تُعرف المكتبة؟
- لماذا المسار ليس جلسة قارئ؟

## الخلاصة

الويب هوك الوارد `POST` عام من مزود، بلا جلسة مستخدم، يثبت بالتوقيع لاحقًا، ويحدّث حالة محلية مربوطة بمعرّف عندكم. صفحة النجاح ليست هذا المسار.

## ماذا بعد؟

رف أيضًا ترسل إشعارات إلى شركاء المكتبة عند نشر كتاب. الدرس التالي الصادر.
