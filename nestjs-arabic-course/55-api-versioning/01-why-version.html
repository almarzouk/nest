لماذا الإصدارات

الهدف من هذا الدرس

تقرير متى يشغّل متجر رف نسختين من نفس القدرة داخل عملية Nest واحدة، ومتى يكون التغيير إضافة يتحملها العملاء الحاليون بلا إصدار.

المشكلة التي يحلها

تطبيق الجوال في المتاجر يقرأ price كعدد صحيح بالسنت. موقع الرف الجديد يريد price كائنًا { amount, currency }. نشر الشكل الجديد يكسر الجوال في نفس اليوم. إبقاء الشكل القديم يمنع الموقع. الفرعان مطلوبان معًا إلى أن يُحدَّث الجوال.

الفكرة ببساطة

الإصدار اسم لعقد لا اسم لتاريخ نشر. طالما العملاء يتحملون الإضافة، تبقى على العقد الحالي. عندما يتغير معنى حقل أو يختفي، تُخدم النسخة السابقة بجانب الجديدة. Nest يختار الفرع من الطلب بعد تفعيل enableVersioning.

التعريف التقني

app.enableVersioning({ type }) من تطبيق HTTP فقط، كما تذكر صفحة Versioning. الأنواع في التوثيق: URI (الافتراضي في الجدول)، Header، Media Type، و Custom. من غير إصدار على المتحكم أو المسار ومن غير defaultVersion، الطلب يأخذ 404 حتى لو كانت الدالة موجودة. هذا الدرس لا يختار النوع؛ يختار إن كان التغيير يستحق نسختين. الصفحة الرسمية: https://docs.nestjs.com/techniques/versioning (نفس الفصل على https://docs.nestjs.com/http/versioning).

Mental Model

تغيير يكسر قارئًا قديمًا  → نسخة جديدة بجانب القديمة
حقل اختياري جديد          → نفس النسخة
إصلاح نص رسالة            → نفس النسخة إن لم يتغير المعنى

أبسط مثال

جوال قديم   يفهم { "price": 2500 }
موقع جديد   يفهم { "price": { "amount": 2500, "currency": "SAR" } }
العملية الواحدة تخدم الشكلين إلى تاريخ إيقاف معلن

شرح المثال

  • الرقمان ليسا «إصدار الكود» في git. هما عقدان على السلك.
  • إيقاف القديمة قرار تقويم: راقب من يناديها ثم احذف المتحكم.
  • الإصدار لا يعزل قاعدة البيانات. الصف واحد، والتمثيل هو الذي يتعدد.

ماذا يحدث داخليًا؟

  1. الفريق يكتب ما الذي سينكسر: نوع price، لا «تحديث الكتب».
  2. يبقي مسار العقد القديم ويستخرج التمثيل القديم من نفس الخدمة.
  3. يضيف مسار العقد الجديد.
  4. التفعيل العام في main.ts يجعل الطلب بلا نسخة 404 ما لم تضع defaultVersion.
  5. بعد إيقاف الجوال القديم، يُحذف الفرع القديم دفعة واحدة لا بحقول مهملة إلى الأبد.

مثال عملي

خدمة واحدة وتمثيلان. الاختيار سيكون في المتحكمات بعد تفعيل النوع:

export function toV1(book: { id: string; title: string; priceCents: number }) {
  return { id: book.id, title: book.title, price: book.priceCents };
}

export function toV2(book: { id: string; title: string; priceCents: number }) {
  return { id: book.id, title: book.title, price: { amount: book.priceCents, currency: 'SAR' } };
}

BooksService.find تعيد النموذج الداخلي priceCents. المتحكم هو الذي يستدعي toV1 أو toV2. هكذا لا تتفرع استعلامات Prisma لكل عميل.

أخطاء شائعة

  • رقم إصدار لكل نشر أسبوعي. العملاء لا يستطيعون اللحاق، والعملية تمتلئ بنسخ ميتة.
  • إصدار لأن الحقل الجديد «قد يزعج أحدًا» رغم أنه إضافة اختيارية.
  • نسخ الخدمة والجدول لكل إصدار فتصبحان كتالوجين.
  • نسيان أن تفعيل الإصدار بلا defaultVersion يخفي المسارات الحالية خلف 404.

متى نستخدمه؟

كسر نوع أو حذف حقل أو تغيير معنى رمز اعتاد عليه عميل لا تستطيع تحديثه في نفس لحظة النشر.

متى لا نستخدمه؟

للإضافات المتوافقة، ولإصلاح عطل يعيد السلوك الموثق، ولتجارب داخلية يمكن عزلها بعلم ميزة على خادم واحد.

مقارنة

التغيير إصدار جديد؟
إضافة subtitle اختياري لا
price من عدد إلى كائن نعم
404 كانت ترجع 200 بالخطأ وأُصلحت لتطابق العقد لا، هذا إصلاح
حذف price نعم

تمارين

تمرين سهل

أضفت available: boolean إلى كتاب. هل تفتح v2؟

الحل

لا، إن بقي كل حقل قديم بنوعه. العميل الذي يتجاهل المجهول يكمل. افتح نسخة فقط إن كان عميل صارم يرفض الحقول الزائدة وأنت ملتزم بدعمه، وهذا يُذكر في العقد.

تمرين متوسط

لماذا تفعيل enableVersioning مساء النشر قد يحوّل كل المسارات الحالية إلى 404؟

الحل

لأن الصفحة تقول: إن فُعّل الإصدار ولم يحدد المتحكم أو المسار نسخة ولم يوجد defaultVersion، فالطلب 404. قبل التفعيل، ضع النسخة على المتحكمات أو ضع defaultVersion.

تمرين متقدم

الجوال سيبقى ستة أشهر. ارسم ماذا يُحذف يوم الإيقاف.

الحل

متحكم أو مسار v1 ودالة toV1 واختباراته. النموذج الداخلي priceCents يبقى. راقب نداءات v1 حتى تصل إلى صفر ثم احذف. لا تترك التمثيل القديم «احتياطًا» بلا مقياس.

أسئلة مراجعة

  • ما شرط فتح نسخة جديدة؟
  • أين يعيش الفرق: في صف القاعدة أم في التمثيل؟
  • ماذا يحدث للمسار بلا نسخة بعد التفعيل إن لم تحدد افتراضيًا؟
  • لماذا ليس كل نشر إصدارًا؟

الخلاصة

الإصدار يخدّم عقدين أثناء انتقال العملاء. الإضافة المتوافقة تبقى على العقد الحالي. التفعيل بلا نسخة معلنة على المسار أو بلا defaultVersion يعيد 404.

ماذا بعد؟

القرار وُجد: سعر رف سيتغير نوعه. الدرس التالي يضع رقم النسخة في المسار نفسه، وهو نوع URI.
