OpenID Connect

الهدف من هذا الدرس

إضافة هوية فوق التفويض: مع رمز الوصول يأتي ID token يقول من المستخدم لدى المزود، وتتحقق رف من توقيعه قبل إنشاء جلستها.

المشكلة التي يحلها

OAuth أعطاكم access token إلى API المزود. قراءته لا تثبت وحدها أنكم عرفتم الشخص: الرمز قد يكون لنطاق بلا هوية، أو لواجهة لا تعيد موضوعًا ثابتًا. موظف رف سجّل بـ Google ثم غيّر بريده، وانكسر الربط لأنكم خزّنتم البريد مفتاحًا.

الفكرة ببساطة

OpenID Connect طبقة هوية على OAuth 2.0. المزود خادم تفويض ويمنح ID token (غالبًا JWT) فيه sub ثابت و iss و aud و exp. التطبيق يتحقق من التوقيع والمطالبات ثم يربط sub بحساب محلي. البريد صفة قد تتغير. sub لا يُستبدل كمفتاح الربط.

التعريف التقني

@nestjs/authentication يشمل OpenID Connect مع الجلسات وتجزئة كلمات المرور والرموز، والحالة في مخزن تكتبونه ضد واجهات موثّقة (OidcStateStore وغيرها). التدفق في الحزمة: authorization code مع PKCE و state و nonce. OidcService.start يبدأ التوجيه و finish ينهي العودة: يطابق state بسر في كعكة __Host-oidc_tx، يستبدل الرمز، ويتحقق من توقيع ID token مقابل مفاتيح المزود المنشورة ومن المصدر والجمهور والانتهاء و nonce. فشل الوصول إلى المزود أو نقطة نهاية ليست https يُجاب بـ 502 لا 401 حسب الصفحة. وصفة Passport تبقى على https://docs.nestjs.com/recipes/passport لمن يختارها. لا تشغّلوا المسارين على نفس تسجيل الدخول.

Mental Model

access token  → ماذا يُسمح أن نفعل عند المزود
ID token      → من هو sub لدى iss
حساب رف       → صف محلي مرتبط بـ (provider, sub)

أبسط مثال

export interface OidcIdentity {
  provider: string;
  subject: string;
}

export function identityKey(id: OidcIdentity) {
  return `${id.provider}:${id.subject}`;
}

شرح المثال

  • المفتاح زوج. sub من Google ليس فريدًا عبر المزودات.
  • لا تضع البريد في المفتاح.
  • الصف المحلي لرف (User.id) شيء آخر. الربط جدول هويات.

ماذا يحدث داخليًا؟

  1. start يحفظ معاملة الدخول تحت state ويرسل المتصفح إلى المزود.
  2. العودة تحمل code. finish يفحص الكعكة ثم يستبدل الرمز.
  3. يتحقق من ID token. nonce يمنع إعادة رمز قديم في غير محاولته.
  4. aud يجب أن يكون عميل رف المسجّل. توكن مزود لجمهور آخر يُرفض.
  5. بعدها فقط يُسأل تطبيقكم: أي مستخدم محلي يقابل هذا sub.

مثال عملي

export function acceptIdClaims(claims: { iss?: string; aud?: string; sub?: string; exp?: number }, now: number) {
  if (claims.iss !== 'https://accounts.google.com') return false;
  if (claims.aud !== process.env.GOOGLE_CLIENT_ID) return false;
  if (!claims.sub) return false;
  if (!claims.exp || claims.exp * 1000 <= now) return false;
  return true;
}

هذا فحص شكل قبل أن تثقوا بمكتبة. التحقق الفعلي من التوقيع ضد JWKS تقوم به الحزمة في finish، لا JSON.parse للجزء الأوسط من JWT. لا تعيدوا بناء التوقيع يدويًا.

أخطاء شائعة

  • الثقة بحمولة JWT من غير تحقق توقيع.
  • ربط الحساب بالبريد فقط.
  • اعتبار access token الخاص بالمزود جلسة رف الدائمة وتمريره إلى كل GET /books.
  • تشغيل Passport strategy و OidcService على نفس المسار فيتنازعان على الكعكة.

متى نستخدمه؟

عندما يثبت مزود خارجي هوية شخص لتفتحوا له جلسة رف أو رمز رف.

متى لا نستخدمه؟

عندما تحتاجون إذنًا على API المزود بلا حساب شخص في رف (مهمة خادم-إلى-خادم بنطاق). هناك OAuth بلا مطالبة هوية. ولا عندما يكون الموظفون كلمات مرور محلية فقط.

مقارنة

OAuth 2.0 OpenID Connect
السؤال هل يُسمح بهذا النطاق؟ من هو sub؟
الرمز البارز access token ID token إضافة إلى التفويض
مفتاح الربط المحلي حسب API (provider, subject)

تمارين

تمرين سهل

مستخدم غيّر بريده عند Google. ماذا يبقى ثابتًا للربط؟

الحل

sub مع اسم المزود. البريد يُحدَّث كصفة إن وثقتهم بتغيّره، ولا يُستخدم كمفتاح الصف.

تمرين متوسط

لماذا 502 لا 401 عندما لا يُوصل إلى مفاتيح Google؟

الحل

لأن الفشل عند الاعتمادية الخارجية لا يعني أن إثبات المستخدم باطل. الصفحة تميّز هذا: تعذّر الوصول أو نقطة ليست https يُجاب بـ 502. التوثيق الفاشل لتوقيع مستخدم يرفض الدخول نفسه.

تمرين متقدم

ID token فيه aud لتطبيق آخر و sub صحيح. هل تفتحون جلسة؟

الحل

لا. الجمهور جزء من التحقق. توكن أُصدر لعميل آخر لا يُقبل حتى لو كان الموقع صحيحًا والتوقيع سليمًا.

أسئلة مراجعة

  • ماذا يضيف OIDC على OAuth؟
  • لماذا sub لا البريد؟
  • من يتحقق من التوقيع في مسار الحزمة؟
  • أين تبقى وثائق Passport؟

الخلاصة

OIDC يعطيكم ID token موثّقًا: مصدر، جمهور، انتهاء، nonce، و sub ثابت. حساب رف يُربط بالزوج (provider, subject). access token ليس جلسة رف. Passport ما زال وصفة رسمية إن اخترتموها بدل هذا المسار لا معه.

ماذا بعد؟

الهوية الخارجية واضحة. الدرس التالي شكل تسجيل الدخول الاجتماعي: حساب جديد، حساب عائد، وربط بحساب موجود.
