# Node.js

## الهدف من هذا الدرس

فهم البيئة التي تعمل داخلها NestJS: عملية JavaScript على الخادم، حلقة أحداث، و HTTP كمواطن من الدرجة الأولى.

## المشكلة التي يحلها

المتصفح يشغّل JavaScript مربوطًا بصفحة. Backend يحتاج عملية تبقى تعمل، تفتح منفذًا، وتتحدث إلى ملفات وشبكة وقواعد بيانات.

Node.js يعطي JavaScript هذه البيئة. NestJS إطار يشتغل فوقها، لا بديل عنها. إذا أوقفت Node، توقفت Nest.

## الفكرة ببساطة

Node.js بيئة تشغيل (runtime) لـ JavaScript خارج المتصفح. تبني على محرك V8، وتضيف مكتبة قياسية للشبكات والملفات والعمليات.

موقع Node يصفها بأنها asynchronous event-driven JavaScript runtime، مصممة لبناء تطبيقات شبكية قابلة للتوسع.

## التعريف التقني

عملية Node تشغّل JavaScript على خيط رئيسي واحد. العمل الذي ينتظر القرص أو الشبكة لا يحتل هذا الخيط طوال الانتظار: Node يسلّم الإدخال/الإخراج للنظام، ويعود ليشغّل JavaScript عندما تصل النتيجة عبر callback أو Promise.

هذا هو نموذج الحدث. الموقع الرسمي يقارنه بنموذج الخيوط (threads): خيط لكل اتصال أثقل وأصعب. Node يخدم اتصالات كثيرة على خيط JavaScript واحد ما دام عملك لا يحسب طويلًا على هذا الخيط.

وجود خيط واحد لـ JavaScript لا يعني أن الجهاز يستخدم نواة واحدة فقط. `worker_threads` وعمليات `cluster` و `child_process` موجودة. لن نوزع العمل الآن. سنذكر الحد حتى لا تظن أن `async` يسرّع حسابًا ثقيلًا.

## Mental Model

```text
طلب HTTP وصل
      |
      v
خيط JavaScript يشغّل دالتك
      |
      +--> إذا استدعت قاعدة البيانات بشكل غير حاجز
      |         الخيط يتفرغ لطلب آخر
      |         والنتيجة ترجع لاحقًا كـ Promise
      |
      +--> إذا حسبت 2 ثانية في حلقة for
                كل الطلبات الأخرى تنتظر
```

NestJS تعيش في هذا النموذج. Controller الذي ينام داخل حلقة ثقيلة يوقف بقية التطبيق على هذه العملية.

## أبسط مثال

المثال الرسمي من صفحة About، بنسخة ESM التي تناسب مشاريع Nest الحديثة:

```ts
import { createServer } from 'node:http';

const hostname = '127.0.0.1';
const port = 3000;

const server = createServer((req, res) => {
  res.statusCode = 200;
  res.setHeader('Content-Type', 'text/plain');
  res.end('Hello World');
});

server.listen(port, hostname, () => {
  console.log(`Server running at http://${hostname}:${port}/`);
});
```

تشغيله، بعد حفظه في `server.ts` وترجمته، أو عبر أداة تشغيل TypeScript تملكها، يفتح العملية. أبقِ التفاصيل العملية للفصل `02`. هنا الهدف هو سلوك Node.

## شرح المثال

مر سطرًا بسطر في درس HTTP. أضف ما يخص Node:

- لا يوجد استدعاء اسمه "ابدأ حلقة الأحداث". صفحة About توضح أن Node يدخل حلقة الأحداث بعد تنفيذ السكربت، ويخرج عندما لا تبقى callbacks. `listen` يسجّل مقبضًا يبقى مفتوحًا، لذلك العملية لا تخرج بعد آخر سطر.
- الدالة التي مررتها إلى `createServer` callback. Node يستدعيها عند الطلب. أنت لا تستدعيها في حلقة `while` كتبتها بنفسك.
- `res.end` لا يوقف العملية. ينهي استجابة واحدة.

هذا هو قلب الجملة التي ستسمعها عن الإطارات: **الإطار يستدعي كودك** في الوقت المناسب. Node بدأ بذلك قبل Express و Nest.

## ماذا يحدث داخليًا؟

صورة مبسطة، كافية الآن:

1. السكربت يشتغل من أعلاه إلى آخره ويسجّل المعالجات.
2. `listen` يطلب من النظام قبول اتصالات TCP.
3. حلقة الأحداث تنتظر: شبكة، مؤقتات، ملفات.
4. عند اكتمال طلب HTTP، تُستدعى دالتك.
5. إذا وصلت دالتك إلى عملية I/O غير متزامنة، تُسجَّل تكملة العمل (Promise أو callback) وتعود الدالة. الخيط يخدم غيرك.
6. عند وصول نتيجة الإدخال/الإخراج، التكملة تدخل الطابور وتعمل على الخيط نفسه.

صفحة About تقول أيضًا: لا شيء تقريبًا في Node يؤدي I/O بشكل مباشر حاجز، إلا إذا استدعيت النسخ المتزامنة من المكتبة القياسية. النسخ المتزامنة، مثل قراءة ملف بطريقة `Sync`، توقف الخيط. سنبتعد عنها في مسارات الطلب.

HTTP في Node مواطن من الدرجة الأولى، مصمم مع الانتباه للتدفق (streaming) والتأخير المنخفض. جملة الموقع: هذا يجعل Node مناسبًا كأساس لمكتبة ويب أو Framework. Express بُني على `node:http`. Nest بُنيت على Express أو Fastify، وهما على Node.

## مثال عملي

قراءة كتاب من قاعدة بيانات، بشكل غير حاجز. الكود توضيحي بلغة JavaScript المألوفة، وليس Nest بعد:

```ts
import { createServer } from 'node:http';

const server = createServer((req, res) => {
  void loadBook()
    .then((book) => {
      res.statusCode = 200;
      res.setHeader('Content-Type', 'application/json');
      res.end(JSON.stringify(book));
    })
    .catch(() => {
      res.statusCode = 500;
      res.end();
    });
});

server.listen(3000);

function loadBook(): Promise<{ id: string; title: string }> {
  return Promise.resolve({ id: '2', title: 'Refactoring' });
}
```

- المعالج لا ينتظر بحلقة. يعيد Promise.
- `void` يخبر القارئ أننا لا ننتظر الـ Promise هنا. Node سيكملها عندما تُحل.
- `JSON.stringify` يصنع جسم الاستجابة الذي درسته.
- `catch` يمنع سقوط العملية بصمت عند فشل غير معالج داخل هذه السلسلة. في Nest ستتحول هذه الأخطاء إلى Exception Filters. السلوك هنا يدوي لأننا على Node الخام.

لو استبدلت `loadBook` بحساب يستغرق ثانيتين على الخيط، الطلبات الأخرى على هذه العملية تتأخر ثانيتين حتى لو كانت قاعدة البيانات حرة.

## npm

Node يأتي مع npm: أداة تثبّت الحزم في المشروع وتدير السكربتات. NestJS نفسها حزمة، و Express حزمة، و Prisma حزمة. الفصل `02` يفرّق npm و pnpm وأوامر `nest`. الآن: كود الخادم الذي نكتبه يعتمد على مكتبات نعلنها في `package.json`، ولا ننسخها يدويًا إلى المشروع.

## أخطاء شائعة

- الظن أن `async/await` ينقل العمل إلى خيط آخر. `await` يعلّق الدالة هي فقط، ويحرر خيط JavaScript أثناء انتظار Promise. الحساب الثقيل بعد `await` ما زال على الخيط نفسه.
- استدعاء دوال `Sync` داخل معالجة الطلب.
- فتح خادم Node لكل مسار. خادم واحد يوجه المسارات. Express و Nest يقومان بهذا التوجيه.
- معاملة سقوط Promise من غير `catch` كأنه تفصيل. في الإنتاج يفشل الطلب وقد يُسقط العملية حسب إصدار Node وإعداداته. الإطارات تعطي مكانًا موحدًا لهذا، وسنصله.

## متى نختار Node؟

عندما نريد Backend بـ JavaScript أو TypeScript، وفريقنا يشارك اللغة مع الواجهة، والعمل الغالب انتظار شبكة وقاعدة بيانات لا حساب صور طويل على الخيط.

NestJS تفترض هذا الاختيار. التوثيق: Nest إطار لتطبيقات Node.js الخادمية، ومكتوب بـ TypeScript، ويشغّل TypeScript و JavaScript.

## متى نعيد النظر؟

عندما يكون العمل حسابًا مستمرًا على المعالج (ترميز فيديو، تدريب نموذج) داخل مسار الطلب. عندها نخرج العمل من خيط الطلب: طابور وعمليات أخرى. فصل Queues مبني على هذه الحقيقة، لا على رغبة في أدوات إضافية.

استخدام كل أنوية الجهاز لخادم HTTP يأتي مع `cluster` أو مع عدة عمليات خلف Nginx. صفحة About تذكر `child_process.fork` و `cluster`. التفاصيل في فصل الأداء والإنتاج.

## مقارنة

| | متصفح | Node.js | NestJS |
| --- | --- | --- | --- |
| يشغّل JavaScript | نعم | نعم | يعمل فوق Node |
| يفتح منفذ خادم | لا بالشكل العام | نعم | نعم عبر Node |
| يفرض Modules و DI | لا | لا | نعم |
| يعطيك `node:http` | لا | نعم | يستخدمه عبر Express أو Fastify |

### تمرين متوسط

لماذا تبقى العملية تعمل بعد تنفيذ آخر سطر في مثال `createServer`، بينما سكربت يطبع `hello` ثم ينتهي يخرج فورًا؟

<details>
<summary>الحل</summary>

`listen` يبقي مقبض استماع مفتوحًا، فحلقة الأحداث ما زال عندها عمل تنتظره. سكربت الطباعة لا يسجّل مؤقتًا ولا منفذًا ولا عملية معلّقة، فتخرج Node عندما تنتهي الـ callbacks، كما تصف صفحة About.

</details>

### تمرين متقدم

طلبان وصلَا معًا. الأول يستدعي `await` على قاعدة بيانات تأخذ 50ms. الثاني يحسب أعدادًا أولية على الخيط لمدة ثانيتين قبل أي `await`. صف أثر الثاني على الأول إذا بدأ الثاني أولًا، بجملتين.

<details>
<summary>الحل</summary>

الثاني يحتل خيط JavaScript ثانيتين، فالأول لا تبدأ دالته، أو لا تكمل، حتى يُعاد التحكم إلى الحلقة. `await` في الأول لا يعمل أثناء انشغال الخيط بالحساب. انتظار قاعدة البيانات لا يزاحم الخيط، أما الحساب المتصل فيفعل.

</details>

## أسئلة مراجعة

- ماذا تقدم Node ولا يقدمه المتصفح لكاتب Backend؟
- لماذا لا يسرّع `async` حلقة حساب طويلة؟
- ماذا يبقي عملية مثال `listen` حية؟
- أين يقع Express بالنسبة إلى `node:http` و NestJS؟

## الخلاصة

Node.js تشغّل JavaScript كخادم شبكي على حلقة أحداث. الإدخال والإخراج غير الحاجز يناسب كثيرًا من الطلبات. الحساب الطويل على الخيط يوقف الجميع. NestJS إطار فوق هذه البيئة، لا بيئة بديلة.

## ماذا بعد؟

نستطيع كتابة خادم بـ `node:http` فقط. الفرق التالي: هل نستدعي نحن المكتبة في كل خطوة، أم الإطار هو الذي يستدعي كودنا داخل هيكل جاهز؟ هذا فرق Library و Framework، وهو سبب وجود طبقات فوق Node.
