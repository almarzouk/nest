Singleton Lifecycle

الهدف من هذا الدرس

تتبع نسخة النطاق الافتراضي: تُنشأ مع حل الرسم، تُشارك بين الطلبات، وتُدمَّر مع التطبيق.

المشكلة التي يحلها

بعد فهم الخانة، يبقى سؤال التشغيل: هل DraftService تُبنى عند أول GET أم قبل listen؟ وهل طلبان متوازيان يحصلان على كائنين؟ الافتراضي في Nest نسخة واحدة لعمر التطبيق. سوء قراءة ذلك يضع memberId على الخدمة فيختلط الأعضاء، أو يدفع الفريق إلى REQUEST لكل صنف.

الفكرة ببساطة

توثيق Scope: عمر DEFAULT مربوط بالتطبيق. عند الإقلاع تُحل الاعتماديات فتُنشأ نسخ Singleton. عند الإيقاف تُدمَّر. المشاركة آمنة من جهة الخيوط لأن Node يعالج JavaScript على خيط واحد. الحقل القابل للتغيير ما زال حالة تطبيق يراها كل طلب.

التعريف التقني

Scope.DEFAULT هو الصمت في @Injectable() ومن غير خاصية scope على الوصفة. التصريح الصريح بالقيمة نفسها لا يغيّر العمر.

الحل أثناء NestFactory.create يملأ الخانات اللازمة قبل قبول الاتصالات. طلب لاحق يستدعي الدوال على المراجع نفسها. مقارنة === بين حقنين للرمز نفسه داخل الحاوية نفسها ناجحة.

الإيقاف مع إغلاق التطبيق يهدم المزوّدات. خطافات onModuleDestroy وأمثالها فصل Application Lifecycle لاحق. هنا يكفي أن العمر ينتهي مع العملية لا مع الطلب.

REQUEST و TRANSIENT استثناءان على هذا العمر، وشرحا في فصل Providers. هذا الدرس يثبت ماذا يعني الافتراضي عندما لا تكتب Scope.

Mental Model

create()
  حل الأوراق
  خزّن DraftService مرة
listen()
  طلبان -> الدوال نفسها على النسخة نفسها
إغلاق العملية
  نهاية النسخة

أبسط مثال

import { Injectable } from '@nestjs/common';

@Injectable()
export class SequenceService {
  private n = 0;

  next() {
    this.n += 1;
    return this.n;
  }
}

شرح المثال

  • n حقل على النسخة الوحيدة.
  • next من طلبين متتاليين يعيد 1 ثم 2.
  • إعادة تشغيل العملية تبدأ من 0 لأن النسخة الجديدة في حاوية جديدة.
  • هذا مرغوب لعدّاد عملية، وكارثي لمعرّف العضو الحالي.

ماذا يحدث داخليًا؟

الخيط الواحد يعني أن دالة JavaScript لا تُقاطع في منتصف تعبير متزامن. this.n += 1 المتزامن لا يتداخل مع نفسه. بين await يعود حلقة الأحداث إلى طلب آخر على النسخة نفسها. نمط «اقرأ n ثم await ثم اكتب» يسمح لطلب ثانٍ بتغيير n قبل الإكمال. التوثيق يصف المشاركة بأنها آمنة بمعنى غياب سباق الخيوط، لا بمعنى أن كل سلسلة await معزولة. حالة الطلب تبقى في وسائط الدالة أو في Scope REQUEST عندما تكون هوية الطلب جزءًا من الكائن.

اختباران يستدعيان NestFactory.create مرتين يحصلان على عدّادين. اختبار يستعلم الخدمة مرتين من التطبيق نفسه يرى التزايد.

الحاوية لا تنسخ الخدمة لكل Controller. DraftsController و ReportsService يأخذان المرجع المخزن إن كان الرمز واحدًا ومرئيًا في سياقيهما عبر التصدير.

مثال عملي

مسودة تتذكر آخر صافي حُسب، وهذا تسريب حالة:

import { Injectable } from '@nestjs/common';
import { TaxPolicy } from './tax.policy.js';

@Injectable()
export class DraftService {
  private lastNet = 0;

  constructor(private readonly tax: TaxPolicy) {}

  total(net: number) {
    this.lastNet = net;
    return { gross: net * (1 + this.tax.rate()), lastNet: this.lastNet };
  }
}

طلب يحسب 100 ثم طلب يحسب 40 يجعل قراءة lastNet في تركيب لاحق ترى 40 حتى لو كان القارئ يتوقع 100. أعد { gross } من غير تخزين net على الحقل. إن لزم آخر حساب لكل عضو، المفتاح عضو لا حقل واحد على Singleton.

أخطاء شائعة

الخطأ الأثر
حفظ هوية الطلب على حقل الخدمة الطلب التالي يقرأ هوية السابق
افتراض نسخة لكل GET العدّاد والذاكرة المؤقتة مشتركان
await ثم كتابة حقل مشترك من غير انتباه طلب آخر يمر على النسخة بين الجزأين
REQUEST لكل الخدمات هربًا من القاعدة تكلفة حل لكل طلب على السلسلة كلها

متى نستخدمه؟

للخدمات التي بلا حالة، أو التي حالتها حالة عملية: مجمع، عميل HTTP بمجمّع وصلات، جدول أسعار محمّل عند الإقلاع. هذا هو النطاق الذي يوصي به التوثيق.

متى لا نستخدمه؟

لحالة يجب أن تموت مع الاستجابة. مرّر القيم إلى الدالة، أو ارفع ذلك الصنف فقط إلى REQUEST مع معرفة أن من يحقنه يصعد معه. لا تضع حالة الزائر على Singleton ثم تمسحها في نهاية المعالج؛ أي فشل في الوسط يترك القيمة للطلب التالي.

مقارنة

اللحظة نسخة DEFAULT
قبل create غير موجودة
بعد الحل في الإقلاع واحدة في الخانة
كل طلب الدوال على تلك النسخة
await داخل الدالة طلب آخر قد يمر على الحقول
إغلاق التطبيق نهاية العمر
create جديد في اختبار نسخة أخرى في حاوية أخرى

تمارين

تمرين سهل

متى تُنشأ SequenceService الافتراضية؟

الحل

أثناء حل الرسم في الإقلاع، لا عند أول استدعاء next بعد أن يصبح الخادم جاهزًا.

تمرين متوسط

لماذا this.n += 1 المتزامن لا يمنح الرقم نفسه لطلبين، بينما نمط القراءة ثم await ثم الكتابة قد يختل؟

الحل

JavaScript على خيط واحد لا يقطع التعبير المتزامن. await يعيد التحكم لحلقة الأحداث، فيكمل طلب آخر على النسخة نفسها قبل أن يعود الأول إلى الكتابة.

تمرين متقدم

كيف ترى اختبارين العدّاد يبدأ من 0 بينما استدعاءان داخل create واحد يتزايدان؟

الحل

كل NestFactory.create حاوية ونسخها. داخل الحاوية الواحدة الخانة تُحل مرة، فالاستدعاء الثاني يرى n بعد الأول. الاختبار الثاني يبني عملية منطقية جديدة.

أسئلة مراجعة

  • بماذا يرتبط عمر Singleton؟
  • ماذا تعني سلامة المشاركة في توثيق Node؟
  • أين تضع قيمة تخص طلبًا واحدًا؟

الخلاصة

Singleton يُحل مع الإقلاع، ويُشارك مرجعه بين الطلبات، وينتهي مع التطبيق. الخيط الواحد يمنع سباق الخيوط، والحقول المتغيرة تبقى حالة عملية، وawait يفتح بابًا لتداخل الطلبات على تلك الحالة.
