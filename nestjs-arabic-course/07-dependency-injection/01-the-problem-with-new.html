مشكلة new

الهدف من هذا الدرس

رؤية ما الذي ينكسر عندما ينشئ الصنف اعتمادياته بـ new بدل أن يطلبها جاهزة.

المشكلة التي يحلها

DraftService التي تنادي new RegionalTax(new SystemClock()) تخفي الشبكة داخل الدالة. اختبار مسودة بلا ضريبة المنطقة يعدّل الخدمة أو ينتظر ساعة الجهاز. Controller ثانٍ يعيد new فيحصل على ضريبة مستقلة عن الأولى.

الفكرة ببساطة

new قرار إنشاء في مكان الاستخدام. كل استدعاء يختار الصنف والوسائط والترتيب. استبدال RegionalTax في الاختبار يعني تحرير كل المواضع، لا موضع تسجيل واحد.

التعريف التقني

سلسلة نموذجية لمكتب المشتريات:

const clock = new SystemClock();
const tax = new RegionalTax(clock);
const vendors = new VendorGateway('https://vendors.internal');
const drafts = new DraftService(tax, vendors);

الترتيب إلزامي لأن كل سطر يحتاج ناتج ما قبله. عنوان البوابة مكتوب حيث تُبنى المسودة، لا حيث تُدار الإعدادات. DraftService إن أعادت البناء داخل open() تتكرر السلسلة عند كل فاتورة.

نسخة لكل Controller تعني أن عدّادًا على RegionalTax لا يمثل المكتب كله. نسخة واحدة يدوية في متغير عام تُصلح العدّاد وتفتح اعتمادًا خفيًا: أي ملف يستدعي getTax() يصير مرتبطًا بالمتغير من غير أن يظهر في توقيعه.

Mental Model

Controller
  new DraftService
      new RegionalTax
          new SystemClock
      new VendorGateway

الشجرة صحيحة الشكل وصعبة الاستبدال. كل عقدة تعرف أصناف أبنائها.

أبسط مثال

export class SystemClock {
  now() {
    return new Date();
  }
}

export class RegionalTax {
  constructor(private readonly clock: SystemClock) {}

  rate() {
    return this.clock.now().getMonth() === 11 ? 0.05 : 0.15;
  }
}

export class DraftService {
  private readonly tax = new RegionalTax(new SystemClock());

  total(net: number) {
    return net * (1 + this.tax.rate());
  }
}

شرح المثال

  • DraftService تعرف RegionalTax و SystemClock بالاسم.
  • اختبار total في ديسمبر يختلف عن اختباره في يونيو لأن الساعة ساعة الجهاز.
  • تمرير شهر ثابت مستحيل من غير تعديل rate أو كسر الحقل الخاص.
  • Controller الذي ينشئ DraftService لا يرى أن النتيجة تعتمد على الشهر.

ماذا يحدث داخليًا؟

كل new يحجز كائنًا ويسند حقوله. لا سجل يبحث عن رمز، ولا مشاركة إلا ما تخزنه أنت في متغير. عند طلبين متوازيين، نسختان من DraftService تعنيان ساعتين. هذا واضح في المثال، ويصبح خفيًا عندما يكون new داخل دالة عميقة.

الاستبدال للاختبار يتطلب أحد ثلاثة: تغيير الأصناف، أو متغيرًا عامًا يضبطه الاختبار، أو إعادة كتابة total لتقبل الضريبة وسيطًا في كل نداء. الوسيط في كل نداء ينفع دالة واحدة، ولا يصف شبكة مكتب فيها بوابة وضريبة وساعة.

مثال عملي

مسار يعيد البناء:

import { Controller, Get, Query } from '@nestjs/common';
import { DraftService } from './draft.service.js';

@Controller('drafts')
export class DraftsController {
  @Get('preview')
  preview(@Query('net') net = '100') {
    const drafts = new DraftService();
    return { gross: drafts.total(Number(net)) };
  }
}

preview تبدو رفيعة، والاعتماد على ديسمبر داخل DraftService. اختبار HTTP يحتاج تثبيت التاريخ أو يقبل نتيجة متغيرة. عنوان VendorGateway لو أُضيف داخل open يتكرر القرار نفسه في كل مسار ينادي new DraftService().

أخطاء شائعة

الخطأ الأثر
new داخل الدالة لكل طلب لا مشاركة مقصودة، ولا مكان واحد لاستبدال الاختبار
متغير عام tax يستدعيه أي ملف الاعتمادية غائبة عن توقيع الصنف
تمرير كل الاعتماديات وسائط على كل دالة التوقيع يطول، والشبكة تبقى قرار المستدعي
نسخ سلسلة new في Controller ثانٍ عدّادات وحالات تتفرع

متى نستخدمه؟

new مناسب لكائن قيمة يصنعه المجال ولا تديره الحاوية: new Date() داخل ساعة، أو DTO تملأه من جسم الطلب. تلك ليست خدمات المكتب.

متى لا نستخدمه؟

لإنشاء Service أو بوابة أو سياسة يعيش مستهلكوها داخل Nest. التسجيل في providers وطلب النوع في constructor ينقلان قرار الإنشاء إلى موضع واحد. آلية ذلك الفصل كله بعد هذا الدرس.

مقارنة

new عند الاستخدام طلب الاعتمادية جاهزة
الصنف يسمي أبناءه الصنف يسمي ما يحتاجه
الاستبدال بتعديل المواضع الاستبدال في التسجيل

تمارين

تمرين سهل

لماذا يختلف total(100) بين يونيو وديسمبر في المثال؟

الحل

RegionalTax تقرأ شهر SystemClock المبنية داخل الخدمة، وهي ساعة الجهاز. ديسمبر يعطي 0.05 وغيره 0.15.

تمرين متوسط

ما الذي يخفيه preview عندما تنشئ DraftService رغم أن الدالة سطران؟

الحل

سلسلة RegionalTax و SystemClock داخل الخدمة، وأي بوابة تُضاف هناك لاحقًا. توقيع preview لا يذكرها.

تمرين متقدم

لماذا المتغير العام getTax() يحل مشاركة النسخة ويبقي الاختبار صعبًا؟

الحل

النسخة واحدة، لكن أي صنف يستدعي الدالة يعتمد عليها من غير معامل. الاختبار يضبط حالة عامة ويخشى أن يراها اختبار آخر. التوقيع ما زال لا يعلن الاحتياج.

أسئلة مراجعة

  • ماذا يختار new في مكان الاستخدام؟
  • لماذا نسخة Controller لكل مسار تفرق الحالة؟
  • أي new يبقى مقبولًا لكائن قيمة؟

الخلاصة

new داخل الخدمة يثبّت الأصناف والوسائط والترتيب عند الاستخدام. الشبكة تعمل، واستبدال فرع واحد للاختبار أو لمكتب آخر يعني تعديل كل موضع بناء.
