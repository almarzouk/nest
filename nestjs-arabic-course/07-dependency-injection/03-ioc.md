# IoC

## الهدف من هذا الدرس

تعريف Inversion of Control: الإطار يملك مسار التحكم وينادي كودك، و DI إحدى تقنيات هذا القلب.

## المشكلة التي يحلها

بعد إخراج `new` من الخدمة، ما زال ملف `main` يدويًا يستطيع بناء الشجرة كلها ثم مناداة `drafts.total`. في Nest لا تكتب هذه الشجرة عند كل تشغيل. `NestFactory.create` يقرأ Module الجذر وينشئ الكائنات وينادي المعالج عندما يصل طلب. التحكم في «متى يُبنى الكائن» و«متى تُستدعى الدالة» انتقل إلى الإطار.

## الفكرة ببساطة

IoC تعني أن كود التطبيق لا يقود الحلقة الرئيسة. هو يقدّم أصنافًا، والإطار يقرر الترتيب ويناديها. DI تقنية IoC خاصة بالاعتماديات: الحاوية تنشئها وتمررها. نداء Nest لمعالج `@Get` عند وصول الطلب IoC أيضًا، على محور الطلب لا على محور البناء.

## التعريف التقني

توثيق Custom providers يسمي DI تقنية IoC تفوّض إنشاء الاعتماديات إلى حاوية NestJS بدل الأسلوب الأمري في كودك.

الحاوية هنا وقت التشغيل. أنت تصف Module و Decorators. `NestFactory.create(AppModule)` نقطة الدخول التي تملكها Nest. بعدها `app.listen` ينتظر الشبكة، وعند الطلب تختار الخريطة دالة Controller. الدالة ليست من تنادي `listen`.

عبارة Hollywood تلخص الاتجاه: الإطار ينادي كودك. كودك يعلن الاحتياج في المُنشئ ثم ينتظر التسليم.

IoC ليس اسم حاوية ولا اسم `@Injectable`. الحاوية أداة. `@Injectable` Metadata. IoC هو اتجاه التحكم.

## Mental Model

```text
من غير IoC
  main يبني الكائنات
  main ينادي total عند الحاجة
  main يقرأ المنفذ

مع Nest
  NestFactory.create يقرأ الجذر
  الحاوية تبني من التسجيل
  listen ينتظر
  الإطار ينادي المعالج
```

## أبسط مثال

```ts
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module.js';

const app = await NestFactory.create(AppModule);
await app.listen(3000);
```

```ts
import { Controller, Get } from '@nestjs/common';
import { DraftService } from './draft.service.js';

@Controller('drafts')
export class DraftsController {
  constructor(private readonly drafts: DraftService) {}

  @Get('preview')
  preview() {
    return { gross: this.drafts.total(100) };
  }
}
```

## شرح المثال

- `main` لا ينشئ `DraftService` ولا `DraftsController`.
- `create` يستلم الجذر. ما يُبنى يقرره `imports` و `providers` و `controllers`.
- عند `GET /drafts/preview` الإطار ينادي `preview`. أنت لا تسجل `app.get` يدويًا في هذا الملف.
- المُنشئ طلب الخدمة. هذا الجزء DI، والنداء على `preview` جزء التحكم بالطلب.

## ماذا يحدث داخليًا؟

الإقلاع يمشي من `AppModule` إلى الوحدات المستوردة، يسجل الوصفات، يحل Singleton من الأوراق نحو الجذر، ثم يربط المسارات. هذا قبل أي طلب. الطلب لا يبني تلك النسخ مرة أخرى ضمن النطاق الافتراضي؛ هو يدخل المعالج الجاهز.

لو بقي التحكم عندك، كل طلب كان سيمر على سطر التركيب الذي كتبته، أو كنت ستخزن النسخة في متغير تغلق عليه بنفسك. الإطار يجعل هذا التخزين داخل الحاوية.

خلط الاسمين شائع: الناس تقول IoC وهي تقصد `@Injectable`. الزينة بلا `NestFactory` وبدون تسجيل لا تقلب التحكم. ملف يشغّل `new DraftsController(new DraftService(...))` ما زال أمريًا حتى لو نسخت شكل المُنشئ من Nest.

## مثال عملي

إقلاع يفشل قبل `listen` إن نقص رمز، لأن الحاوية تحل الرسم أثناء `create`. هذا أثر IoC: خطأ التركيب يظهر عند بدء العملية لا عند أول زائر يصل إلى `preview`. طلب لاحق ينادي دالة على كائنات سُلّمت أصلًا.

مهمة مجدولة أو رسالة طابور، لاحقًا في الدورة، تتبع النمط نفسه: الإطار ينادي دالة مزوّد جاهز. بناء المزوّد لا ينتقل إلى معالج الرسالة.

## أخطاء شائعة

| الخطأ | الأثر |
| --- | --- |
| تسمية `@Injectable` باسم IoC | الزينة Metadata والتحكم عند `create` والحاوية |
| `new DraftsController(...)` داخل أمر تشغيلي بجانب Nest | مساران للبناء، وأحدهما خارج السجل |
| توقع أن DI تغطي نداء المسار فقط | DI للتسليم، ونداء `@Get` محور تحكم آخر |
| بناء الخدمات داخل `preview` | الطلب عاد يقود الإنشاء |

## متى نستخدمه؟

عندما تريد أن يبقى تشغيل التطبيق ونداء المسارات وتسليم الاعتماديات عند Nest. هذا هو نموذج التطبيق الذي يبدأ بـ `NestFactory.create`.

## متى لا نستخدمه؟

في سكربت من عشرين سطرًا يبني صنفًا واحدًا وينهي. `new` هناك أوضح من حاوية. عندما تكبر الاعتماديات أو يظهر HTTP، نقل التحكم إلى الإطار يعيد الشكل الذي تبنيه هذه الدورة.

## مقارنة

| المحور | من ينادي |
| --- | --- |
| DI | الحاوية تنشئ الاعتمادية وتمررها للمُنشئ |
| مسار HTTP | الإطار ينادي المعالج بعد المطابقة |
| سكربت أمري | `main` ينشئ وينادي |
| Metadata | لا تنادي أحدًا؛ تصف ما يقرأه الإطار |

## أسئلة مراجعة

- ماذا يملك الإطار في IoC بدل ملفك؟
- كيف يصف التوثيق علاقة DI بـ IoC؟
- لماذا `@Injectable` وحدها لا تقلب التحكم؟

## الخلاصة

IoC نقل قرار التشغيل والنداء إلى Nest. DI التقنية التي تفوّض إنشاء الاعتماديات إلى الحاوية. نداء المعالج عند الطلب الوجه الآخر للتحكم، على محور مختلف.

## ماذا بعد؟

الاعتماد على تجريد لا على صنف تفصيلي: Dependency Inversion.
