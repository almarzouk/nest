Hexagonal Architecture

الهدف من هذا الدرس

تسمية الحافة منافذًا ومحولات: منفذ دخول يقود التطبيق، ومنفذ خروج يتحدث إلى قاعدة أو بريد، مع إبقاء Nest موصّل المحولات لا قلب السياسة.

المشكلة التي يحلها

Clean والشكل السداسي يصفان القلق نفسه من جهتين. السداسي (Alistair Cockburn) يبرز أن التطبيق في الوسط يمكن قيادته من أكثر من محول دخول: HTTP اليوم، رسالة غدًا، واختبار دائمًا. إن بقي المدخل الوحيد متحكمًا يعرف الخدمة وتعرف الخدمة Prisma، فالمحول الثاني سينسخ القواعد. المنفذ يثبت عقد القيادة وعقد الخروج.

الفكرة ببساطة

الوسط تطبيق لا يستورد Express ولا Prisma. محول أولي (primary) يستدعي منفذ دخول: المتحكم ينادي PlaceOrder.execute. محول ثانوي (secondary) يطبّق منفذ خروج: PrismaOrders يطبّق OrdersPort. الاختبار محول أولي أيضًا ينادي execute مباشرة. Nest يربط المحول الثانوي بـ useClass على رمز المنفذ.

التعريف التقني

منفذ دخول غالبًا دالة تطبيق واحدة واضحة، لا واجهة لكل المتحكم. منفذ خروج واجهة صغيرة: save و find بما تحتاجه الحالة لا كل عمليات الجدول.

export interface OrdersPort {
  nextId(): string;
  save(order: { id: string; totalMinor: number }): Promise<void>;
}

export const ORDERS = Symbol('ORDERS');

محول أولي:

@Controller('orders')
export class OrdersController {
  constructor(private readonly placeOrder: PlaceOrder) {}

  @Post()
  create(@Body() dto: CreateOrderDto) {
    return this.placeOrder.execute(dto);
  }
}

محول ثانوي في ملف يعرف Prisma ويُربَط { provide: ORDERS, useClass: PrismaOrdersAdapter }.

لا طبقة سداسية مولَّدة من Nest. إن تطابق هذا مع Clean عندك فأنت لا تحتاج الاسمين في مجلدين. اختر تسمية الفريق: منافذ ومحولات أو دوائر. المعنى: الوسط أعمى عن الحافة.

فرق عملي عن «الخدمة تحقن Prisma»: استبدال المحول الثانوي في الاختبار لا يحتاج خادم HTTP، واستبدال المحول الأولي لا يحتاج إعادة كتابة execute.

Mental Model

[ HTTP Controller ] ---> PlaceOrder.execute ---> OrdersPort
[ Test ]             /                      \--- PrismaOrdersAdapter
[ Queue handler ] ---

الثلاثة محولات أولية. Prisma محول ثانوي واحد حتى يظهر مخزن ثانٍ.

أبسط مثال

PlaceOrder يحقن ORDERS، يرفض مجموعًا سالبًا، ثم save. اختبار:

const orders: OrdersPort = {
  nextId: () => 'o1',
  save: async () => undefined,
};
const place = new PlaceOrder(orders);
await place.execute({ totalMinor: 100 });

new هنا مقبول لأن الحالة لا تبحث في الحاوية عن شيء آخر. داخل التطبيق الكامل الربط في الوحدة.

شرح المثال

الاختبار محول أولي بلا Nest. هذا ربح الشكل السداسي الذي يبرر الواجهة. إن كان الاختبار الوحيد هو supertest على المسار، فالمنفذ لم يُشترَ بعد. أضف المنفذ عندما تريد هذا الاختبار السريع أو محول دخول ثانٍ.

ماذا يحدث داخليًا؟

  1. طلب HTTP يدخل المحول الأولي.
  2. execute يشغّل السياسة.
  3. النداء على OrdersPort يضرب المحول الثانوي الذي سجلته الحاوية.
  4. لا يعرف الوسط اسم الجدول.
  5. معالج طابور يستدعي execute نفسه فيصبح محولًا أوليًا ثانيًا.
  6. محول ثانوي بديل في الاختبار يخزن في مصفوفة.

مثال عملي

بريد بعد إتمام الطلب منفذ خروج ثانٍ MailPort ومحول SMTP. PlaceOrder ينادي mail.send بعد save إن كانت السياسة «أرسل فور الحفظ» داخل الحالة. إن كان الإرسال أثرًا جانبيًا يمكن تأخيره، فحدث بعد الحفظ يبقي الحالة أقصر، وذلك حد لاحق. لا تحقن عميل SMTP في PlaceOrder بالاسم.

أخطاء شائعة

  • منفذ خروج يعيد أنواع Prisma.
  • محول أولي فيه خصم السعر.
  • منفذ بكل دوال الجدول «احتياطًا».
  • مجلدان hexagonal/in و hexagonal/out بلا سياسة داخلية.
  • محول ثانوي يستدعي محولًا أوليًا فيصنع دورة.

متى نستخدمه؟

أكثر من طريقة لقيادة الحالة نفسها، أو اختبار سياسة بلا HTTP ولا قاعدة.

متى لا نستخدمه؟

مسار واحد واختبار HTTP يكفي. أبقِ خدمة الوحدة النمطية حتى يظهر المحول الثاني.

مقارنة

الاسم في السداسي في Nest
محول أولي Controller، معالج رسالة، اختبار
منفذ دخول execute على خدمة تطبيق
منفذ خروج واجهة + Symbol
محول ثانوي صنف Prisma أو SMTP في useClass

تمارين

تمرين سهل

ما المحول الأولي في POST /orders؟

الحل

OrdersController. الوسط هو PlaceOrder.

تمرين متوسط

لماذا الاختبار الذي ينادي execute محول أولي؟

الحل

لأنه يقود التطبيق من الخارج عبر منفذ الدخول، مثل HTTP، بلا أن تعرفه السياسة بالاسم.

تمرين متقدم

متى تضيف MailPort بدل استيراد عميل البريد في الحالة؟

الحل

عندما تريد تشغيل execute في اختبار بلا شبكة، أو استبدال SMTP لاحقًا. إن كان الإرسال سطرًا واحدًا مؤقتًا داخل محول الخروج مع الحفظ، يمكن تأجيل المنفذ الثاني حتى يتكرر.

أسئلة مراجعة

  • ما الفرق بين منفذ الدخول ومنفذ الخروج؟
  • أين يُربط useClass؟
  • متى الاسم السداسي لا يبرر ملفاتًا جديدة؟

الخلاصة

الشكل السداسي وسط أعمى ومحولات على الحافة. Nest يوصل محول الخروج بالرمز. أضف المنافذ عندما يوجد محول ثانٍ أو اختبار يريد الوسط وحده.

ماذا بعد؟

أساسيات DDD: لغة مشتركة، كيان، وحدود سياق تساوي تقريبًا حدود الوحدة.
