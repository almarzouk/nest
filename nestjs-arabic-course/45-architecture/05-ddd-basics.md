# أساسيات DDD

## الهدف من هذا الدرس

التقاط مفردات Domain-Driven Design التي تغيّر حدود وحدة Nest: اللغة المشتركة، الكيان والقيمة، الجذر التجميعي، والسياق المحدود، بلا بناء نموذج تكتيكي كامل.

## المشكلة التي يحلها

وحدة `ShopModule` فيها كتاب وفاتورة وشحنة لأن الجداول في قاعدة واحدة. التغيير على الضريبة يكسر صفحة الكتالوج. DDD يطلب أن تتبع الحدود لغة الفريق لا مخطط القاعدة. السياق المحدود مكان تتفق فيه كلمة «طلب» على معنى واحد. في Nest هذا المرشح الأقوى ليكون `Module`.

## الفكرة ببساطة

اللغة المشتركة ألفاظ يستعملها المنتج والكود معًا: `place` لا `insertOrder`. الكيان له هوية تستمر (`Order` بالمعرف) حتى لو تغيّر المجموع. كائن القيمة يُعرَّف بحقوله (`Money` بالمبلغ والعملة) ويمكن استبداله. الجذر التجميعي البوابة التي تعدّل ما بداخلها: تعدّل سطور الطلب عبر `Order` لا عبر حفظ سطر وحده من ميزة أخرى. السياق المحدود حد تتوقف عنده هذه المعاني. خارجه كلمة «حساب» قد تعني مستخدمًا لا فاتورة.

## التعريف التقني

لا حزمة رسمية في Nest لهذه المفردات. التطبيق:

- سياق الكتالوج `CatalogModule` وكيان `Book` بمعرف.
- سياق الفوترة `BillingModule` لا يستورد كيان الكتاب كاملًا. يحتفظ `bookId` ونسخة سعر إن لزم الاتفاق عند الحافة.
- `Money` صنف أو كائن `{ minor: number; currency: 'SAR' }` بلا معرف. المساواة بالحقول.
- الجذر `Order` فيه `addLine` الذي يرفض سطرًا بلا كمية. الحفظ عبر منفذ يحفظ الجذر، لا `prisma.orderLine.create` من المتحكم.

بين السياقات: معرف ونسخة بيانات، أو حدث «تم الدفع»، لا مشاركة جدول مع كتابة من الطرفين. مشاركة قاعدة واحدة ممكنة في monolith نمطي، والجداول يمكن أن تُقسَّم لاحقًا إن صارت الحدود صحيحة أولًا.

التوثيق التكتيكي الأوسع (مصانع، مستودعات غنية، أحداث مجال) يتقاطع مع فصلي المستودع و CQRS. هنا لا تبنِهما لكل سياق.

## Mental Model

```text
سياق الكتالوج: Book كيان، Money قيمة
سياق الفوترة: Invoice جذر، يعرف bookId لا كائن Book الحي
العبور: معرف أو حدث، لا استيراد الكيان وتعديله
```

## أبسط مثال

```ts
export class Money {
  constructor(
    readonly minor: number,
    readonly currency: 'SAR',
  ) {
    if (minor < 0) {
      throw new Error('مبلغ سالب');
    }
  }
}
```

```ts
export class Order {
  private readonly lines: { bookId: string; unit: Money }[] = [];

  addLine(bookId: string, unit: Money): void {
    this.lines.push({ bookId, unit });
  }
}
```

`Order` لا يستورد Prisma. `BillingModule` يحفظه عبر منفذ. الكتالوج يبني `Money` عند عرض السعر ولا يعدّل `Order`.

## شرح المثال

القاعدة «لا مبلغ سالب» في `Money` تعيش مع القيمة أينما استُعملت داخل السياق. إن نسخت الفحص في كل خدمة ضاع عند مسار جديد. `addLine` بوابة التجميع. دفع سطر إلى `prisma` من `CatalogService` يكسر الجذر لأن الكتالوج ليس مالك الطلب.

## ماذا يحدث داخليًا؟

1. اللغة في أسماء الدوال تطابق كلام الفريق.
2. الهوية (`id`) تميز الطلب عبر الحفظ.
3. `Money` جديد عند كل تغيير بدل تعديل حقول مشتركة من سياقين.
4. المنفذ في السياق المالك يحفظ الجذر.
5. السياق الآخر يخزن معرفًا. قراءة التفاصيل نداء على واجهة الكتالوج أو نسخة أُخذت عند الشراء.
6. حدث بين السياقات يمنع الاستيراد المتبادل الذي رأيته في الدورات.

## مثال عملي

كلمة «إلغاء»: في الشحن تعني إرجاع طرد، وفي الفوترة تعني إشعار دائن. سياقان ووحدتان. دالة `cancel()` عامة في `ShopService` تخلط المعنيين. سمِّ `cancelShipment` و `voidInvoice` في وحدتين، واترك منسقًا يستدعيهما بالترتيب إن كانت عملية المتجر تحتاج الاثنين.

## أخطاء شائعة

- كيان لكل جدول بما فيها `UserPreference` بلا قواعد.
- مشاركة كائن `Book` الحي وتعديله من الفوترة.
- سياق واحد اسمه Domain فيه كل شيء.
- قيمة `Money` لها `id` من الجدول فتنقلب كيانًا مرتبكًا.
- بدء Event Sourcing قبل أن تستقيم الحدود.

## متى نستخدمه؟

عندما تتعدد معاني الكلمة الواحدة أو يوجد جذر يجب أن يحمي لامتغيرات. ابدأ بتقسيم الوحدات حسب اللغة.

## متى لا نستخدمه؟

تطبيق فيه سياق واحد واضح. وحدة نمطية وطبقات تكفي. لا ورشات نمذجة قبل أول مسار يعمل.

## مقارنة

| المفهوم | في المتجر | في Nest |
| --- | --- | --- |
| سياق محدود | كتالوج غير فوترة | `Module` وتصدير ضيق |
| كيان | طلب له معرف | صنف بلا Prisma |
| قيمة | مبلغ وعملة | كائن بلا هوية |
| جذر | الطلب لا السطر اليتيم | دوال التعديل على الجذر |

## أسئلة مراجعة

- ماذا يقابل السياق المحدود غالبًا في Nest؟
- ماذا يعبر بين السياقات؟
- لماذا الجذر يمنع حفظ السطر من الخارج؟

## الخلاصة

DDD هنا لغة وحدود: كيان وهوية، قيمة بلا هوية، جذر يحمي الداخل، وسياق يطابق وحدة. لا تبنِ كل الأنماط التكتيكية قبل أن تستقيم هذه الأربعة.

## ماذا بعد؟

ما لا تستورده إلى مشروع صغير: قائمة ما تؤجله حتى يظهر الألم.
