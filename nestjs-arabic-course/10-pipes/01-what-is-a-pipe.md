# ما هو Pipe

## الهدف من هذا الدرس

تعريف الأنبوب: صنف يطبّق `PipeTransform` ويعمل على معامل المعالج قبل استدعائه.

## المشكلة التي يحلها

المسار يصل والمعامل ما زال نصًا من عنوان URL، أو جسمًا بلا فحص. وضع `parseInt` داخل كل دالة يكرر القاعدة ويجعل الخدمة ترى قيمًا لم تُراجع.

## الفكرة ببساطة

الأنبوب دالة `transform(value, metadata)`. القيمة التي يرجعها تحل محل المعامل. إن رمى، المعالج لا يُستدعى.

## التعريف التقني

الصنف `@Injectable()` ويطبّق `PipeTransform`. التوقيع:

```ts
transform(value: T, metadata: ArgumentMetadata): R | Promise<R>;
```

`value` هو المعامل الحالي. `metadata` يصف من أين أتى. الحقول التي تهم هذا الدرس: `type` تكون `body` أو `query` أو `param` أو `custom`، و `metatype` نوع TypeScript المنعكس، و `data` النص الممرَّر إلى الزينة مثل `'id'` في `@Param('id')`. حقل `schema` يخص مخططات الفصل 12.

الأنبوب يعمل داخل منطقة الاستثناءات. الاستثناء يصل إلى الفلاتر المرتبطة بالسياق الحالي، عالميًا وعلى المتحكم وعلى المسار. هذا يختلف عن استثناء Middleware الذي تراه الفلاتر العامة فقط.

موضعه في الدورة، بعد Interceptors التي تسبق المعالج، وقبل جسم المتحكم: أنابيب عامة، ثم أنابيب المتحكم، ثم أنابيب المسار، ثم أنابيب المعاملات. تفصيل الربط درس في آخر هذا الفصل.

## Mental Model

```text
المعامل الخام  →  transform  →  المعامل الذي يراه المتحكم
                     ↘ رمي استثناء → المعالج لا يعمل
```

الأنبوب لا يرى الطلب كله كموضوع له. موضوعه قيمة واحدة ذاهبة إلى معامل واحد، أو كل المعاملات إذا رُبط على المسار. الظرف العام بقي في Middleware.

## أبسط مثال

```ts
import {
  type ArgumentMetadata,
  Injectable,
  type PipeTransform,
} from '@nestjs/common';

@Injectable()
export class PassThroughPipe implements PipeTransform {
  transform(value: unknown, metadata: ArgumentMetadata): unknown {
    void metadata;
    return value;
  }
}
```

```ts
@Get(':code')
findOne(@Param('code', PassThroughPipe) code: string): string {
  return code;
}
```

تمرير الصنف لا النسخة يترك البناء للإطار ويسمح بالحقن. النسخة `new PassThroughPipe()` تصلح حين لا تحتاج الحاوية.

## شرح المثال

- `transform` ترجع القيمة كما هي. هذا أنبوب هوية لرؤية العقد.
- `metadata` متاح حتى لو تجاهلته. الأنابيب المفيدة تقرأ `type` أو `data`.
- الربط هنا على معامل `@Param`. المعالج يستلم ما رجعه الأنبوب.
- لا `next()`. هذا ليس Middleware.

## ماذا يحدث داخليًا؟

1. بعد الحراس و Interceptors السابقة، يجمع Nest معاملات الدالة.
2. يشغّل الأنابيب المرتبطة بهذا المعامل.
3. ناتج `transform` يصبح قيمة المعامل.
4. إن اكتملت الأنابيب، تُستدعى الدالة.
5. إن رمى أنبوب، تتوقف الدورة عند الاستثناء وتذهب إلى الفلتر المناسب للسياق. الخدمة لا تُستدعى.

`try/catch` داخل المتحكم لا يرى هذا الرمي، لأن الرمي حدث قبل الدخول إلى الدالة.

الأنبوب يستطيع أن يكون `async`. الإطار ينتظر الوعد. الوعد المرفوض يُعامل كاستثناء.

## مثال عملي

`GET /invoices/18` يصل والمعامل نص. أنبوب لاحق يحوّله إلى عدد. في هذا الدرس الأنبوب يعيد النص حتى ترى أن الربط وحده لا يغيّر النوع. الدالة `findOne` تطبع `typeof code` وتجد `string`. التحويل قرار تكتبه داخل `transform`، وهو موضوع الدرس التالي، لا أثر جانبي للربط.

## أخطاء شائعة

- انتظار أن الأنبوب يعمل قبل الحارس. الدورة تضعه بعد Interceptor السابق للحارس.
- إرجاع `undefined` سهوًا فيضيع المعامل.
- وضع ختم ترويسة داخل `transform`. الأنبوب لا يُستدعى على مسار بلا معامل مرتبط به بهذه الطريقة، ومكان الترويسة Middleware.
- اعتبار أن `metadata.metatype` حاضر للواجهات. الواجهة تُمسح، و `metatype` للأصناف والقيم المنعكسة.

## متى نستخدمه؟

حين تكون القاعدة عن قيمة داخلة إلى المعالج: تحويل أو رفض، قبل أول سطر في المتحكم.

## متى لا نستخدمه؟

لكتابة ترويسة على كل طلب، أو للسماح حسب دور الدالة، أو لتغليف JSON الراجع. تلك الطبقات السابقة واللاحقة في الدورة.

## مقارنة

| | Middleware | Pipe |
| --- | --- | --- |
| المدخل | `req`, `res`, `next` | `value`, `metadata` |
| المخرج | `next()` أو إنهاء الرد | قيمة أو استثناء |
| متى | قبل الحارس | قبل جسم المتحكم وبعد Interceptor السابق |

## تمارين

### تمرين سهل

ماذا يصبح معامل المتحكم إن رجعت `transform` العدد `18` بينما الأصل نص `"18"`؟

<summary>الحل</summary>

العدد `18`. القيمة المرجعة تستبدل القيمة السابقة للمعامل.

</details>

### تمرين متوسط

أنبوب رمى `BadRequestException`. هل تعمل `InvoicesService`؟ وأي منطقة تلتقط الخطأ؟

<details>
<summary>الحل</summary>

الخدمة لا تُستدعى. الاستثناء داخل منطقة الاستثناءات، فتراه فلاتر المسار ثم المتحكم ثم العام، لا الفلاتر العامة وحدها كما في Middleware.

</details>

### تمرين متقدم

لماذا لا يكفي `try/catch` في أول سطر من `findOne` لالتقاط فشل الأنبوب؟

<details>
<summary>الحل</summary>

الأنبوب يعمل قبل استدعاء الدالة. الرمي لا يدخل جسم المتحكم، فالـ `catch` لا يرى شيئًا. التقاط الشكل للعميل عمل الفلتر.

</details>

## أسئلة مراجعة

- ما الواجهة التي يطبّقها الأنبوب؟
- ما الحقول الأساسية في `ArgumentMetadata`؟
- أين يقع الأنبوب بالنسبة إلى المتحكم؟
- ماذا يحدث للمعالج حين يرمي `transform`؟

## الخلاصة

Pipe صنف `transform` على قيمة المعامل قبل الدالة. الإرجاع يستبدل القيمة، والرمي يمنع الاستدعاء ويذهب إلى فلاتر السياق. الظرف العام ليس عمله.

## ماذا بعد؟

الدرس التالي يفرّق الوظيفتين: تحويل القيمة، أو التحقق منها وتمريرها أو رمي استثناء.
