# قاعدة البيانات قبل أي ORM

## الهدف من هذا الدرس

رؤية الاتصال والجدول والاستعلام قبل أي مكتبة تخفي SQL، حتى لا يصبح Prisma أو TypeORM سحرًا.

## المشكلة التي يحلها

مصفوفة `books` داخل الخدمة تموت مع العملية، ولا يراها تطبيق ثانٍ، ولا تنجو من إعادة التشغيل. وضع جملة SQL داخل دالة المسار يخلط HTTP بشكل الصف، ويصعّب اختبار القاعدة من غير طلب.

## الفكرة ببساطة

قاعدة البيانات عملية أخرى تحتفظ بالجداول. التطبيق يفتح اتصالًا، يرسل SQL بمعاملات مربوطة، ويقرأ صفوفًا. Nest لا يختار القاعدة. توثيق البيانات يقول إن الربط في أدناه هو تحميل مشغّل Node المناسب وكشفه كمزوّد.

## التعريف التقني

PostgreSQL قاعدة علائقية. الجدول مجموعة صفوف بأعمدة معروفة. المفتاح الأساسي يميّز الصف. الاستعلام نص SQL. المعاملات المربوطة، مثل `$1` في مشغّل `pg`، تفصل النص عن القيمة حتى لا يُبنى الاستعلام بلصق مدخل المستخدم.

عميل رفيع:

```ts
import { Injectable, OnModuleDestroy } from "@nestjs/common";
import { Pool } from "pg";

@Injectable()
export class LibraryPool implements OnModuleDestroy {
  readonly pool = new Pool({ connectionString: process.env.DATABASE_URL });

  async onModuleDestroy() {
    await this.pool.end();
  }
}
```

هذا ليس ORM. لا نماذج، لا ترحيل، لا كائن `book`. الصف مصفوفة حقول أو كائن بأسماء الأعمدة كما رجعت من SQL. الدروس التالية تسمي PostgreSQL ثم تشرح ماذا يضيف ORM، ثم تغلف Prisma.

لا تقرأ `process.env` هنا في المشروع النهائي. بعد فصل الإعداد، العنوان يأتي من `ConfigService.getOrThrow("DATABASE_URL")`.

## Mental Model

```text
Controller -> BooksService -> LibraryPool.query(sql, params) -> PostgreSQL
                                      |
                                 صفوف خام
```

الخدمة تترجم الصف إلى شكل المكتبة. المتحكم لا يرى `Pool`.

## أبسط مثال

```ts
import { Injectable } from "@nestjs/common";
import { Pool } from "pg";

@Injectable()
export class BooksReader {
  constructor(private readonly pool: Pool) {}

  async findTitle(id: number): Promise<string | null> {
    const result = await this.pool.query(
      "select title from books where id = $1",
      [id],
    );
    const row = result.rows[0] as { title: string } | undefined;
    return row?.title ?? null;
  }
}
```

## شرح المثال

`$1` موضع القيمة، و `[id]` القيمة. المشغّل يرسلهما منفصلين. عنوان الكتاب الذي يحتوي `'` لا يكسر الجملة. إن لم يوجد صف، `rows` فارغة والنتيجة `null`، فيحوّلها المتحكم لاحقًا إلى `404`.

`Pool` مجموعة اتصالات تُعاد، لا اتصال جديد لكل استعلام إن ضبطتها كمزوّد واحد.

## ماذا يحدث داخليًا؟

`query` ينتظر الشبكة. Node لا يحجز الخيط الرئيسي أثناء انتظار PostgreSQL. النتيجة تصل كحدث ثم تكمل الدالة. إن سقطت القاعدة، الوعد يُرفض ويصل إلى مرشح الاستثناءات إن لم تمسكه الخدمة.

المخطط نفسه غير موجود في هذا الكود. شخص أنشأ الجدول بأداة أو بسطر `CREATE TABLE`. من غير أثر محفوظ لذلك الأمر، بيئة الزميل لا تعرف الأعمدة. هذا النقص هو سبب الترحيل لاحقًا.

## مثال عملي

جدول `books` فيه `id` و `title`. مسار `GET /books/3` يستدعي `BooksReader` لا `pool.query` داخل المتحكم. اختبار الخدمة يمرّر `Pool` مزيفًا يرجع صفًا واحدًا، من غير PostgreSQL. اختبار آخر يشغّل قاعدة حقيقية ويثبت أن `$1` يعيد عنوان الكتاب `3` فقط.

انسخ الجملة إلى المتحكم وستحتاج في كل اختبار إلى HTTP وقاعدة معًا.

## أخطاء شائعة

- لصق `id` داخل نص SQL.
- فتح `new Pool()` داخل كل دالة مسار.
- إرجاع `result.rows` خامًا إلى العميل وفيه أعمدة لم يقصدها العقد.
- اعتبار المصفوفة في الذاكرة بديلًا دائمًا بعد أول تجربة ناجحة.

## متى نستخدمه؟

لفهم الطبقة التي يجلس فوقها أي ORM، ولأداة إدارة تكتب SQL صريحًا بمعرفة.

## متى لا نستخدمه؟

كمسار بناء كل موارد المكتبة يدويًا إن كان الفريق سيعتمد Prisma. الدرس يبني الحدس، والفصل يكمل على عميل مولَّد.

## مقارنة

| مصفوفة في الخدمة | `pg` و SQL |
| --- | --- |
| تموت مع العملية | تبقى بعد إعادة التشغيل |
| بلا مخطط مشترك | جدول بأعمدة |
| بلا معاملات | `$1` يفصل القيمة |

## تمارين

### تمرين سهل

أين تعيش جملة `select` في المثال، وأين لا تعيش؟

<details>
<summary>الحل</summary>

في `BooksReader`. المتحكم يستدعي `findTitle` ولا يفتح `Pool`.

</details>

### تمرين متوسط

لماذا `[id]` وليس دمج `id` في نص الجملة؟

<details>
<summary>الحل</summary>

الموضع `$1` معامل مربوط. القيمة لا تصبح جزءًا من نص الأمر، فلا تغيّر معنى الاستعلام.

</details>

### تمرين متقدم

زميل أنشأ الجدول من شاشة رسومية. لماذا تفشل نسختك من التطبيق على قاعدة فارغة رغم أن الكود نفسه يعمل عنده؟

<details>
<summary>الحل</summary>

أثر `CREATE TABLE` ليس في المستودع. الترحيل لاحقًا يحفظ SQL الذي يبني الجدول حتى يُعاد على أي بيئة.

</details>

## أسئلة مراجعة

- ماذا يضيع عند إيقاف العملية إن كانت الكتب في مصفوفة؟
- ما دور `$1`؟
- لماذا لا يُستدعى `pool.query` من المتحكم؟

## الخلاصة

قبل ORM هناك اتصال واستعلام وصف. الخدمة تملك SQL، والمخطط ما زال بلا أثر محفوظ. PostgreSQL هو محرك الدورة لهذا الجدول.
