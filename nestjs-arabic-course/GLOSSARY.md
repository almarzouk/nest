# قاموس المصطلحات

شرح قصير بالعربية. المصطلح الإنجليزي يبقى كما في التوثيق. كل بند يشير إلى أول فصل يعمّقه. القاموس يكبر مع المادة.

## من المقدمة

### Backend

الجزء الخادمي الذي يملك القواعد والبيانات المشتركة ويرد على الطلبات. المقدمة: `00-introduction`.

### Frontend

الجزء الذي يعرض ويجمع المدخلات. ليس مكان القرار النهائي على السعر أو الصلاحية.

### Client

الطرف الذي يبدأ الطلب في هذه المحادثة. قد يكون متصفحًا أو اختبارًا أو خادمًا آخر.

### Server

الطرف الذي يستمع ويقبل الطلب ويكتب الاستجابة.

### Request

رسالة العميل: Method و URL و Headers وجسم اختياري.

### Response

رسالة الخادم: Status و Headers وجسم اختياري.

### HTTP

بروتوكول الطلب والاستجابة الذي تتحدث به واجهات هذه الدورة. Stateless: كل طلب يحمل ما يلزم لفهمه.

### Method

فعل HTTP. الأكثر استخدامًا هنا: `GET` و `POST` و `PUT` و `PATCH` و `DELETE`.

### Status code

عدد يصف قرار الخادم. `2xx` نجاح، `4xx` مشكلة في الطلب، `5xx` فشل الخادم.

### URL

عنوان المورد: scheme و host و port و path و query.

### Header

زوج اسم وقيمة يحمل سياق الرسالة، مثل `Content-Type` و `Authorization`.

### Body

حمولة الرسالة بعد الرؤوس. في الـ API عندنا غالبًا JSON.

### JSON

صيغة نصية للبيانات بين العمليتين. النحو أضيق من كائن JavaScript. `JSON.parse` لا يفرض معنى الحقول.

### REST

أسلوب تصميم يسمي الموارد في المسار ويستخدم أفعال HTTP بمعناها. التمثيل الشائع JSON. ليس بروتوكولًا، وليس مرادفًا لأي JSON على HTTP.

### Resource

شيء نسميه ونخاطبه بعنوان، مثل كتاب أو قائمة كتب.

### Representation

نسخة وصفية تُنقل عبر الشبكة. تختلف عن الكائن داخل ذاكرة الخادم وعن صف الجدول.

### API

عقد ظاهر لاستخدام برنامج من غير فتح داخله. في هذه الدورة غالبًا Web API على الشبكة.

### REST API

API على HTTP بأسلوب REST.

### Idempotent

تكرار الطلب المكافئ يترك الخادم في الحالة التي يتركها تنفيذ واحد. وصف شائع لـ `GET` و `PUT` و `DELETE`. `POST` الإنشاء ليس كذلك بالضرورة.

### Node.js

بيئة تشغيل JavaScript خارج المتصفح، غير متزامنة ومقادة بالأحداث، و HTTP فيها من أساسيات المكتبة. NestJS تعمل فوقها.

### Event loop

حلقة في Node تنتظر الشبكة والملفات والمؤقتات وتشغّل JavaScript على خيط رئيسي. حساب طويل على هذا الخيط يؤخر الطلبات الأخرى.

### Library

أداة تناديها أنت. مثال: `JSON.parse`.

### Framework

هيكل ينادي كودك في نقاط حددها. Express إطار توجيه رقيق. NestJS إطار ذو رأي معماري فوق Express أو Fastify.

### Inversion of Control

قلب التحكم: الإطار يملك ترتيب التشغيل أو إنشاء الكائنات، وأنت تملأ النقاط. المعنى الأوسع في المقدمة، والمعنى الخاص بالإنشاء في فصل Dependency Injection.

### Express

إطار HTTP خفيف على Node. المنصة الافتراضية لـ Nest عبر `@nestjs/platform-express`. `req` و `res` هما كائنا Node مع إضافات Express.

### Middleware

في Express: دالة `(req, res, next)` في مكدس الطلب. `next()` يمرر التحكم. في Nest: دالة تُستدعى قبل route handler، وهي أول محطة في Request Lifecycle بعد دخول الطلب. الفصل `09`.

### Fastify

منصة HTTP بديلة أسرع في وصف توثيق Nest، وتُركب بمحوّل. ليست الافتراضية.

### HTTP Adapter

قطعة Nest تترجم تسجيل المسارات والـ middleware إلى نداءات Express أو Fastify.

### Platform-agnostic

تصميم Nest بحيث تُعاد استخدام القطع المنطقية عبر HTTP و WebSockets و Microservices، ما دامت القطعة لا تلتصق بكائنات منصة واحدة.

### NestJS

إطار Node.js لبناء تطبيقات خادم قابلة للاختبار والنمو، قليلة الارتباط، وقابلة للصيانة. المعمارية مستوحاة من Angular. الإصدار الذي كُتبت عليه هذه المادة: 12، حسب التوثيق في 5 أكتوبر 2026.

### Module

صنف معلّم بـ `@Module()` ينظم المتحكمات والمزوّدات وما يُستورد وما يُصدَّر. يغلّف مزوّداته افتراضيًا. الفصل `04`.

### Root Module

الوحدة التي تُمرَّر إلى `NestFactory.create`، ومنها يبدأ application graph. في القالب: `AppModule`.

### Application graph

التركيب الداخلي لعلاقات الوحدات والمزوّدات الذي تبنيه Nest عند الإقلاع.

### Controller

صنف يستقبل HTTP ويعيد الرد. يقابل `app.get` في Express، ولا يُفترض أن يملك Business Logic. الفصل `05`.

### Provider

أي شيء تسجّله الحاوية ليُحقن. الفصل `06`.

### Service

مزوّد نضع فيه Business Logic. كل Service مزوّد، وليس كل مزوّد خدمة بالمعنى الضيق.

### Dependency Injection

تمرير الاعتماديات من الخارج، عادة عبر constructor، بدل `new` داخل الدالة. الفصل `07`.

### IoC container

الحاوية التي تنشئ المزوّدات المسجّلة وتحقنها.

### Decorator

دالة خاصة تعلّم صنفًا أو دالة وتلصق Metadata. أمثلة الأسماء: `@Module` و `@Controller` و `@Get` و `@Injectable`. الآلية في الفصل `01`، والاستخدام في كل فصل لاحق.

### Metadata

بيانات وصفية يلصقها الـ Decorator ويقرأها Nest عند الإقلاع عبر `reflect-metadata`.

### Request lifecycle

ترتيب معالجة الطلب في التوثيق: Middleware، ثم Guards، ثم Interceptors، ثم Pipes، ثم Controller، ثم Service، ثم Interceptors في العودة، ثم Exception Filters عند الاستثناء. الفصل `08`.

### Guard

محطة تقرر هل يُكمل الطلب. مكان Authentication و Authorization على البوابة. الفصل `13`.

### Interceptor

يلتف حول تنفيذ المعالج قبلًا وبعدًا، ويعمل مع `Observable`. الفصل `14`.

### Pipe

يحوّل مدخل المسار أو يرفضه قبل الدالة. الفصل `10`.

### Exception Filter

يلتقط استثناءً غير ممسوك ويحوله إلى رد. الاختيار من الأخص إلى الأعم. الفصل `15`.

### DTO

كائن يصف شكل البيانات على حدود التطبيق. الفصل `11`.

### Singleton

نسخة واحدة من المزوّد طوال عمر التطبيق. هذا السلوك الافتراضي لمزوّدات Nest، واسمه في التوثيق scope من نوع DEFAULT. الفصل `40`.

### Business Logic

قواعد العمل: ما الذي يجوز شراؤه، وبأي سعر، ومن يملك المراجعة. بيتها Service لا شكل HTTP.

### Coupling

ارتباط قطعة بتفاصيل قطعة أخرى. المعالج الذي يعرف أعمدة SQL ورؤوس HTTP معًا شديد الارتباط. Nest تدفع القواعد نحو خدمات وحدود وحدات.

## من بقية المسار

### ValidationPipe

أنبوب يفحص أصناف DTO وقت التشغيل. الخيارات المهمة: `whitelist` و `forbidNonWhitelisted` و `transform`.

### StandardSchemaValidationPipe

أنبوب Nest 12 لفحص مخططات متوافقة مع Standard Schema مثل Zod، ويمكن أن يعمل مع `ValidationPipe` معًا.

### Guard / CanActivate

بوابة قبل الأنبوب ترجع هل يكمل الطلب. مكان الهوية والإذن على حافة المسار.

### Interceptor / Observable

يلف التنفيذ. `next.handle()` ترجع `Observable`. ما قبل الاستدعاء يجري قبل المتحكم، وما داخل `pipe` بعده.

### Exception Filter

يلتقط الاستثناء غير الممسوك. الاختيار من المسار إلى المتحكم إلى العام.

### DTO

صنف عقد على حدود HTTP. الواجهة لا تكفي لـ `ValidationPipe`.

### JWT

إثبات موقع يحمله العميل. ليس بديلًا عن تجزئة كلمة المرور، ولا يُخزَّن فيه سر قابل للقراءة الحساسة.

### RBAC

تفويض بالأدوار. السياسة أدق عندما يهم مالك السجل.

### Prisma

عميل بيانات مولَّد من مخطط، مع ترحيل. مسار الدورة التطبيقي. TypeORM و Drizzle موثّقان أيضًا.

### BullMQ

طابور مهام على Redis. الحزمة `@nestjs/bullmq`. Bull موثّق وفي وضع الصيانة.

### Idempotency

تنفيذ مكرر للنفس الطلب لا يضاعف الأثر. لازم على الدفع والويب هوك.

### Tenant

زبون تُعزل بياناته. في النموذج المشترك كل استعلام يحمل معرفه القادم من هوية موثوقة.
