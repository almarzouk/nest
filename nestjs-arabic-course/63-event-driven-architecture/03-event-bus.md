# Event Bus

## الهدف من هذا الدرس

تمييز ناقل يمرر الأحداث داخل عملية رف عن ناقل يصل بين عمليات، واختيار الوسيط حسب ما يجب أن يعيش بعد سقوط العملية.

## المشكلة التي يحلها

الفريق يسمي `EventEmitter2` ناقلًا موزعًا. عند إعادة التشغيل تختفي أحداث النشر التي لم يخدمها المستمع. أو يضعون Kafka لحدث تدقيق داخل نفس العملية فيتعقد التشغيل بلا حاجة.

## الفكرة ببساطة

ناقل داخل العملية يسلّم في الذاكرة: سريع ويضيع مع العملية. ناقل بين العمليات (طابور، Redis، وسيط Nest) يسلّم رسائل تكامل ويتحمل إعادة المحاولة. الاختيار يتبع سؤالًا: هل ضياع الرسالة بعد النجاح التجاري مقبول؟

## التعريف التقني

`@nestjs/event-emitter` ناقل داخل العملية: `emit` و `@OnEvent`. لا مخزن. ناقل التكامل في Nest قد يكون نقلًا في microservices (`ClientProxy.emit`) أو طابور BullMQ كما في الحدود السابقة. الرسالة على الناقل الخارجي حدث تكامل لا صنف نطاق. المستهلك يعالج بمعرّف. لا تشغّلوا الأثر التجاري فقط على الناقل من غير كتابة الحالة أولًا، وإلا ضاعت الحقيقة إن ضاعت الرسالة. صندوق الصادر لاحقًا يقرب الكتابة من الإرسال.

## Mental Model

```text
ذاكرة: EventEmitter → مستمع محلي → قد يضيع عند القتل
وسيط: كتاب ملتزم → رسالة book.published → مستهلك بعيد
```

## أبسط مثال

```ts
import { OnEvent } from '@nestjs/event-emitter';
import { Injectable } from '@nestjs/common';

@Injectable()
export class LocalAuditListener {
  @OnEvent('book.published')
  handle(event: { organizationId: string; bookId: string }) {
    return event.bookId;
  }
}
```

## شرح المثال

- هذا ناقل ذاكرة. مناسب لتدقيق تريدونه في نفس العملية بعد `emit`.
- لا عنوان شريك هنا.
- إن رمى `handle` قد يصل الاستثناء إلى الناشر حسب طريقة الإطلاق. التقطوا داخل المستمع إن كان جانبيًا.

## ماذا يحدث داخليًا؟

1. `emit` يستدعي المستمعين المسجّلين في هذه العملية.
2. لا كتابة إلى قرص الوسيط.
3. `ClientProxy.emit` أو `queue.add` يسلّم نسخة إلى وسيط خارج الذاكرة.
4. المستهلك البعيد يقرأ حدث التكامل.
5. إعادة تشغيل API تمسح مستمعي الخطوة 1 غير المنفَّذين، ولا تمسح رسالة وسيط متين إن التزمت هناك.

## مثال عملي

```ts
export interface Bus {
  local(name: string, payload: unknown): void;
  integration(name: string, payload: { id: string }): Promise<void>;
}
```

`local` غلاف `EventEmitter`. `integration` غلاف الطابور. `PublishCoordinator` يستدعي `local` للتدقيق الفوري و `integration` لنسخة `toIntegration`. الاختبار يستبدل الواجهة. لا تمرروا نفس الدالة إلى الاثنين بالخطأ.

## أخطاء شائعة

- تسمية EventEmitter «Kafka داخلي».
- أثر وحيد (خصم مخزون الشريك) على الناقل الذاكري.
- مستهلك بعيد يستورد `BookPublished` من مسار `src` الخاص بالكتالوج.
- ناقل خارجي بلا معرّف تكرار.

## متى نستخدمه؟

الذاكرة للمستمعين الذين إن فشلوا تُعاد من حالة الصف (أو يُقبل ضياعهم). الوسيط لما يجب أن يعبر عملية.

## متى لا نستخدمه؟

لا تضيفوا وسيطًا قبل أن يوجد مستهلك خارج العملية. ابدأوا بالدالة ثم بالذاكرة ثم بالوسيط عندما يظهر الحد.

## مقارنة

| | EventEmitter | طابور / ناقل خارجي |
| --- | --- | --- |
| البقاء بعد القتل | لا | نعم إن كان الوسيط متينًا |
| العقد | صنف داخلي | حدث تكامل |
| التشغيل | بلا بنية إضافية | وسيط تشغّلونه |

## تمارين

### تمرين سهل

أُعيد تشغيل API قبل أن يعمل مستمع الذاكرة. هل يصل `book.published`؟

<details>
<summary>الحل</summary>

لا. لم يُخزَّن. إن كان الأثر واجب الوصول، فالنشر يكتب الحالة والمستمع يُعاد من الصفوف أو الرسالة على وسيط.

</details>

### تمرين متوسط

لماذا واجهتان `local` و `integration` أفضل من `emit` واحدة؟

<details>
<summary>الحل</summary>

حتى لا يذهب حدث داخلي إلى الشريك أو يُرسل العقد العام في الذاكرة فقط. مكان الاستدعاء يعلن نوع التسليم.

</details>

### تمرين متقدم

التدقيق يجب ألا يضيع، والبريد يجوز أن يتأخر. أين كل منهما؟

<details>
<summary>الحل</summary>

التدقيق في معاملة النشر (صف) لا على أمل الناقل. البريد حدث أو مهمة على وسيط يعيد المحاولة. الذاكرة لا تكفي للاثنين إن كان الضياع ممنوعًا.

</details>

## أسئلة مراجعة

- ماذا يضيع مع عملية Node؟
- أي حمولة تركب على الوسيط الخارجي؟
- لماذا لا يكفي اسم «ناقل»؟
- أين يُكتب الأثر الذي لا يجوز أن يضيع؟

## الخلاصة

ناقل الذاكرة يبلّغ مستمعي هذه العملية. ناقل التكامل يبلّغ عبر وسيط برسالة عقد. ما لا يجوز ضياعه يُكتب في القاعدة أولًا لا يُعلَّق على الذاكرة.

## ماذا بعد؟

بعد الإرسال، الشريك أو الفهرس قد يتأخر عن حالة الكتاب. الدرس التالي الاتساق المؤجَّل.
