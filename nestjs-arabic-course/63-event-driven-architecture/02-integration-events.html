Integration Events

الهدف من هذا الدرس

تعريف الحدث الذي يعبر حد رف إلى نظام آخر، أو بين خدمتين تنشران منفصلتين، كعقد عام لا كصنف داخلي.

المشكلة التي يحلها

الفريق يصدّر BookPublished نفسه إلى HTTP الشريك. عندما أضيفتم حقلًا داخليًا انكسر الشريك. أو أرسلتم كيان Prisma فيه حقول لم يُعلَن عنها. إعادة المحاولة بلا اسم عقد تخلط «نُشر» مع «تغيّر السعر».

الفكرة ببساطة

حدث التكامل وثيقة: اسم ثابت book.published، إصدار، معرّف حدث، ومعرّفات عامة. يتغير بإصدار لا بإعادة هيكلة الصنف الداخلي. النقل ويب هوك أو طابور أو ناقل. حدث النطاق قد يُترجم إلى حدث تكامل بعد الالتزام، وليس كل حدث نطاق يُنشر خارجًا.

التعريف التقني

الحمولة JSON مستقرة: id, type, specversion إن اتبعتم أسلوبًا مثل CloudEvents أو حقولًا أصغر توثّقونها. لا أصناف TypeScript الخاصة بالمستودع. organizationId إن كان الشريك متعدد المكتبات عندكم؛ وإلا يكفي ما اتفقتم أنه مفتاحه. التوقيع والجسم الخام من فصل الويب هوك على النقل HTTP. المستهلك يطبق قيد المعرّف. إصدار الحمولة عندما يُحذف حقل أو يتغير معناه، لا عندما تضيفون مستمعًا داخليًا.

Mental Model

BookPublished (داخلي)
→ ترجمة
book.published v1 { id, bookId } (عقد)
→ ويب هوك أو ناقل

أبسط مثال

export interface BookPublishedV1 {
  id: string;
  type: 'book.published';
  specversion: '1';
  organizationId: string;
  bookId: string;
}

شرح المثال

  • type و specversion يثبّتان العقد.
  • id للتكرار عند المستهلك لا مفتاح جدول داخلي متغير.
  • الحقول أقل من صف Book.

ماذا يحدث داخليًا؟

  1. حدث النطاق يقع بعد الالتزام أو تُبنى رسالة التكامل في نفس المعاملة عبر صندوق لاحق.
  2. مترجم صريح ينسخ الحقول المعلنة فقط.
  3. النقل يرسل JSON.
  4. المستهلك يتحقق من type و specversion قبل الأثر.
  5. تغيير داخلي في اسم عمود Prisma لا يغيّر الواجهة إن بقي المترجم.

مثال عملي

export function toIntegration(event: { id: string; organizationId: string; bookId: string }): BookPublishedV1 {
  return {
    id: event.id,
    type: 'book.published',
    specversion: '1',
    organizationId: event.organizationId,
    bookId: event.bookId,
  };
}

لا تمرّروا BookPublished إلى JSON.stringify مباشرة إن كان الصنف سيكبر. الدالة هي الحد.

أخطاء شائعة

  • نشر كائن النطاق كما هو.
  • معرّف جديد كلما أُعيد الإرسال.
  • حقل status يتغير معناه في v1 بصمت.
  • اعتبار كل @OnEvent حدث تكامل لأنه «حدث».

متى نستخدمه؟

عندما يستهلك فريق أو نظام آخر الحقيقة، بما فيه عامل رف إن كان عملية منفصلة لا تشارك الذاكرة.

متى لا نستخدمه؟

لمستمع في نفس العملية يستطيع استيراد النوع الداخلي. ولا لكل console.log.

مقارنة

نطاق تكامل
الجمهور نموذجكم خارج الحد
الشكل صنف عقد مُصدَّر
التغيير حر داخل الاختبارات إصدار
النقل ذاكرة العملية غالبًا HTTP أو ناقل

تمارين

تمرين سهل

هل إضافة مستمع تدقيق داخلي ترفع specversion؟

الحل

لا. العقد الخارجي لم يتغير. الإصدار عندما تتغير حمولة الشريك.

تمرين متوسط

لماذا لا تُرسل أعمدة Prisma كلها؟

الحل

لأنها ليست عقدًا. عمود داخلي جديد سيصل إلى الشريك بلا قرار، وقد يتضمن بيانات لا تخصه.

تمرين متقدم

خدمتا رف منفصلتان: كتالوج وإشعارات. أي نوع حدث بينهما؟

الحل

تكامل، حتى لو كتبتموه أنتم، لأن الإشعارات عملية أخرى لا تشارك كائن BookPublished في الذاكرة. الناقل أو الطابور يحمل book.published v1.

أسئلة مراجعة

  • ما الذي يثبَّت في حدث التكامل؟
  • من يترجم حدث النطاق؟
  • لماذا المعرّف ثابت عبر الإعادة؟
  • متى لا يُنشر الحدث خارجًا؟

الخلاصة

حدث التكامل عقد مُصدَّر بمعرّف وإصدار وحقول عامة. حدث النطاق يبقى داخل النموذج. الترجمة دالة صريحة على الحد.

ماذا بعد؟

النقل داخل العملية أو بين العمليات يحتاج اسمًا للوسيط. الدرس التالي ناقل الأحداث.
