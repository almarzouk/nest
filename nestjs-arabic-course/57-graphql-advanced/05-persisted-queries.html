Persisted Queries

الهدف من هذا الدرس

قبول تنفيذ استعلام كتب في رف فقط إذا كان نصه مسجّلًا مسبقًا لدى الخادم، أو إذا جاء بمعرّف تعرفه، بدل فتح باب أي مستند تحت سقف التعقيد.

المشكلة التي يحلها

الحدود ترفض الأسوأ وما زال الباب مفتوحًا لنص جديد كل دقيقة: استكشاف الحقول، أو عميل يخزّن استعلامًا ثقيلًا تحت السقف بقليل. فريق الواجهة أصلًا يعرف الاستعلامات التي تبني الشاشات. الخادم يمكنه تنفيذ هذه القائمة وإغلاق الباقي.

الفكرة ببساطة

عند البناء، تُحسب بصمة لكل استعلام واجهة ويُحفظ النص على الخادم. في التشغيل يرسل العميل البصمة (وأحيانًا النص مرة أولى في النمط التلقائي). الخادم ينفّذ النص الذي يعرفه. النص المجهول يُرفض. هذه آلية Apollo ومنصات GraphQL، تُركَّب مع الخادم. ليست @PersistedQuery() من @nestjs/common.

التعريف التقني

نمطان شائعان. Automatic Persisted Queries: العميل يرسل SHA-256 للنص؛ إن لم يعرفه الخادم يطلب النص ثم يخزّنه. هذا يقلل حجم النقل ولا يغلق الباب، لأن أي عميل يستطيع التسجيل بإرسال النص. القائمة المغلقة (safelist) تناسب رف العام: الخادم يملك خريطة hash → document بُنيت من ملفات الواجهة، ويرفض التجزئة الغائبة. التوصيل يتم في إعداد Apollo (إضافة persisted queries أو مخزن تعرفه عملية Nest)، لا في Resolver الكتاب. DataLoader والتعقيد والعمق تبقى للحماية داخل الاستعلامات المسموحة إن بقيت القائمة واسعة.

Mental Model

بناء الواجهة → hash لاستعلام شاشة الكتب
تشغيل: { extensions: { persistedQuery: { sha256Hash } } }
الخادم يجد النص أو يعيد خطأ
لا نص حر في الإنتاج

أبسط مثال

import { createHash } from 'node:crypto';

export function queryId(document: string) {
  return createHash('sha256').update(document).digest('hex');
}

export const allowed = new Map<string, string>();

export function register(document: string) {
  allowed.set(queryId(document), document);
}

شرح المثال

  • المفتاح تجزئة النص الكامل بما فيه الفراغات التي ثبّتها المولّد. تغيير مسافة يغيّر المفتاح.
  • register يعمل وقت البناء أو الإقلاع من ملف ولّدته الواجهة، لا من طلب الإنتاج.
  • التنفيذ لاحقًا يبحث في allowed قبل execute.

ماذا يحدث داخليًا؟

  1. طلب الإنتاج يحمل التجزئة في امتداد Apollo المعتاد أو في حقل اتفقتم عليه.
  2. طبقة قبل الـ Resolver تبحث في الخريطة.
  3. الغياب: خطأ واضح ولا تنفيذ. لا تمرر النص الحر «مؤقتًا» في الإنتاج.
  4. الوجود: يُستبدل المعرّف بالنص المحفوظ ويُكمل التحقق (عمق، تعقيد) ثم الحل.
  5. النمط التلقائي الذي يخزّن أي نص عند أول مقابلة لا يحقق هذا الدرس. هو تحسين نقل.

مثال عملي

export function resolvePersisted(hash: string, documents: Map<string, string>) {
  const document = documents.get(hash);
  if (!document) {
    return { ok: false as const, error: 'Persisted query not found' };
  }
  return { ok: true as const, document };
}

اختبار: سجّل query Shelf { books { title } } وتوقع ok. أرسل تجزئة عشوائية وتوقع الرسالة. لا تضع هذه الدالة داخل @Query الكتب؛ هي بوابة الخادم. إن ربطتها بإضافة Apollo، الإضافة هي التي تستدعي المخزن الذي تملؤه register.

أخطاء شائعة

  • تفعيل APQ التلقائي وظن الباب أُغلق.
  • حساب التجزئة على خادم يختلف في المسافات عن مولّد الواجهة فتفشل الاستعلامات الشرعية.
  • نسيان أن المتغيرات (variables) تبقى حرة حتى داخل نص ثابت: limit ما زال يحتاج حدًا وتعقيدًا.
  • اعتبار القائمة المغلقة بديلًا عن صلاحيات الحقول. النص المسموح قد يطلب حقل مدير.

متى نستخدمه؟

واجهة أولى تبني استعلاماتها وقت البناء، وAPI عام لا تريد له مستندًا حرًا في الإنتاج.

متى لا نستخدمه؟

أثناء بناء المخطط محليًا حيث GraphiQL يحتاج نصًا حرًا. عطّل الإغلاق في التطوير. ولا كآلية تخزين مؤقت لنتيجة الكتب؛ هو تخزين لنص الاستعلام.

مقارنة

النمط أي نص يُنفَّذ
باب مفتوح + تعقيد أي مستند تحت السقف
APQ تلقائي أي نص بعد إرساله مرة
قائمة مغلقة ما سجّله البناء فقط

تمارين

تمرين سهل

ما الذي يرسله العميل في الإنتاج المغلق: النص أم التجزئة؟

الحل

التجزئة. النص يعيش في خريطة الخادم التي بناها إصدار الواجهة.

تمرين متوسط

لماذا المتغيرات تبقى خطرًا داخل استعلام محفوظ؟

الحل

النص الثابت قد يعلن books(limit: $n). العميل يضع n = 10000. احفظ الاستعلام وقيّد المتغير في التحقق والتعقيد.

تمرين متقدم

فرّق APQ التلقائي عن قائمة رف المغلقة في جملة تشغيل.

الحل

التلقائي يخزّن النص عندما يراه أول مرة فيقبل عميلًا جديدًا لم يمر بالبناء. المغلقة لا تكتب في الخريطة من الطلب، وترفض التجزئة الغائبة. الأول توفير بايتات، والثاني قيد تنفيذ.

أسئلة مراجعة

  • أين تُسجَّل الاستعلامات: من الطلب أم من البناء؟
  • لماذا اختلاف المسافات يكسر التجزئة؟
  • هل هذا ديكور في @nestjs/graphql؟
  • ماذا يبقى مطلوبًا للمتغيرات؟

الخلاصة

الاستعلامات المحفوظة في الإنتاج المغلق خريطة من تجزئة إلى نص ولّدها البناء. الطلب الحر لا يُنفَّذ. APQ التلقائي لا يغلق الباب. الآلية إضافة على Apollo لا ديكور Nest واحد.

ماذا بعد؟

مخطط رف ما زال في عملية واحدة. الدرس التالي يشرح Federation عندما يملك فريق آخر جزءًا من النوع نفسه.
