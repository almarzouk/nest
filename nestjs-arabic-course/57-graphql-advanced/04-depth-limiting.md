# Depth Limiting

## الهدف من هذا الدرس

منع استعلام رف الذي يغرق في سلسلة علاقات أطول مما يسمح به المخطط، بقاعدة تحقق على المستند، منفصلة عن حساب التعقيد.

## المشكلة التي يحلها

عميل، أو أداة تولّد استعلامات، يكتب `book { reviews { user { reviews { user { reviews { user } } } } } }`. كل مستوى رخيص في جدول التعقيد إن كانت التكلفة 1 والعدد صغيرًا، لكن العمق يضاعف العمل ويضغط المحلل. تريد رفض الشكل قبل الـ Resolver.

## الفكرة ببساطة

قس طول أطول سلسلة حقول في المستند. إن تجاوزت حدًا (مثل 5) ارفض المستند. هذا لا يقيس `limit` العريض. هو يقيس القعر فقط. لذلك يعيش بجانب التعقيد لا مكانه.

## التعريف التقني

`@nestjs/graphql` لا يقدّم `@Depth(5)` كجزء من الإطار. القاعدة الشائعة مكتبة تحقق مثل `graphql-depth-limit` تُمرَّر في `validationRules` عند إعداد `GraphQLModule.forRoot`. القواعد تعمل عند التحقق من المستند في Apollo. البديل كتابة `ValidationRule` تمشي على AST وتعد التداخل. كلاهما كود إضافة. لا تقل إن Nest «يشحن تحديد العمق» لأن صفحة Complexity موجودة؛ تلك الصفحة تكلفة لا عمق. Federation والحمولات المحفوظة أيضًا أدوات غير هذا الخيار.

## Mental Model

```text
query { books { author { name } } }     عمق صغير
query { books { author { books { author { books { title } } } } } }  يرفض عند الحد
```

## أبسط مثال

```ts
import { GraphQLDefinitionsFactory } from '@nestjs/graphql';
import depthLimit from 'graphql-depth-limit';

export const validationRules = [depthLimit(5)];
```

تمرير `validationRules` يتم في كائن إعداد GraphQL الذي يستخدمه تطبيقك (Apollo driver). الأسطر أعلاه تثبت نية الحد: 5 مستويات. راجع توقيع `forRoot` في إصدار الحزمة عند التوصيل حتى يبقى المفتاح في المكان الذي يقرأه المحول.

## شرح المثال

- الرقم 5 قرار منتج: أعمق مسار شرعي في رف (كتاب → مراجعة → مستخدم) زائد هامش، لا رقمًا من مقال.
- الاستعلام الشرعي يجب أن يمر في الاختبار قبل رفع الحد إلى الإنتاج.
- الحد يرفض المستند كله. لا يقص الحقول الزائدة بصمت.

## ماذا يحدث داخليًا؟

1. يصل نص الاستعلام.
2. Apollo يبني AST ويشغّل `validationRules` قبل التنفيذ.
3. قاعدة العمق تعد سلسلة الاختيار.
4. التجاوز يعيد خطأ GraphQL ولا يستدعي `BooksResolver`.
5. استعلام عريض وضحيل يمر من هنا وقد يوقفه حساب التعقيد. الاستعلام العميق الضيق يمر من تعقيد متساهل ويوقفه العمق.

## مثال عملي

اختبر الحد على سلسلة تعرفها:

```text
عمق مقبول: books → author → name
عمق مرفوض: books → author → books → author → books → author → name
```

اكتب الاختبارين معًا. إن رفض الأول، فالحد أضيق من المخطط الذي وثّقته للواجهة. إن قبل الثاني، فالقاعدة غير موصولة و `validationRules` لم تصل إلى الخادم الذي يشغّل الاختبار.

## أخطاء شائعة

- الاعتماد على التعقيد وحده بتكاليف 1 فيمر العمق.
- حد 2 يكسر الواجهة التي تطلب كتابًا ومؤلفًا ومراجعة في جولة مشروعة.
- حساب العمق بعد `await prisma` فلا يوفر الرحلة.
- توثيق أن «Nest يحد العمق افتراضيًا». الافتراضي بلا هذه القاعدة أن المحرك ينفذ ما يُطلب.

## متى نستخدمه؟

مخطط فيه علاقات يمكن المشي عليها في حلقة (كتاب ومؤلفه وكتبه). الحد يحمي من التولد الآلي للاستعلامات.

## متى لا نستخدمه؟

كمقياس وحيد للقائمة العريضة. وكمخطط داخلي لا يغادر خدمتك؛ هناك استعلامات محفوظة تغلق المجموعة أصلًا.

## مقارنة

| | Depth | Complexity |
| --- | --- | --- |
| يقيس | طول السلسلة | مجموع الأوزان |
| قائمة `limit: 500` ضحلة | قد تمر | تُرفض إن ضُرب الوزن |
| سلسلة طولها 12 بتكلفة 1 | تُرفض | قد تمر |
| من يشحنها | قاعدة تحقق تضيفها | صفحة Complexity عبر إضافة |

### تمرين سهل

هل `@Field({ complexity: 1 })` يحد العمق؟

### تمرين متوسط

أعمق استعلام في واجهة رف هو كتاب → مراجعات → مستخدم. أي حد يبدأ منطقيًا، وماذا تختبر؟

<details>
<summary>الحل</summary>

حد أعلى بقليل من 3، مثل 5، حتى لا يكسر الواجهة هامش fragment. اختبر نجاح المسار الشرعي وفشل سلسلة تعيد الدخول إلى `books` مرات إضافية.

</details>

### تمرين متقدم

استعلام عمقه 4 و `limit` 200 مرّ من depth limit وأسقط القاعدة. أي طبقة كانت ناقصة؟

<details>
<summary>الحل</summary>

التعقيد الذي يضرب تكلفة القائمة في `limit`، وحد `limit` في الوسائط. العمق عمل عمله ولم يَعِد بوزن العرض.

</details>

## أسئلة مراجعة

- لماذا العمق والتعقيد قاعدتان لا قاعدة واحدة؟
- هل الإطار يرفض العمق بلا مكتبة أو قاعدة تكتبها؟
- متى يُرفض المستند نسبة إلى الـ Resolver؟
- ماذا يحدث للواجهة إن كان الحد أضيق من أعمق شاشة مشروعة؟

## الخلاصة

تحديد العمق يرفض سلسلة حقول أطول من الحد عبر قاعدة تحقق تضيفها إلى GraphQL. Nest لا يختصره في ديكور جاهز، وصفحة التعقيد لا تغني عنه.

## ماذا بعد؟

حتى العمق والتعقيد يسمحان بأي نص تحت السقف. الدرس التالي يقصر التنفيذ على استعلامات عرفتها الواجهة مسبقًا.
