Single DB / Shared Schema

الهدف من هذا الدرس

عزل مكتبات رف بعمود tenantId داخل نفس الجداول ونفس القاعدة، وهو نموذج المسبح (pool): تكلفة تشغيل منخفضة وقيد إجباري على كل استعلام.

المشكلة التي يحلها

عشر مكتبات صغيرة لا تحتمل قاعدة لكل واحدة، وتريد ترحيل Prisma واحدًا. من غير عمود مشترك، إما تكررون الجداول يدويًا أو تخلطون الصفوف. من غير قيد في كل استعلام، العمود موجود والكشف ما زال يعيد كتب الجار.

الفكرة ببساطة

كل صف عمل يحمل tenantId. القائمة والفرد والتعديل والحذف تضيف where: { tenantId }. فهرس القائمة يبدأ بهذا العمود. العزل منطقي داخل المحرك لا في اتصال منفصل. خطأ واحد في استعلام يكفي لتسريب.

التعريف التقني

Pool يعني مخططًا مشتركًا وقاعدة مشتركة. Prisma model واحد لـ Book. لا search_path يتغير لكل طلب. العزل عقد استعلام: لا findMany بلا المستأجر، ولا findUnique({ where: { id } }) لأن المعرّف قد يُخمَّن عبر المكتبات إن كان تسلسليًا أو متسربًا. استخدموا findFirst({ where: { id, tenantId } }) أو مفتاحًا مركبًا. القيد الفريد الذي كان isbn يصبح @@unique([tenantId, isbn]). الكاش والمهام والطوابير تحمل المفتاح نفسه.

Mental Model

books
  id | tenantId | title
  b1 | lib_a    | موسم
  b2 | lib_b    | موسم
استعلام lib_a لا يرى b2

أبسط مثال

model Book {
  id       String @id
  tenantId String
  title    String
  isbn     String

  @@unique([tenantId, isbn])
  @@index([tenantId, status, publishedAt(sort: Desc)])
}

أضيفوا status و publishedAt إن كانت القائمة كما في درس الفهرس. الشكل هنا يثبت أن التفرد والفهرس يبدأان بالمستأجر.

شرح المثال

  • ISBN يتكرر بين مكتبتين ولا يتكرر داخل واحدة.
  • الفهرس الذي لا يبدأ بـ tenantId قد يخدم بحثًا عالميًا لا تريدهون.
  • الحذف deleteMany({ where: { id } }) بلا مستأجر خطر حتى لو أعاد صفًا واحدًا.

ماذا يحدث داخليًا؟

  1. السياق يعطي tenantId بعد العضوية.
  2. الخدمة تمرره وسيطًا صريحًا إلى دالة المستودع لا تقرأه من متغير عام غير مربوط بالطلب.
  3. Prisma يرسل WHERE tenantId = $1 AND id = $2.
  4. صفر صفوف يعني غيابًا داخل المكتبة (404) حتى لو وُجد المعرّف عند جار.
  5. اختبار يسجّل مكتبة ثانية ويتأكد أن الأولى لا تراها.

مثال عملي

import { Injectable } from '@nestjs/common';
import { PrismaService } from '../prisma/prisma.service.js';

@Injectable()
export class BooksService {
  constructor(private readonly prisma: PrismaService) {}

  list(tenantId: string) {
    return this.prisma.book.findMany({
      where: { tenantId, status: 'published' },
      take: 20,
      orderBy: { publishedAt: 'desc' },
    });
  }

  find(tenantId: string, id: string) {
    return this.prisma.book.findFirst({ where: { id, tenantId } });
  }
}

tenantId وسيط إجباري في التوقيع حتى لا تُستدعى الدالة «بلا مكتبة». من يملأ الوسيط حارس أو interceptor يقرأ السياق، لا حقل الجسم.

أخطاء شائعة

  • findUnique على id فقط.
  • update({ where: { id }, data }) يعدل كتاب جار إن تسرّب المعرّف.
  • تقرير إداري بلا مستأجر يُنسخ إلى مسار عام بالخطأ.
  • فهارس بلا tenantId ثم بطء يبدو كأنه خطأ Nest.

متى نستخدمه؟

عدد مكتبات كبير وخطة متشابهة، وفريق يستطيع فرض مراجعة «كل استعلام مقيّد». هذا الافتراضي المعتاد لرف في البداية.

متى لا نستخدمه؟

عندما يفرض عميل كبير قاعدة مستقلة أو منع مشاركة القرص مع غيره. ذلك silo. وعندما تحتاجون عزل صلاحيات SQL على مستوى schema لا عمود تطبيقي فقط.

تمارين

تمرين سهل

لماذا @@unique([isbn]) يكسر مكتبتين تستخدمان نفس الرقم؟

الحل

لأن القيد عالمي على الجدول المشترك. الصحيح @@unique([tenantId, isbn]) حتى يتكرر الرقم بين المستأجرين لا داخل أحدهم.

تمرين متوسط

findUnique({ where: { id } }) أعاد كتاب مكتبة أخرى. ما التعديل وما الرمز للعميل الذي لا يملك الصف؟

الحل

findFirst({ where: { id, tenantId } }). إن لم يُوجد الصف داخل المستأجر فالنتيجة غياب 404 حتى لو كان id موجودًا في جدول الجار. لا تعيدوا الصف.

تمرين متقدم

اكتب شرط مراجعة PR يمنع الدمج.

الحل

أي prisma.book.* في مسار طلب بلا tenantId في where يُرفض، إلا دالة تقرير منصة تعيش في وحدة إدارة منفصلة ولا تُستورد من BooksController. اختبار تكامل ينشئ مستأجرين ويتوقع قائمة فارغة للثاني.

أسئلة مراجعة

  • أين يعيش العزل في نموذج pool؟
  • لماذا المفتاح الفريد مركب؟
  • ما خطر where: { id } وحده؟
  • متى لا يكفي هذا النموذج؟

الخلاصة

المخطط المشترك يعزل بـ tenantId على كل صف وكل استعلام وكل قيد تفرد يخص الكتالوج. التكلفة تشغيلية منخفضة وثمن الخطأ تسريب عرضي من استعلام ناقص.

ماذا بعد؟

بعض المكتبات تريد فصلًا أقوى داخل نفس خادم Postgres: schema باسمها. الدرس التالي هذا النموذج.
