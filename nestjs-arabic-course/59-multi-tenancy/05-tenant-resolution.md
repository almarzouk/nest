# Tenant Resolution

## الهدف من هذا الدرس

تحديد مكتبة الطلب في رف من المضيف أو من ترويسة تثقون بها أو من مطالبة داخل رمز موقّع، ثم رفض `tenantId` الآتي في الجسم.

## المشكلة التي يحلها

ثلاثة عملاء يصلون بطرق مختلفة: نطاق `lib-a.raf.example`، وتطبيق جوال يرسل ترويسة، ورمز دخول فيه `tenant_id` لأن الشخص اختار المكتبة عند الإصدار. مسار رابع يقبل `{ "tenantId": "lib-b" }` في JSON فيقرأ الموظف كتالوج جاره.

## الفكرة ببساطة

الحل استخراج لا ثقة عمياء. المضيف يُعيَّن إلى مستأجر في جدول تملكونه. الترويسة تُقبل فقط من بوابة أضافت القيمة بعد ما عرفت المستأجر، أو تُعاد مطابقتها على العضوية. مطالبة الرمز تُقرأ بعد التحقق من التوقيع. ثم `assertMembership`. الجسم لا يدخل هذه السلسلة.

## التعريف التقني

مصادر مقبولة: اسم المضيف (`Host`) مثل `lib-a.raf.example` يُطابق سجل المستأجرين. ترويسة مثل `X-Tenant-Id` إن كانت قناة تتحكمون في من يكتبها (تطبيقكم بعد اختيار المكتبة) وما زالت العضوية تُفحص على الخادم. مطالبة `tenant_id` داخل access token الذي أصدرتموه عند اختيار المكتبة، وتُراجع في `validate`. مصادر مرفوضة: أي حقل جسم أو استعلام يحدده المهاجم ليتجاوز المضيف أو الرمز. إن تعارضت المصادر، ارفضوا الطلب بدل اختيار «الأول». غيّروا الرمز عند تبديل المكتبة حتى لا تبقى مطالبة قديمة.

## Mental Model

```text
Host أو ترويسة تطبيقكم أو مطالبة موقعة
        → tenantId
        → عضوية المستخدم
        → سياق الطلب
الجسم لا يشارك
```

## أبسط مثال

```ts
export function tenantFromHost(host: string | undefined, domain: string) {
  if (!host) return null;
  const name = host.split(':')[0];
  if (!name.endsWith(`.${domain}`)) return null;
  const slug = name.slice(0, -(domain.length + 1));
  if (!/^[a-z0-9-]+$/.test(slug)) return null;
  return slug;
}
```

## شرح المثال

- المنفذ يُقص قبل المطابقة.
- `evil.com` لا ينتهي بـ `.raf.example` بالشكل الذي تتوقعون؛ اختبروا `lib-a.raf.example.evil.net`.
- الناتج slug يُحوَّل إلى `tenantId` عبر جدول، لا يُستخدم كعنوان قاعدة مباشرة.

## ماذا يحدث داخليًا؟

1. الحارس يقرأ المصدر المتفق عليه لقناة API هذه.
2. يجد المستأجر في السجل. الغياب 404 لمضيف مجهول أو 403 لترويسة بلا عضوية، حسب العقد المكتوب.
3. يفحص العضوية للمستخدم المصدق.
4. يضع `tenantId` في سياق الطلب (مخزن أو مطالبة الطلب).
5. أي `body.tenantId` مختلف يُرفض بـ 400 حتى يظهر الخلل للعميل، أو يُتجاهل مع اختبار يثبت التجاهل. الرفض أوضح.

## مثال عملي

```ts
export function resolveTenant(input: {
  hostSlug: string | null;
  headerSlug: string | null;
  tokenTenantId: string | null;
  bodyTenantId: string | null;
}) {
  if (input.bodyTenantId && input.bodyTenantId !== (input.tokenTenantId ?? input.hostSlug ?? input.headerSlug)) {
    throw new Error('tenant in body is not a source');
  }
  const tenantId = input.tokenTenantId ?? input.hostSlug ?? input.headerSlug;
  if (!tenantId) throw new Error('tenant missing');
  return tenantId;
}
```

القنوات الثلاث الموثوقة لها ترتيب مكتوب. الجسم إن وُجد وخالفها يفشل. لا تجمعوا slug المضيف مع مكتبة الرمز إن اختلفا؛ في منتج حقيقي ارفضوا التعارض بدل `??` الصامت عندما تصل قناتان بقيمتين. الدالة أعلاه تبدأ بالرمز ثم المضيف للتوضيح، والاختبار يجب أن يغطي التعارض كخطأ.

## أخطاء شائعة

- الثقة بترويسة يضعها المتصفح نيابة عن أي موقع من غير فحص عضوية.
- مطالبة `tenant_id` يضعها العميل في JWT لم توقّعوه.
- قبول الجسم «لأنه أسهل للنموذج».
- كاش سياق الطلب على singleton فيتسرّب slug بين الطلبات.

## متى نستخدمه؟

على كل قناة تدخل رف: نطاق المتجر، جوال بترويسة، ورمز بعد اختيار المكتبة.

## متى لا نستخدمه؟

لا تحلّوا المستأجر داخل كل خدمة بطريقة مختلفة. نقطة واحدة في الحارس، والباقي يقرأ السياق.

## مقارنة

| المصدر | يُقبل عندما |
| --- | --- |
| المضيف | الاسم في سجلكم بعد التطهير |
| الترويسة | تطبيقكم أرسلها وتُفحص العضوية |
| مطالبة الرمز | الرمز موقّع من رف وفيه المكتبة المختارة |
| جسم JSON | لا يُقبل كمصدر |

## تمارين

### تمرين سهل

`Host: lib-a.raf.example` والمستخدم عضو. ما مكتبة الاستعلام؟

<details>
<summary>الحل</summary>

مكتبة `lib-a` بعد تحويل slug إلى المعرّف. كتب `lib-b` لا تدخل `where` أو الاتصال.

</details>

### تمرين متوسط

الرمز يقول `lib-a` والجسم يقول `lib-b`. ماذا تفعلون؟

<details>
<summary>الحل</summary>

ترفضون الطلب. الرمز هو المصدر، والجسم المخالف لا يُتبع ولا يُتجاهل بصمت إن كان الاختبار أوضح عند 400. الاستعلام لا يجري على `lib-b`.

</details>

### تمرين متقدم

جوال بلا نطاق لكل مكتبة. من أين تأتي المكتبة عند إصدار الرمز؟

<details>
<summary>الحل</summary>

من اختيار صريح بعد قائمة عضويات المستخدم، ثم تُكتب المطالبة في الرمز الذي توقّعونه. التبديل إلى مكتبة أخرى يصدر رمزًا جديدًا. الترويسة وحدها تُعاد مطابقتها على هذه المطالبة أو على العضوية في كل طلب.

</details>

## أسئلة مراجعة

- اذكر ثلاثة مصادر مقبولة.
- لماذا الجسم مرفوض حتى لو طابق العضوية بالصدفة؟
- ماذا تفعلون عند تعارض الرمز والمضيف؟
- أين تُفحص العضوية نسبة إلى استخراج slug؟

## الخلاصة

حل المستأجر من المضيف أو ترويسة قناتكم أو مطالبة رمز موقّع، ثم عضوية. `tenantId` في الجسم ليس مصدرًا. التعارض يُرفض لا يُدمج.

## ماذا بعد؟

المعّرف معروف لكل طلب. الدرس التالي شكل ذلك داخل Nest: حارس، سياق، وخدمة لا تلمس `Request` في كل دالة.
