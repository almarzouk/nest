Database per Tenant

الهدف من هذا الدرس

وضع مكتبة رف في قاعدة Postgres خاصة بها (نموذج الصومعة، silo): اتصال مستقل، ترحيل مستقل، وعطل أو استعادة لا تمس الجار.

المشكلة التي يحلها

مكتبة كبيرة تشترط نسخة احتياطية مستقلة، أو منطقة بيانات، أو حد اتصالات لا يشاركه كتالوج الجيران. عمود في جدول مشترك لا يقنع عقدهم. schema في نفس العنقود ما زالت تشارك القرص والنسخة والإصدار.

الفكرة ببساطة

لكل مستأجر عنوان قاعدة. الطلب يختار عميل Prisma (أو اتصالًا) تلك القاعدة بعد حل المستأجر. لا استعلام «ينسى» العمود لأن الجداول لا تحتوي الجار أصلًا. الثمن: إنشاء قاعدة، سر، ترحيل، مراقبة، وتجميع اتصالات لكل عميل.

التعريف التقني

Silo يعني قاعدة لكل مستأجر. التطبيق يحتفظ بسجل توجيه: tenantId → connection string في مخزن تتحكمون فيه لا في جسم الطلب. العميل يُنشأ بكسل ويُعاد استخدامه. عدد المكتبات الكبير يعني عدد عملاء كبيرًا؛ لا تفتحوا PrismaClient لكل طلب. الترحيل حلقة على كل قواعد أو أداة تنشر بالتدريج. إسقاط قاعدة جار خطأ تشغيلي لا يمر من where. النسخ والاستعادة تتم لمكتبة واحدة. صفحة النطاقات في Nest تناقش شجرة حقن دائمة عندما تكون مصادر البيانات قليلة؛ مع مئات القواعد، خريطة عملاء singleton أصدق من Scope.REQUEST لكل طلب.

Mental Model

سجل التوجيه
  lib_a → postgres://.../lib_a
  lib_b → postgres://.../lib_b
الطلب يختار عميلًا من الخريطة ثم يعمل

أبسط مثال

import { PrismaClient } from '@prisma/client';

export class TenantClients {
  private readonly clients = new Map<string, PrismaClient>();

  get(tenantId: string, url: string) {
    let client = this.clients.get(tenantId);
    if (!client) {
      client = new PrismaClient({ datasources: { db: { url } } });
      this.clients.set(tenantId, client);
    }
    return client;
  }
}

شرح المثال

  • الخريطة تعيش مع العملية لا مع الطلب.
  • url يأتي من سجل التوجيه الداخلي بعد التحقق من المستأجر، لا من ترويسة اتصال.
  • عند إغلاق التطبيق أغلقوا كل العملاء حتى لا تبقى مقابس.

ماذا يحدث داخليًا؟

  1. يُحل tenantId ويُفحص العضوية.
  2. يُجلب عنوان القاعدة من السجل السري.
  3. يُستخدم عميل تلك القاعدة في book.findMany بلا الحاجة إلى عمود مستأجر للعزل (يمكن إبقاؤه دفاعًا).
  4. فشل الاتصال عطل لمكتبة واحدة: 503 لتلك الطلبات، والآخرون على قواعدهم.
  5. النشر يشغّل الترحيل على كل عنوان قبل توجيه الحركة إلى كود يعتمد عمودًا جديدًا.

مثال عملي

@Injectable()
export class BooksService {
  constructor(private readonly clients: TenantClients, private readonly directory: { urlFor: (id: string) => string }) {}

  list(tenantId: string) {
    const db = this.clients.get(tenantId, this.directory.urlFor(tenantId));
    return db.book.findMany({ where: { status: 'published' }, take: 20 });
  }
}

directory.urlFor يرمي إن لم تُنشأ القاعدة بعد. لا تسقطوا إلى قاعدة افتراضية «حتى تعمل» فيظهر كتالوج المكتبة الأولى للثانية.

أخطاء شائعة

  • عنوان القاعدة في ترويسة X-Database-Url يتحكم فيها العميل.
  • new PrismaClient() داخل كل طلب فيُنهك Postgres.
  • ترحيل المكتبة الكبيرة فقط ونسيان الباقي.
  • كاش في الذاكرة بمفتاح bookId بلا tenantId رغم أن المعرّفات قد تتشابه عبر القواعد.

متى نستخدمه؟

عقد عزل قوي، أو حجم يبرر عمليات مستقلة، وعدد مستأجرين تقدرون على تشغيل قواعدهم.

متى لا نستخدمه؟

لمئات المكتبات المجانية المتشابهة. التكلفة والمجمع والترحيل ستتجاوز ثمن عمود tenantId. ابدأوا pool حتى يفرض عميل الصومعة.

تمارين

تمرين سهل

لماذا لا يُنشأ PrismaClient لكل GET /books؟

الحل

لأن كل عميل مجمع اتصالات. لكل طلب يعني استنفاد max_connections وإبطاء الإقلاع. الخريطة تعيد العميل الموجود للمكتبة.

تمرين متوسط

طلب مكتبة lib_b وقع على عميل lib_a بسبب خريطة خاطئة. هل ينقذك where tenantId إن لم يكن العمود موجودًا في نموذج الصومعة؟

الحل

لا. الجداول لا تحتوي الجار أصلًا، والعميل الخطأ يعرض كتالوج lib_a كاملًا. الاختبار يجب أن يثبت أن المعرّف يختار العنوان الصحيح. عمود زائد دفاع ممكن لكنه لا يصلح عنوانًا خاطئًا وحده إن نسيتم الشرط.

تمرين متقدم

مكتبة واحدة على silo والباقي على pool. ماذا يبقى مشتركًا في كود رف؟

الحل

حل المستأجر والعضوية وشكل الـ API. يختلف مصدر البيانات: عميل مشترك مع where tenantId أو عميل من الخريطة. الخدمة لا تقرأ الجسم لتعرف الفرق. التوجيه في السجل الداخلي.

أسئلة مراجعة

  • ماذا يختار الطلب في نموذج silo؟
  • من أين يأتي عنوان القاعدة؟
  • لماذا الترحيل حلقة؟
  • متى تبقى pool كافية؟

الخلاصة

قاعدة لكل مستأجر تعزل النسخة والاتصال والاستعادة. العميل يُخزَّن لكل مكتبة، والعنوان من سجل سري بعد حل موثوق. الثمن تشغيل. ليست الخطوة الأولى لكل مكتبة صغيرة في رف.

ماذا بعد؟

النماذج الثلاثة تحتاج نفس البداية: من أين نعرف مكتبة هذا الطلب. الدرس التالي حل المستأجر.
