# Single DB / Schema per Tenant

## الهدف من هذا الدرس

عزل مكتبة رف في schema خاصة داخل Postgres واحدة، بحيث تُبنى الجداول لكل مستأجر ولا يعتمد العزل على تذكر `where tenantId` في كل سطر.

## المشكلة التي يحلها

عميل يشترط أن جداوله لا تختلط فيزيائيًا مع جداول جاره داخل نفس العلاقة، لكنه لا يريد قاعدة واتصالًا مستقلين. نموذج العمود يخيف مراجعهم لأن نسيان `where` يسرب. تريدون حدًا عند اسم الـ schema.

## الفكرة ببساطة

لكل مكتبة schema مثل `tenant_lib_a` فيها جدول `books` بلا عمود مستأجر، أو مع العمود دفاعًا إضافيًا. الطلب يضبط مسار البحث أو الاتصال إلى هذه الـ schema قبل أي استعلام. الترحيل يتكرر لكل schema. هذا نموذج الجسر (bridge): قاعدة واحدة وحد أقوى من العمود وأضعف من قاعدة كاملة.

## التعريف التقني

Postgres يسمح بعدة schemas في قاعدة. `search_path` يحدد أين يُحل اسم `books`. إن بقي المسار على `public` فالاستعلام يضرب الجدول الخطأ. Prisma لا يبدّل الـ schema لكل طلب من إعداد واحد بشكل سحري؛ تحتاجون مصدر بيانات يضبط المسار عند فتح الاتصال أو يستخدم اسم schema مؤهلًا. الترحيلات: أداة تشغّل نفس SQL على كل schema عند النشر. إنشاء مكتبة جديدة يعني إنشاء schema ثم تطبيق الترحيل لا إدراج صف في `tenants` فقط. عدد المخططات الكبير يثقل أدوات الإدارة والنسخ.

## Mental Model

```text
database raf
  schema tenant_lib_a / books
  schema tenant_lib_b / books
الاتصال في الطلب يشير إلى schema واحدة
```

## أبسط مثال

```ts
export function schemaName(tenantId: string) {
  if (!/^lib_[a-z0-9]+$/.test(tenantId)) throw new Error('unsafe tenant id');
  return `tenant_${tenantId}`;
}
```

## شرح المثال

- اسم الـ schema يُشتق من معرّف ضيق. لصق `tenantId` الخام في SQL يعيد حقنًا.
- المعرّف ما زال من السياق الموثوق لا من الجسم.
- الفشل في التطابق يرفض الطلب قبل `SET search_path`.

## ماذا يحدث داخليًا؟

1. يُحل المستأجر ويُفحص نمط المعرّف.
2. يُؤخذ اتصال وتُضبط الـ schema لهذه الجلسة.
3. استعلامات Prisma اللاحقة على هذا الاتصال ترى جداول المكتبة.
4. إعادة الاتصال إلى المجمع من غير إعادة ضبط المسار تسرّب مكتبة إلى الطلب التالي. لذلك لا تُعاد الجلسة إلى المجمع وهي ما زالت على schema مستأجر، أو يُضبط المسار في كل استعارة.
5. الترحيل الناقص على schema واحدة يترك مكتبة على نسخة مخطط قديمة.

## مثال عملي

```ts
export async function withTenantSchema(sql: { unsafe: (q: string) => Promise<void> }, tenantId: string, run: () => Promise<void>) {
  const schema = schemaName(tenantId);
  await sql.unsafe(`set search_path to ${schema}`);
  try {
    await run();
  } finally {
    await sql.unsafe('set search_path to public');
  }
}
```

`schema` هنا من معرّف طُهر في `schemaName` لا من سلسلة الطلب. `finally` يعيد المسار حتى لا يرث الطلب التالي schema الجار على نفس الاتصال. في الإنتاج فضّلوا واجهة معاملات Postgres على بناء SQL إن وُجدت، وأبقوا التطهير.

## أخطاء شائعة

- `search_path` من نص الترويسة مباشرة.
- مجمع اتصالات يعيد جلسة ملوثة.
- ترحيل يُطبَّق على `public` فقط وتُنسى schemas المكتبات.
- عشرات الآلاف من المخططات على قاعدة واحدة ثم تعطل النسخ الاحتياطي.

## متى نستخدمه؟

عدد مكتبات محدود نسبيًا، ومطلب عزل جداول داخل خادم واحد، مع قدرة على ترحيل متكرر.

## متى لا نستخدمه؟

لآلاف المكتبات الصغيرة المتشابهة؛ العمود أرخص. ولعميل يشترط محركًا أو منطقة جغرافية مستقلة؛ ذلك قاعدة منفصلة.

## مقارنة

| | عمود في public | schema لكل مستأجر |
| --- | --- | --- |
| نسيان القيد | تسريب صفوف | غالبًا جدول فارغ أو خطأ إن ضُبط المسار |
| النشر | ترحيل واحد | ترحيل × عدد المكتبات |
| إنشاء مكتبة | صف | schema + ترحيل |

## تمارين

### تمرين سهل

لماذا لا يُبنى اسم الـ schema من `body.tenantId` كما وصل؟

<details>
<summary>الحل</summary>

لأن الجسم غير موثوق وقد يحتوي مسافات أو فواصل SQL. الاسم يُشتق من معرّف طُهر بعد حل المستأجر من المصدر الموثوق.

</details>

### تمرين متوسط

ماذا يحدث إن أُعيد الاتصال إلى المجمع و `search_path` ما زال على `tenant_lib_a`؟

<details>
<summary>الحل</summary>

طلب مكتبة أخرى قد ينفّذ SQL على جداول `lib_a`. أعيدوا المسار إلى `public` قبل الإرجاع، أو اضبطوه في بداية كل طلب على الاتصال المستعار.

</details>

### تمرين متقدم

مكتبة جديدة في الإنتاج. ما ترتيب الخطوات حتى ترى `GET /books` جدولها لا جدول public؟

<details>
<summary>الحل</summary>

إنشاء schema بالاسم المطهر، تطبيق نفس الترحيلات عليها، ثم ربط الطلبات القادمة بهذه الـ schema. إدراج صف المستأجر وحده يترك المسار بلا جداول أو يوقعه على public.

</details>

## أسئلة مراجعة

- ماذا يغيّر الطلب: العمود أم مسار الـ schema؟
- لماذا الترحيل يتكرر؟
- ما خطر المجمع مع `search_path`؟
- متى يبقى نموذج العمود أنسب؟

## الخلاصة

Schema لكل مستأجر تعزل الجداول داخل قاعدة واحدة. الاسم مطهر، والمسار يُضبط لكل استعارة اتصال ويُعاد، والترحيل يطال كل schema. هذا جسر بين العمود المشترك وقاعدة كاملة.
