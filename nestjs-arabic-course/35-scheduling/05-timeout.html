Timeout

الهدف من هذا الدرس

تشغيل دالة مرة واحدة بعد تأخير من إقلاع العملية، وتمييز هذه الزينة عن مهلة HTTP ومهلة RxJS.

المشكلة التي يحلها

بعض التهيئة تحب أن تتأخر حتى تفتح Redis أو حتى ينتهي onModuleInit الثقيل: طباعة جاهزية العامل، أو إدراج مهمة تعويضية مرة عند البدء. setTimeout داخل الباني يعمل قبل اكتمال الحقن أحيانًا ويصعب إيقافه في الاختبار. @Timeout من @nestjs/schedule مؤقت مرة واحدة مرتبط بالمزوّد.

ليست هذه مهلة lookup ولا timeout() في pipe. إن استعملتها لقطع ناشر ISBN فلن تُستدعى لكل طلب، بل مرة بعد الإقلاع.

الفكرة ببساطة

@Timeout(5_000) يستدعي الدالة بعد 5 ثوانٍ من جدولة المزود، ثم لا يعيد. للنبضة المتكررة استخدم @Interval. للتقويم @Cron. الرقم بالميلي ثانية.

التعريف التقني

import { Injectable, OnApplicationBootstrap } from '@nestjs/common';
import { Timeout } from '@nestjs/schedule';

@Injectable()
export class StartupPingService {
  @Timeout(5_000)
  async pingCovers() {
    const counts = await this.covers.getJobCounts('waiting', 'failed');
    this.logger.log(`covers waiting=${counts.waiting} failed=${counts.failed}`);
  }
}

الاسم الاختياري @Timeout('covers-ping', 5_000) إن أردت إلغاءه من SchedulerRegistry.

لا تضع في هذه الدالة إرسال بريد ترحيبي لكل المستخدمين. كل إقلاع، وكل نسخة، ستشغّلها مرة. القياس في السجل آمن نسبيًا. الأثر الخارجي يحتاج jobId أو خروجًا إن كانت العلامة موجودة.

إن احتجت «بعد أن تكتمل تهيئة الوحدات» لا «بعد 5 ثوانٍ أملًا»، فخطاف OnApplicationBootstrap أدق من رقم سحري. @Timeout عندما يكون التأخير نفسه هو القرار، مثل إمهال Redis 5 ثوانٍ في التطوير.

أبسط مثال

@Timeout(5_000)
logReady() {
  this.logger.log('cover worker process is up');
}

الدالة بلا await طويلة. إن كانت تقرأ Redis، اجعلها async والتقط فشل الاتصال حتى لا يظهر رفض صامت بعد خمس ثوانٍ من كل نشر.

شرح المثال

خمس ثوانٍ تكفي في تمرين محلي ليظهر السطر بعد رسالة Nest الجاهزة. في الإنتاج السجل نفسه مفيد مرة لكل عملية، أي سطر لكل نسخة. لا ترفع مستوى الإنذار إن كان waiting صفرًا. الإنذار شرط من درس @Interval حيث يتكرر القياس.

ماذا يحدث داخليًا؟

المكتبة تسجل مؤقتًا واحدًا. عند النار تُستدعى الدالة ويُزال المؤقت. إعادة تشغيل العملية تعيد الدورة. لا تعويض إن قُتلت العملية في الثواني الخمس الأولى: العمل لم يحصل، والمرة التالية بعد الإقلاع التالي فقط. هذا مقبول لسطر سجل وغير مقبول لتسوية دفع.

SchedulerRegistry يتيح حذف المؤقت بالاسم في الاختبار بعد إنشاء الوحدة حتى لا يشتغل أثناء الإغلاق. إن لم تسمِّ المؤقت، تتبّعه أصعب. للاختبار الأفضل استخراج الجسم إلى logReady() ونقل الزينة، ثم استدعاء الدالة بلا انتظار.

مثال عملي

تعويض نافذة فشل add مرة عند البدء، مع طابور:

@Timeout(5_000)
async requeueOnBoot() {
  const stuck = await this.books.pendingOlderThan(60_000);
  for (const book of stuck) {
    await this.producer.enqueueResize({ bookId: book.id, coverKey: book.coverKey });
  }
}

مع @Interval الدوري قد يكفي أحدهما. الاثنان معًا يكرران الفكرة. اختر تعويض الإقلاع إن كانت النسخ تُنشر كثيرًا والصفوف تعلق، أو النبضة الدورية إن بقيت العملية أسابيع. jobId في المنتج يمنع التضاعف إن جمعتهما بالخطأ فترة.

أخطاء شائعة

  • خلط الزينة مع مهلة Axios على HttpModule.
  • @Timeout(5) أي 5 ميلي ثانية.
  • عمل له أثر مالي عند كل إقلاع.
  • توقع التكرار. لن يتكرر حتى إقلاع جديد.

متى نستخدمه؟

لأثر مرة بعد البدء: سجل جاهزية، أو التقاط عالقين بعد الإقلاع.

متى لا نستخدمه؟

لمهلة طلب، أو لتأخير POST خمس ثوانٍ قبل الرد. ذلك await في الطلب أو مهمة متأخرة في BullMQ إن كان التأخير لكل كتاب لا لكل عملية.

مقارنة

الاسم الحزمة كم مرة
@Timeout(5_000) @nestjs/schedule مرة بعد الإقلاع
@Interval @nestjs/schedule كل مدة
timeout في RxJS أو Axios rxjs / Axios لكل تيار أو طلب

لأن كل نشر وكل نسخة تشغّل الدالة. السجل يتكرر بلا ضرر على المستخدم. البريد أثر خارجي يتضاعف.

تمرين متقدم

متى تفضّل OnApplicationBootstrap على @Timeout؟

الحل

عندما يجب أن تعمل الدالة بعد تهيئة الوحدات لا بعد رقم ثابت قد يسبق اتصال Redis أو يتأخر بلا سبب.

أسئلة مراجعة

  • ما وحدة الرقم؟
  • هل الزينة تقطع lookup البطيء؟
  • ماذا يحدث للمؤقت عند إعادة التشغيل؟

الخلاصة

@Timeout من @nestjs/schedule نبضة واحدة بعد الإقلاع. لا تخلطها بمهلة الطلب. الأثر الخارجي عند البدء يحتاج مفتاح تكرار أو يُستبدل بخطاف تهيئة.

ماذا بعد؟

إعلان داخل العملية أن شيئًا حدث، من غير أن يستدعي المعلن كل المستمعين بالاسم.
