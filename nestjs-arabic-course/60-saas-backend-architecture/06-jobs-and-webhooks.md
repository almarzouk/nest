# Background Jobs و Webhooks

## الهدف من هذا الدرس

تحديد مكانين في معمارية رف: عمل لا ينتظره طلب HTTP (مهمة)، وإشعار يعبر حدود النظام (ويب هوك صادر أو وارد)، من غير بناء أي منهما كاملًا هنا.

## المشكلة التي يحلها

نشر الكتاب يضغط الصورة ويرسل بريدًا وينادي شريك المخزون داخل `POST` واحد. المهلة تقطع الرد بعد ما نُشر الكتاب جزئيًا. شريك آخر يريد أن يُبلَّغ عند النشر، فيُطلب منكم إبقاء الاتصال مفتوحًا حتى يرد.

## الفكرة ببساطة

المهمة وحدة عمل تُعاد بأمان: مفتاح، مدخلات، حالة. الويب هوك رسالة عبر HTTP إلى عنوان سجّله الطرف الآخر، أو رسالة منه إليكم. الطلب الذي ينشر الكتاب يلتزم الأثر ويجدول المهمة أو يدرج حدثًا. التسليم يعيد المحاولة. التفاصيل: التوقيع، الجسم الخام، والتكرار تأتي في فصل الويب هوك. هنا نرسم الحدود حتى لا تكبر `BooksService`.

## التعريف التقني

طابور `@nestjs/bullmq` أو ما شابه يعيش في وحدة `JobsModule` ويستهلك أسماء وظائف مثل `cover.resize`. المعالج يحمّل المستأجر من حمولة المهمة لا من سياق طلب غائب. الويب هوك الصادر صف `WebhookEndpoint` لكل منظمة: `url`, سر, أحداث مشتركة. الحدث `book.published` يُدرج بعد الالتزام. الوارد من Stripe أو غيره مسار مستقل `POST /webhooks/...` لا يمر من حارس جلسة المستخدم. لا تستورد وحدة الكتب SDK الشريك.

## Mental Model

```text
POST /books/:id/publish
  COMMIT book + audit
  enqueue cover.resize { organizationId, bookId }
  enqueue webhook.deliver { organizationId, event }

عامل لاحق يسلّم
```

## أبسط مثال

```ts
export interface JobPayload {
  organizationId: string;
  bookId: string;
}

export const jobs = {
  resizeCover: 'cover.resize',
  deliverWebhook: 'webhook.deliver',
} as const;
```

## شرح المثال

- الحمولة معرّفات لا كائن كتاب كامل قد يشيخ.
- `organizationId` إجباري لأن العامل بلا حارس طلب.
- الاسم ثابت حتى لا تتفرق السلاسل في المتحكمات.

## ماذا يحدث داخليًا؟

1. الطلب يتحقق من الصلاحية والخطة والمستأجر.
2. يلتزم النشر والتدقيق.
3. يدفع رسالة إلى الطابور. إن فشل الدفع بعد الالتزام فمهمة تعويض أو نمط صادر لاحقًا يعيد البناء من الصفوف.
4. العامل ينفّذ ثم يعلّم النجاح. الفشل يعيد المحاولة بعدد محدود.
5. الويب هوك الفاشل لا يعيد الكتاب مسودة. هو تسليم متأخر.

## مثال عملي

```ts
@Injectable()
export class PublishCoordinator {
  constructor(private readonly books: BooksService, private readonly queue: { add: (name: string, payload: JobPayload) => Promise<void> }) {}

  async publish(tenantId: string, bookId: string, actorId: string) {
    await this.books.publish(tenantId, bookId, actorId);
    await this.queue.add(jobs.resizeCover, { organizationId: tenantId, bookId });
    await this.queue.add(jobs.deliverWebhook, { organizationId: tenantId, bookId });
  }
}
```

`books.publish` المعاملة. الطابور بعدها. إن أردتم ذرية أقوى فسيأتي صندوق الصادر في فصول الاعتمادية. هذا الدرس يمنع فقط أن يكون الضغط نداءً متزامنًا داخل المتحكم.

## أخطاء شائعة

- `await sharp()` و `await fetch(partner)` داخل طلب النشر.
- مهمة بلا `organizationId` فتحدّث أول عميل Prisma في الخريطة.
- ويب هوك وارد على مسار الجلسة فيفشل توقيع المزود لأن الجسم مُحلِّل خطأ، وهذا يُعالج في فصل لاحق لكن الحد هنا مسار خاص.
- إعادة محاولة بلا مفتاح فتتكرر الدعوة للشريك.

## متى نستخدمه؟

عمل أطول من مهلة HTTP، وتسليمه غير لازم لرمز 200/201، وتبليغ نظام خارجي.

## متى لا نستخدمه؟

لا تؤجلوا التحقق من الصلاحية إلى العامل؛ المتصفح يظن أن النشر نجح. ولا تضعوا كل دالة في طابور «للنظافة».

## مقارنة

| | مهمة | ويب هوك صادر |
| --- | --- | --- |
| من يستدعي | عامل داخل منصتكم | عنوان العميل عبر HTTP |
| الحمولة | معرّفات عمل | حدث بعقد |
| الفشل | إعادة داخل الطابور | إعادة تسليم موقّعة |
| أثره على الكتاب | لا يلغي الالتزام | لا يلغي الالتزام |

## تمارين

### تمرين سهل

هل ينتظر `POST publish` رد شريك المخزون؟

<details>
<summary>الحل</summary>

لا. يلتزم النشر ويجدول التسليم. الشريك البطيء لا يمسك مهلة المتصفح.

</details>

### تمرين متوسط

العامل استيقظ بلا طلب HTTP. من أين يأخذ `tenantId`؟

<details>
<summary>الحل</summary>

من حمولة المهمة التي كُتبت عند الجدولة. لا من `tenantStorage` لطلب انتهى، ولا من قيمة افتراضية لأول مكتبة.

</details>

### تمرين متقدم

الطابور قُبل بعد الالتزام ثم ضاعت الرسالة. ماذا يبقى صحيحًا في الكتالوج، وما الذي يجب أن يُعاد بناؤه؟

<details>
<summary>الحل</summary>

الكتاب منشور والتدقيق موجود. صورة الغلاف وتسليم الويب هوك قد يغيبان. إعادة البناء من الصفوف التي بلا مهمة مكتملة (أو صندوق صادر لاحقًا) تعيد الجدولة. لا تعيدوا النشر نفسه فتكرروا الأثر.

</details>

## أسئلة مراجعة

- ماذا يلتزم طلب النشر، وماذا يُجدول؟
- لماذا الحمولة معرّفات؟
- أين يعيش ويب هوك المزود نسبة إلى حارس الجلسة؟
- هل فشل التسليم يعيد المسودة؟

## الخلاصة

المهام والويب هوك حدود تسليم بعد الالتزام. العامل يعرف المكتبة من الحمولة. فشل القناة لا يلغي فعل الكتالوج. التوقيع والجسم الخام يأتيان في فصلهما.

## ماذا بعد؟

الحد المعماري جاهز. الفصل التالي يفتح الويب هوك نفسه: وارد وصادر، توقيع، جسم خام، إعادة، ومفتاح تكرار.
