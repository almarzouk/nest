# 36 — طلب يخصم المخزون

**المستوى:** متقدم  
**النوع:** Backend فقط  
**الأمر الذي تبدأ منه:** `nest new order-stock`

## ماذا تبني

PostgreSQL و Prisma. إنشاء طلب يخصم الكمية في المعاملة نفسها. المخزون الناقص 409 ولا يترك طلبًا نصف مكتوب.

## لماذا هذا المشروع الآن

الذاكرة لم تعد تكفي. أول قاعدة حقيقية مع قاعدة عمل تُكسر إن انفصل الخصم عن الإدراج.

## ماذا ستتعلم

- PrismaService
- transaction
- قيد لا ينقص تحت الصفر

## ما الذي لن تبنيه في هذا المشروع

- دفع
- شحن
- synchronize العشوائي. استخدم ترحيل Prisma لا TypeORM synchronize.

## قبل أن تبدأ

السلة والفصل 18. Docker لـ Postgres مقبول.

من الدورة: [18-database](../../nestjs-arabic-course/18-database/README.md).

## قواعد العمل

- الكمية المتوفرة لا تنزل تحت صفر.
- فشل الخصم يلغي إدراج الطلب.
- السعر يُنسخ إلى سطر الطلب وقت الشراء حتى لا يتغير التاريخ لاحقًا.
- لا SQL من المتحكم.

## عقد HTTP

| الطريقة | المسار | الرمز | ماذا يفعل |
| --- | --- | --- | --- |
| `POST` | `/orders` | 201 | طلب وخصم |
| `POST` | `/orders` | 409 | عند نقص المخزون |

القائمة الفارغة `200` بجسم `[]` أو غلاف بيانات، لا `404`. الإنشاء `201`. الغائب `404`. التعارض `409`. الدخل الرديء `400`.

## من الصفر

1. أنشئ مجلدًا فارغًا خارج هذا الدليل التعليمي، ثم نفّذ `nest new order-stock`. اختر ESM عندما يسأل Nest CLI.
2. لا تنسخ `node_modules` إلى مجلد الدليل. هذا المجلد للشرح، والكود يعيش في مشروعك.
3. أبقِ `AppModule` جذرًا يسجّل وحدة الميزة. لا تضع القاعدة داخل `main.ts`.
4. ابنِ بالترتيب الموجود تحت «خطوات البناء». لا تقفز إلى آخر مسار قبل أن يعمل الأول.

## خطوات البناء

1. مخطط Product و Order و OrderLine وترحيل.
2. prisma.$transaction تضم الخصم والإدراج.
3. اختبر طلبين متوازيين على آخر قطعة إن استطعت، أو على الأقل طلبًا أكبر من المتوفر.

## شكل مقترح

```text
prisma/schema.prisma
src/orders/orders.service.ts
src/prisma/prisma.service.ts
```

## أصغر قطعة تبدأ منها

```ts
await this.prisma.$transaction(async (tx) => {
  const updated = await tx.product.updateMany({
    where: { id: productId, stock: { gte: quantity } },
    data: { stock: { decrement: quantity } },
  });
  if (updated.count !== 1) throw new ConflictException("out of stock");
});
```

هذه القطعة بداية لا مشروعًا مكتملًا. أكمل القواعد والمسارات بنفسك، ثم ارجع إلى العقد في الأعلى.

## أخطاء تظهر هنا كثيرًا

- خصم ثم إدراج من غير معاملة.
- الثقة بالمخزون الذي قرأته قبل ثانية من غير شرط في التحديث.
- تشغيل مخطط يمسح الجداول في الإنتاج.

## ينتهي المشروع عندما

- طلب ناجح يقلل المخزون.
- طلب زائد لا يترك صف طلب.
- السعر على السطر ثابت بعد تغيير سعر المنتج.

## تمديد بعد الانتهاء

أضف إلغاء طلب يعيد الكمية في معاملة.

## كيف نبنيه معًا

عندما تقول «ابدأ المشروع 36» نفتح مشروع Nest فارغًا وننفّذ خطوة واحدة في كل مرة: مسار، ثم قاعدة، ثم خطأ متوقع، ثم اختبارًا صغيرًا إن كان الفصل قد وصل إليه. لا نلصق الحل كاملًا قبل أن ترى الطلب يفشل للسبب الصحيح.
