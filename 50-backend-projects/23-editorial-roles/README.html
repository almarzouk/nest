23 — أدوار التحرير

المستوى: متوسط
النوع: Backend فقط
الأمر الذي تبدأ منه: nest new editorial-roles

ماذا تبني

قارئ يرى المنشور. محرر يعدّل مقالاته. مدير يحذف أي مقال. القرار في سياسة لا في if مبعثرة داخل كل مسار.

لماذا هذا المشروع الآن

الهوية من المشروع السابق لا تكفي. هنا المنع 403 بعد أن عُرف الشخص.

ماذا ستتعلم

  • 401 مقابل 403
  • دور على المستخدم
  • سياسة can

ما الذي لن تبنيه في هذا المشروع

  • CASL
  • صلاحيات لكل حقل
  • دعوات

قبل أن تبدأ

الملف الحالي والمقالات. يمكن تبسيط المقال إلى عنوان وحالة.

من الدورة: 21-authorization.

قواعد العمل

  • من غير رمز 401.
  • قارئ يحاول الحذف 403 لا 404 حتى لا نخلط الغياب بالمنع. إن كان المقال لغيره والمدير فقط يحذف، فالمحرر على مقال غيره 403.
  • المدير يمر. المحرر يحذف مقاله فقط.
  • الدور لا يُقبل من الجسم عند التعديل. تغيير الدور مسار مدير منفصل.

عقد HTTP

الطريقة المسار الرمز ماذا يفعل
GET /articles 200 المنشور للجميع بعد الرمز، أو قرر أن القراءة عامة ووثّق ذلك
DELETE /articles/:id 204 حسب السياسة
PATCH /users/:id/role 200 للمدير فقط

القائمة الفارغة 200 بجسم [] أو غلاف بيانات، لا 404. الإنشاء 201. الغائب 404. التعارض 409. الدخل الرديء 400.

من الصفر

  1. أنشئ مجلدًا فارغًا خارج هذا الدليل التعليمي، ثم نفّذ nest new editorial-roles. اختر ESM عندما يسأل Nest CLI.
  2. لا تنسخ node_modules إلى مجلد الدليل. هذا المجلد للشرح، والكود يعيش في مشروعك.
  3. أبقِ AppModule جذرًا يسجّل وحدة الميزة. لا تضع القاعدة داخل main.ts.
  4. ابنِ بالترتيب الموجود تحت «خطوات البناء». لا تقفز إلى آخر مسار قبل أن يعمل الأول.

خطوات البناء

  1. اكتب ArticlePolicy.canDelete(user, article).
  2. الحارس يثبت الهوية. السياسة تثبت الإذن. لا تخلطهما في دالة واحدة طويلة.
  3. ازرع ثلاثة مستخدمين في الذاكرة للاختبار اليدوي.

شكل مقترح

src/articles/article.policy.ts
src/users/roles.ts

أصغر قطعة تبدأ منها

canDelete(user: { id: string; role: string }, article: { authorId: string }) {
  if (user.role === "admin") return true;
  if (user.role === "editor" && article.authorId === user.id) return true;
  return false;
}

هذه القطعة بداية لا مشروعًا مكتملًا. أكمل القواعد والمسارات بنفسك، ثم ارجع إلى العقد في الأعلى.

أخطاء تظهر هنا كثيرًا

  • 403 لمن لا يحمل رمزًا.
  • إخفاء مقال الغير بـ 404 كسياسة عامة من غير توثيق. هنا العقد 403.
  • قبول role داخل PATCH المقال.

ينتهي المشروع عندما

  • القارئ 403 على الحذف.
  • المحرر يحذف مقاله ويفشل على غيره.
  • المدير يحذف الاثنين.

تمديد بعد الانتهاء

انقل السياسة إلى شكل أقرب لـ @nestjs/authorization إن أنهيت ذلك الفصل.

كيف نبنيه معًا

عندما تقول «ابدأ المشروع 23» نفتح مشروع Nest فارغًا وننفّذ خطوة واحدة في كل مرة: مسار، ثم قاعدة، ثم خطأ متوقع، ثم اختبارًا صغيرًا إن كان الفصل قد وصل إليه. لا نلصق الحل كاملًا قبل أن ترى الطلب يفشل للسبب الصحيح.
